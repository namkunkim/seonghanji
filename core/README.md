## 규칙 하나

**코어는 Node 에 의존하지 않는다.** `RefCounted` 와 정적 함수만 쓴다.

헤드리스로 돌아야 하기 때문이다. `dev-requirements.md` §9 가 M0 의 산출물을
「화면 하나 없이 190년 시나리오가 AI 대 AI로 100회 자동 진행되는 것」으로 잡았고,
§2.3 은 그 코어가 **클라이언트·서버·시뮬레이터 셋이 공유하는 한 벌**이어야 한다고 못박았다.

## 시간 모델 (S2.1)

```
[코어]  Sim.advance(world, elapsed_ms)     ← 시계의 출처를 모른다
   ↑
[단기]  게임 루프 델타 × 배속               앱이 켜져 있는 동안만
[장기]  서버 벽시계 경과분                  앱이 꺼져 있어도
```

단기판의 「명령 중에도 시간이 흐른다」와 장기판의 「접속하지 않아도 세계가 나아간다」는
**같은 함수의 두 호출자**다. 이 하나를 지키면 L3 온라인 전환 때 코어를 그대로 쓴다.

### 고정 스텝 (DECISIONS.md V-25 ③)

세계는 **게임 내 1일 단위로만** 나아간다.

```
누적 += 실제경과 × 배속
while 누적 >= 1일:
    advance_one_day()
    누적 -= 1일
```

- 기준: **실제 1시간 = 게임 1개월**, 1개월 = 30일 → **게임 1일 = 실제 120초**
- **부동소수를 누적하지 않는다.** 프레임 델타는 `from_delta()` 에서 즉시 정수 밀리초가 된다.
  이 함수가 부동소수가 코어로 들어오는 **유일한 문턱**이다
- 배속 ×1 / ×2 / ×4 (상한 미결 — roadmap-solo.md 검토 포인트 1)

### 결정론의 실제 보장 지점

프레임률이 달라도 결과가 같은 이유는 누적기가 정확해서가 아니다.
**세계가 날 단위로만 변하고, 명령이 `game_day` 로 찍히기 때문**이다.

- 라이브 플레이(`Sim.advance`) — dt 경로. 「언제 하루가 넘어가는가」만 결정한다
- 재생·검증(`Sim.step_days`) — dt 를 거치지 않고 날 단위로만 진행한다

세이브가 「시드 + 명령 로그」인 것이 여기에 맞물린다 (`schema/save.json`).

`_advance_one_tick()` 의 **호출 순서 자체가 규칙이다.** 바꾸면 결정론이 깨진다.

### ⚠ `Sim` 은 `clock.advance()` 를 쓰지 않는다

**틱을 하나씩 밟아야 한다.**

```gdscript
var ticks := world.clock.take_ticks(elapsed_ms)   # 나머지만 누적
for _i in ticks:
    world.clock.step_ticks(1)                     # 한 틱씩 올리고
    _advance_one_tick(world)                      # 그 틱을 처리한다
```

시계를 **한 번에** 밀어 올린 뒤 루프를 돌면, 루프 내내 `clock.tick` 이 최종값에
고정되어 「지금 몇 틱인가」에 의존하는 처리가 전부 어긋난다.

> **2026-08-24 실제 사고.** 11년치를 진행하자 **연 1회 정산이 7,920번** 돌았다
> (`tick % 720 == 0` 이 루프 내내 참이었다). 전화 계수가 상한으로 튀었다.
>
> **시험 8번(dt 경로 ↔ 재생 경로 일치)이 이것을 못 잡았다** — **총량만 비교**했기 때문이다.
> 「지금 몇 틱인가」에 의존하는 처리가 생기고 나서야 드러났다.
> 새 처리를 `_advance_one_tick` 에 넣을 때는 **두 경로의 결과를 함께 비교**한다
> (시험 17번이 그 형태다).

## 자체 시험

```
godot --headless --path . --script tests/run_tests.gd
```

Windows 설치 위치: `%USERPROFILE%\Tools\Godot\Godot_v4.7.2-stable_win64_console.exe`
(콘솔판을 쓴다 — GUI판은 표준 출력을 분리해 결과가 안 보인다)

**처음 한 번은 임포트가 필요하다.** `class_name` 전역은 프로젝트 스캔 때 등록되므로,
`.godot/` 가 없으면 `--script` 가 `Identifier "GameClock" not declared` 로 실패한다.

```
godot --headless --path . --import      # 최초 1회
godot --headless --path . --script tests/run_tests.gd
```

여덟 항목 32단언 — 기본 · 나머지 보존 · 배속 · **프레임률 무관** · 일시정지 ·
소요표 변환 · **dt 경로와 재생 경로 일치** · 명령 도달 지연.

> ✅ **섹션 27/27 · 통과 280 · 실패 0** (2026-08-24, Godot 4.7.2-stable)
>
> 시험은 **섹션 수를 함께 센다.** GDScript 는 없는 함수를 부르면 오류만 찍고
> 「실패 0」으로 끝나기 때문이다 — 실제로 `battle.gd` 컴파일 실패로
> **시험 26개가 소리 없이 빠진 적이 있다.**

국력 검산은 별도다 — 합격/불합격이 아니라 **대조표**다.
```
godot --headless --path . --script tests/verify_power.gd
```

## 검토 포인트

| # | 쟁점 | 비고 |
|---|---|---|
| 1 | **15분 단위가 항상 반일에 떨어진다** | 1시간 = 30일이므로 45분 = 22.5일 · 2시간 15분 = 67.5일 · 3시간 45분 = 112.5일. **셋 다 정확히 .5** — 눈금이 만든 구조적 동률이다. 지금은 **올림**으로 깬다(회랑을 짧게 만들지 않기 위해). 근본 해법은 **고정 스텝을 반일로** 내리는 것 |
| 2 | 배속 상한 | ×4 에서 대회랑 3시간 45분이 56분이 된다. roadmap-solo.md 검토 포인트 1 |
| 3 | 일시정지 | `paused` 를 두었으나 기본은 false. 전투 개입 시점의 자동 정지 여부 미결 — roadmap-solo.md 검토 포인트 7 |
| 5 | **전화 회복의 정수 반올림** | 부동소수를 못 쓰므로(§2.3) 정수 반올림으로 근사한다. 문서 §3.5-d 대비 총 절대오차 **48** (절사는 161). 55년 누적에서 1% 이내이나 **문서값과 완전히 같지는 않다** |
| 8 | **권역 인접이 대부분 추정이다** | 성계 간 간선 37개 중 귀속 항로로 실제 유도되는 것은 **9개**뿐이고 나머지 27개는 주권역끼리 이은 보완이다. `partial-occupation.md` §2.2 2급 성계 표에 항로 열이 없다. **AI 절단 가치의 정확도가 여기 걸린다** |
| 7 | **불러오기가 곧 재생이다** | 세이브가 「시드 + 명령 로그」이므로 불러오기가 처음부터 다시 돌리는 것이다. 5.8개월 캠페인이면 **재생 시간이 문제가 된다.** 주기적 스냅샷(규칙 버전과 함께)이 다음 과제 |
| 6 | **회복 꼬리의 최소 1** | 반올림해도 이득이 0 이 되어 C≈0.936 에서 영구히 멈춘다. 최소 1 로 수렴을 보장했으나, 꼬리 구간이 **체감형이 아니라 선형**이 된다 |
| 4 | `tick_count` 이중 계수 | `clock.tick` 과 별도로 센다. 어긋나면 진행 경로에 구멍이 있다는 뜻 — 검증용이며 나중에 뺄 수 있다 |
