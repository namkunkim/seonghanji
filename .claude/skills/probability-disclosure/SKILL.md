# 확률형 아이템 표시 의무 점검

> 상위: `docs/07-production/dev-requirements.md` §7.2 [중대] · `docs/03-systems/time-and-monetization.md`

## 0. 이 프로젝트가 대상인가 — 그렇다

`time-and-monetization.md` §5.2가 확정한 수익 축은 이렇다.

> 초빙권 뽑기 · 시즌 패스 · 외형/연출 · 추가 시나리오 · 편의 기능

**「초빙권 뽑기」가 확률형 아이템이다.** 시간 단축 과금을 전면 배제했어도(§2-1)
이 항목 하나로 표시 의무의 적용 대상이 된다. **「우리는 착한 과금이라 해당 없다」는
성립하지 않는다.** 의무는 설계 의도가 아니라 **구조**를 보고 판단한다.

## 1. 이 게임 고유의 난제 — 확률이 고정값이 아니다

`time-and-monetization.md` §5.2와 불가침 §2-3이 만든 구조가 이렇다.

> 과금해도 **천명이 낮으면 인재가 붙지 않는다.**
> 돈으로 초빙 기회는 살 수 있으나 등용 성공은 살 수 없다.

게임 설계로는 훌륭하지만, **표시 의무 관점에서는 가장 어려운 형태다.**

| 층 | 무엇 | 표시 의무상의 문제 |
|---|---|---|
| ① 구매물 | 초빙권 | 이건 확정 지급이라 단순 |
| ② 대상 추출 | 어떤 재야 인재가 나오는가 | **확률 표시 대상.** 명장 150인 제외 사실도 함께 명시 |
| ③ 등용 판정 | 3중 판정 · **천명 연동** | **여기가 핵심 쟁점.** 플레이어 상태에 따라 성공률이 달라진다 |

**③을 어떻게 표시할 것인가가 이 프로젝트의 실제 과제다.** 선택지는 셋이다.

| 안 | 내용 | 평가 |
|---|---|---|
| A | 천명 구간별 확률표를 전부 공개 | 가장 안전. 다만 **역설계로 시스템이 노출**된다 |
| B | ③을 과금 경로에서 분리 — 초빙권은 ②까지만 관여하고 등용은 순수 게임 내 행위 | **권장.** 확률형 아이템의 범위가 ②로 좁아진다 |
| C | 「천명에 따라 달라짐」만 표기 | **위험.** 구체적 확률 미표시로 판단될 소지 |

> **B를 권한다.** 불가침 §2-3의 취지(과금이 전략을 대체하지 못한다)를 그대로 지키면서,
> 표시 대상을 ②로 한정해 법적 노출을 줄인다. 설계 변경 없이 **경계선만 명확히 하는 것**이다.

## 2. 점검 항목

설계·문서·빌드에 대해 순서대로 확인한다.

- [ ] 확률형 아이템에 **해당하는 상품 목록**이 문서에 명시되어 있는가
- [ ] 각 상품의 **공급 확률정보**가 백분율로 산출 가능한가 (미정 수치가 남아 있지 않은가)
- [ ] **게임 내 표시 위치**가 UI 설계에 반영되어 있는가 (`ui-design.md`)
- [ ] **광고·선전물**(스토어 페이지·영상·SNS)에도 표시 계획이 있는가 — 게임 안만으로는 부족하다
- [ ] **천장(pity)·중복 보정**이 있다면 그 조건도 표시 대상에 넣었는가
- [ ] 확률이 **이벤트·기간에 따라 변동**하면 변동분도 표시하는가
- [ ] 표시 문구가 **한국어로, 구매 결정 전에** 보이는가
- [ ] 확률 산출의 **근거 데이터가 코드와 일치**하는가 (표시값과 실제값 불일치가 가장 큰 위험)

## 3. 하지 말 것

| 금지 | 이유 |
|---|---|
| 「낮은 확률로 등장」 같은 **정성 표현** | 구체적 수치가 요구된다 |
| 확률표를 **외부 링크로만** 제공 | 게임 내 접근 경로가 필요하다 |
| 표시값과 실제 코드값의 **불일치** | 가장 무거운 위반 유형. §8 QA에 검증 항목으로 넣는다 |
| 「확률 미공개가 재미」라는 설계 논거 | 법령 앞에서는 논거가 되지 않는다 |

## 4. 법령 확인 — 이 스킬은 법률 자문이 아니다

**이 문서의 내용을 근거로 최종 판단하지 않는다.** 확률형 아이템 규제는
게임산업법 개정과 시행령·고시를 통해 계속 바뀌어 왔고, 표시 대상·방식·제재
수준이 개정마다 달라졌다.

착수 시 **반드시** 다음을 순서대로 한다.

1. **게임산업진흥에 관한 법률**과 그 **시행령**의 확률형 아이템 조항 **원문**을 확인한다
2. **게임물관리위원회**의 최신 해설·가이드라인을 확인한다
3. 전자상거래법·표시광고법 등 **중복 적용 법령**을 확인한다
4. 수익 모델을 확정하기 **전에** 게임 전문 법률 검토를 받는다 — 확정 후에는 되돌리는 비용이 크다

> 확인 결과는 `dev-requirements.md` §7.2에 **확인일과 함께** 기록한다.
> 「확인했다」가 아니라 「2026-XX-XX 기준 무엇을 확인했다」로 남긴다.
