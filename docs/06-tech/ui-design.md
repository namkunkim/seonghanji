## 1. 제약 조건

### 1.1 물리적 제약

| 항목 | 값 |
|---|---|
| 기준 화면 | 390 × 844 pt (세로) |
| 리스트 표시 한계 | **12~15행** |

| 지도 표시 | **가로 전환 권장** (성도는 가로형) |

### 1.2 설계적 제약

| 항목 | 출처 |
|---|---|
| 세션 길이 **3~5분** | 기획서 §6.2 |
| **오프라인 진행이 기본** | 시간템포 v0.2 §6 |
| 개입은 **선택적** | 전투 v0.2 §2.2 |
| 결정 주기 1~3시간 | AI설계 §2 |

> **접속은 명령을 위한 것이지 진행을 위한 것이 아니다.**
> 이 원칙이 UI 설계의 출발점이다.

### 1.3 내비게이션 깊이

모바일에서 사용자가 길을 잃지 않는 한계는 **3단계**다.

**현재 설계를 그대로 옮기면:**

```
성도 → 성계 → 권역 → 거점(4층) → 함대 → 인물 편성
                                              = 6단계  ✕
```

**이것이 이 문서에서 해결해야 할 첫 번째 문제다.**

## 3. 화면 구조 — 3단계로 압축

### 3.1 최종 구조

```
[L1] 성도(Star Map)
      19개 성계 노드. 점유 파이 · 분쟁 표식 · 함대 아이콘
        │ 탭
        ▼
[L2] 성계 뷰
      권역 카드 2~4개 (한 화면에 전부)
      각 카드에 소유·국력·공략 진행도 바
        │ 탭
        ▼
[L3] 상세 패널 (하프 시트)
      권역 상세 / 함대 상세 / 인물 상세 / 전투 지시
```

**성계 내부 4층은 별도 화면이 아니다.**

> **2026-08-27 갱신 — L2·L3의 명세가 `screens.md`에서 열렸다.**
> 그 문서 §0.2가 이 그림을 한 곳 고쳤다: **L3은 세부 뷰(권역 내부 4층 · 함대 진형)**이고,
> 위에 적힌 **하프 시트는 층이 아니라 L2 위에 겹치는 오버레이**다.
> **깊이는 그대로 셋이다** — 오버레이를 층으로 세면 §1.3의 압축이 도로 풀린다.

### 3.2 4층 구조의 축약

| 기존 | UI 표현 |
|---|---|
| 외곽 → 궤도권 → 식민지 → 지구형 행성 | **권역 카드의 진행도 바 1개** |

```
[ 형주 중부권 ]  소유: 오
━━━━━━━━━░░░░  공략 진행 68%
외곽 ✓  궤도 ✓  식민지 3/5  행성 —
```

> **내부 계산은 4층을 그대로 유지한다.** 표시만 한 줄로 접는다.
> 공략 중일 때만 세부가 펼쳐지고, 평시에는 소유·국력만 보인다.

### 3.3 성도(L1) 표시 규칙

| 요소 | 표현 |
|---|---|
| 성계 소유 | 노드 색 **파이 차트** (부분 점령 비율) |
| 분쟁 중 | 노드 테두리 점멸 |
| 회랑 | 붉은 이중선 + 관문 아이콘 |
| 고속항로 | 청록 실선 |
| 기저 항로 | 회색 점선 |
| 함대 이동 | 항로 위 광점 + **도착 예정 시각** |
| 특급 성계 | 금빛 후광 |
| **태양계권** | 형주 노드에 별도 마커 |

> **HTML 지도(성계지도 인터랙티브)가 이미 이 구조를 검증했다.**
> 19노드 + 15회랑 + 항로망이 한 화면에 들어간다.

## 4. 핵심 화면 5종

### 4.1 복귀 브리핑 — 가장 중요한 화면

> **오프라인 진행이 기본이므로, 「그동안 무슨 일이 있었나」가 최우선이다.**

접속 시 첫 화면. **자동 표시.**

```
┌─────────────────────────────┐
│  건안 십삼년 시월             │
│  ─────────────────────────  │
│  「그대가 자리를 비운 사이,    │
│   장강에 안개가 걷혔다.」      │  ← 사가 서술체 1~2문장
│                              │
│  ● 제3함대 형주 중부권 도착   │
│  ● 오 사절 도착 — 회담 요청   │
│  ● 남중 반란 확대 (2권역)     │
│  ▲ 천명 −3 (할거 지속)        │
│                              │
│  [ 처리하기 (3) ]            │
└─────────────────────────────┘
```

| 요소 | 설계 |
|---|---|
| 상단 | **사가 서술체 1~2문장** — 프롤로그와 같은 목소리 |
| 중단 | 사건 목록 (최대 6개, 중요도 순) |
| 하단 | **처리 대기 결정 수** — 여기서 세션이 시작된다 |

> **이 화면이 게임의 정체성을 매 접속마다 재확인시킨다.**
> 숫자만 보여주면 방치형 게임이 되고, 문장을 보여주면 사서가 된다.

### 4.2 결정 큐(Decision Queue)

브리핑에서 「처리하기」를 누르면 **대기 중인 결정을 순차 제시**한다.

```
┌─────────────────────────────┐
│  2 / 3                       │
│  ─────────────────────────  │
│  오의 사절이 형주 반환을       │
│  요청한다                     │
│                              │
│  현재 신뢰도  ████████░░ 78  │
│  중부권 국력  20             │
│                              │
│  ○ 전면 반환   천명+  국력−  │
│  ○ 부분 반환   신뢰+  국력−  │
│  ○ 거부       신뢰−−         │
│  ○ 재협상     시간 소요       │
│                              │
│  [ 나중에 ]                  │
└─────────────────────────────┘
```

| 원칙 | 내용 |
|---|---|
| **한 화면 한 결정** | 스크롤 없이 전부 보인다 |
| **결과 미리보기** | 각 선택지에 예상 영향 표시 |
| **「나중에」 허용** | 시급하지 않은 결정은 미룰 수 있다 |
| 3~5개면 세션 종료 | 결정 하나당 **약 40초** |

### 4.3 전투 화면

**개입은 1~2회뿐이므로 전투는 전용 화면이 아니라 결정 큐의 한 항목이다.**

```
┌─────────────────────────────┐
│  적벽 · 3페이즈 교전          │
│  ─────────────────────────  │
│  아군 ████████░░ 사기 72     │
│  적군 ██████░░░░ 사기 58     │
│                              │
│  ⚑ 화공 조건 충족            │
│    주유「미주랑」 +50%        │
│                              │
│  ○ 중앙 돌파                 │
│  ○ 양익 포위                 │
│  ● 화공 시도    ← 권장        │
│  ○ 종심 방어                 │
│                              │
│  10:00 후 자동 (인물 위임)    │
└─────────────────────────────┘
```

| 요소 | 설계 |
|---|---|
| 상단 | 전역명 · 현재 페이즈 |
| 사기 게이지 | **양측 동시 표시** — 승패의 실제 지표 |
| 조건 알림 | 계략·일기토 등 발동 가능 조건 |
| 지시 | 3~4택 |
| **타이머** | 10분 무응답 시 위임 처리 (전투 v0.2 §2.2) |

> **전투 결과 리플레이는 별도 화면에서 사가 서술체로 요약한다.**
> 「그날 장강에는 동남풍이 불었다」

### 4.4 인물 관리 — 자동화 전제

**406명 직접 관리는 불가능하다.** 다음과 같이 계층을 나눈다.

| 계층 | UI |
|---|---|
| **명장 150** | **카드**. 초상·특성·클래스·소속 표시. 직접 배치 |
| **일반 무장 256** | **리스트 항목**. 이름·스탯 요약만. **자동 배치** |
| 재야 | 뽑기 결과 화면에서만 등장 |

**자동 배치 규칙**

```
① 플레이어는 「방침」만 정한다
   — 방어 중시 / 공세 중시 / 균형 / 개발 중시

② 시스템이 클래스·스탯·성향에 따라 자동 배치

③ 플레이어는 예외만 지정한다
   — 「관우는 반드시 형주 중부권에」
```

> **편성 퍼즐(클래스 겹침)은 유지된다.** 다만 그것을 푸는 것은 시스템이고,
> 플레이어는 **핵심 인물의 배치만** 결정한다.

**편성 프리셋**

| 기능 | 내용 |
|---|---|
| 프리셋 저장 | 자주 쓰는 함대 편성 저장 |
| **일괄 명령** | 성계 단위 명령 → 하위 권역 자동 배분 |
| 경고 | 비지 위험 · 지휘관 부재 · 보급 부족 |

### 4.5 외교 화면

```
┌─────────────────────────────┐
│  외교                        │
│  ─────────────────────────  │
│  오        군사동맹  신뢰 78 │
│  위        적대       —      │
│  동이연합  화친      신뢰 44 │
│  대월지    책봉      천명+   │
│  ─────────────────────────  │
│  ⚠ 오의 신뢰도 하락 중        │
└─────────────────────────────┘
```

세력 수가 최대 19개이나 **접촉 중인 세력만** 표시한다. 통상 5~8개.

## 6. 검증 결과 — 들어가는 것 / 안 들어가는 것

### 6.1 ✅ 그대로 들어감

| 시스템 | 근거 |
|---|---|
| 성계 19 + 회랑 15 + 항로망 | HTML 지도로 검증 완료 |
| 전투 5페이즈 | 개입 1~2회이므로 결정 큐 항목으로 충분 |
| 기능 이벤트 40 | 순차 제시. 동시 표시 불필요 |
| 외교 4단계 | 접촉 세력만 표시하면 5~8행 |
| 용병 21 | 목록 화면 |
| 부분 점령 (권역 단위) | 성계 뷰 카드로 표현 가능 |

### 6.2 ⚠ 축약 필요

| 시스템 | 문제 | 해결 |
|---|---|---|
| **성계 내부 4층** | 45 × 4 = 180 단위 | **진행도 바 1개로 접기.** 내부 계산은 유지 |
| **인물 406** | 개별 관리 불가 | **명장만 카드, 나머지 자동 배치** |
| 내비게이션 6단계 | 길을 잃음 | **3단계로 압축** (L1/L2/L3) |

### 6.3 감축하지 않는다 — 권역 45 유지 [확정]

검토 과정에서 **2급 성계의 부권역을 통합해 45 → 36으로 줄이는 안**을 제기했으나 **기각한다.**

**기각 사유**

> **관리 부담을 줄이겠다고 세계의 해상도를 낮추는 것은 순서가 거꾸로다.**

| 문제 | 내용 |
|---|---|
| **역사 생성과 충돌** | 어디가 전장이 될지 미리 알 수 없다. 지금 조용한 권역이 다른 세계선에서는 결전지가 된다 |
| **원전 근거 존재** | 광릉권 — 서주는 도겸·유비·여포·조조 사이를 오갔다. 접으면 이 전개가 표현되지 않는다 |
| **절단 가치 훼손** | AI의 그래프 연산(AI설계 §5.2)은 노드가 촘촘할수록 정확하다. 통합하면 「한 권역만 빼앗아 끊는」 수가 줄어든다 |
| **비지 시스템 약화** | 권역이 굵어지면 고립이 잘 발생하지 않는다 |

**부담은 UI로 푼다**

권역이 45개여도 **플레이어가 45개를 항상 신경 쓸 필요는 없게** 만드는 것이 해법이다.

| 장치 | 내용 |
|---|---|
| **기본 뷰는 성계 단위** | L1 성도에서는 19개 노드만 본다. 권역은 파이 비율로만 표현 |
| **일괄 명령** | 성계 단위 명령 → 하위 권역 자동 배분 |
| **주목 권역만 표면화** | 분쟁 중 · 비지 위험 · 개발 완료 권역만 알림·브리핑에 등장 |
| **자동 위임 단계** | 권역별로 「직접 관리 / 위임」을 지정. 위임 권역은 시야에서 접힌다 |
| **정렬·필터** | 국력순 · 위험순 · 미개발순 |

> **평시에 플레이어가 실제로 다루는 권역은 3~6개다.**
> 나머지 40개는 존재하되 화면에 나타나지 않는다.
> **세계는 촘촘하고, 인터페이스는 성긴다.**

## 7. 추가 설계 — 알림

오프라인 진행이 기본이므로 **알림이 곧 게임 루프다.**

| 유형 | 예 | 기본값 |
|---|---|---|
| **긴급** | 전투 분기점 · 적 함대 접근 · 인재 이탈 경고 | 즉시 발송 |
| 완료 | 항행 완료 · 건설 완료 | 묶어서 발송 |
| 정보 | 천명 변동 · 외교 제안 | 브리핑에만 표시 |

**빈도 상한**

| 항목 | 값 |
|---|---|
| 긴급 알림 | 1일 최대 5회 |
| 완료 알림 | **1일 3회 묶음 발송** (아침·점심·저녁) |
| 야간 (23~07시) | **발송 없음** |

> **알림 피로가 이 장르 이탈의 주원인이다.**
> 회랑 돌파 3시간 45분이 「기다릴 만한 시간」이 되려면
> 그 사이에 방해받지 않아야 한다.
