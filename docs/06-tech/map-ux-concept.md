## 0. 요구 사항과 설계안의 구분

**사용자 확정**은 직접 설명한 요구다. **설계안**은 이를 화면·조작·데이터 관리로 구체화한 이번 문서의 안이며, 사용자 승인으로 간주하지 않는다. **확인 필요**는 기존 설정과 접점이 있거나 기능의 뜻이 더 정해져야 하는 부분이다.

| 상태 | 내용 |
|---|---|
| 사용자 확정 | 플레이 지원 대상은 Windows PC·Android·iOS다. **Windows PC용을 먼저 개발한다.** |
| 사용자 확정 | 게임 화면 진입 시 우주 전체 지도가 보인다. |
| 사용자 확정 | 확대할수록 은하 지형이 드러나고, 더 확대하면 우주 지형이 세밀하고 구체적으로 보인다. |
| 사용자 확정 | 함대·전대는 확대 정도에 따라 간략한 모습에서 상세한 모습으로 바뀐다. |
| 사용자 확정 | 검은 공간은 통행 가능한 빈 공간이다. 녹색은 통과 가능하나 감속되는 소행성·장애물 지대다. 옅은 녹색일수록 장애물이 적고, 짙을수록 많다. |
| 사용자 확정 | 중국 지형을 은하 상세지도의 기반으로 삼는다. 하천 형상은 비가시 지형 참고선으로만 사용하고 성간 항로는 지형을 따라 곡선으로 표시한다. 분지·평원은 전체 면적의 20~30%가 장애 지대다. |
| 사용자 확정 | 거주 행성계는 항성·거주 행성+위성·수성형·금성형 천체로 구성한다. 주변 환경 밀도는 5~10%, 장애물은 소행성·먼지·가스·강한 방사의 고정 혼합이다. 행성 간 경로는 주변보다 낮은 밀도다. 총 밀도 70% 이상은 통과 불가이며 그 미만은 밀도별 비용을 적용한다. |
| 사용자 확정 | 기존 37개 성간 경로를 먼저 고정하고 주변 지형을 배치한다. 회랑은 내부 약 40%, 주변 70% 이상이며 회랑으로 연결된 두 지역은 회랑 밖으로 우회할 수 없다. 기저항로는 이동 명령 때만, 회랑·고속항로는 상시 표시한다. |
| 사용자 확정 | 전체 지도와 최대 확대 지형이 서로 대응한다. 동일 지점을 반복 축소·확대해도 지형이 바뀌지 않는다. |
| 사용자 확정 | 이동은 실시간이다. 사용자가 일시정지한 뒤 경로·함대 진형·속도·무장 등을 변경하고, 재개(Resume) 시 변경 사항을 적용한다. |
| 사용자 요청 범위 | 지도 표시, 함대 이동, 함대전, 행성 전투, 함대 설정 메뉴, 성계·성간 표시를 기존 시나리오에 맞춰 검토한다. |
| 설계안 | 하나의 지도 위에서 정보 밀도와 표현만 바꾸고, 선택 대상과 지휘 맥락을 유지한다. |
| 확인 필요 | 재개와 기존 전투 페이즈 규칙의 관계, 오프라인·시즌 모드에서의 일시정지 적용 범위. 무장 화면은 기존 함종별 제원·전투 지시·편성·기술 계획을 따른다. |

이 문서는 화면 설계다. 새 자원·세력·시나리오·함종·무기 성능을 추가하지 않는다. 수치가 필요한 위치는 기존 정본을 참조하거나 미정으로 남긴다.

## 1. 두 참고 게임에서 적용하는 특징

참고 게임의 이름은 제공되지 않았다. 이하 **우주 게임**과 **삼국지 모바일 게임**으로 구분한다. 원본의 기능은 사용자가 설명한 범위만 확정하며, 정지 이미지에서 보이지 않는 동작을 추정해 원본 기능으로 기록하지 않는다.

| 참고 | 눈에 보이는 특징 | 성한지 적용 |
|---|---|---|
| 우주 게임: 상세 먼지·가스 | 검은 바탕, 낮은 대비의 녹청·갈색 구름, 희소한 별빛 | 상세 공간의 먼지·가스 질감 기준. 배경을 가득 채우는 밝은 성운으로 바꾸지 않는다. |
| 우주 게임: 상세 소행성대 | 회보랏빛 가스, 불규칙한 회색 암석, 크기·깊이·분포 차이 | 상세 장애물의 입체 표현. 동일한 돌을 균일 간격으로 늘어놓지 않는다. |
| 우주 게임: 확대 중 먼지 지대 | 어두운 구름층과 희미한 비정형 경계 | 원거리에서 영역을 먼저 인지하고 가까워지면서 구성 물체가 드러나는 전환. |
| 우주 게임: 전체 지도 일부 | 녹색·보라·갈색 성운층과 미세 입자의 혼합 | 가스·먼지·소행성 지역을 넓은 지형 덩어리로 요약. |
| 우주 게임: 행성 상세 | 표면 질감·명암을 가진 구체, 가까운 명칭, 분리된 시설·부대 표식 | 행성은 입체로, 명칭과 소유·주둔 정보는 별도 GUI로 표시. |
| 우주 게임: 한 단계 확대 | 빈 공간과 농도가 다른 녹색 장애물 지대, 함대 표식과 경로 | 통행 조건과 실제 이동의 관계를 지도에서 읽게 한다. 화면에 보인 사각 영역을 게임의 이동 타일 규칙으로 확정하지는 않는다. |
| 삼국지: 천하 지도 | 큰 지역명, 세력별 영역, 경계, 거점·전투 필터 | 우주 전체의 성역·권역·소유 관계를 한눈에 읽는 정보 구조. |
| 삼국지: 중간 지도 | 영토 구분과 지형이 공존, 다수 거점의 축약 모델·이름·수치 | 성계 사이의 관계에서 권역·행성·거점 분포로 정보가 구체화되는 단계. |
| 삼국지: 확대 지도 | 산맥·강·길·거점의 위치 관계가 명확, 상단 상태·우측 부대·하단 명령 | 우주 지형과 이동 가능 공간을 식별하면서 함대를 지휘하는 화면 구성. |

두 참고의 결합 기준은 **우주 게임의 공간·물성 표현 + 삼국지 게임의 영토·거점·부대 판독 구조**다. 지상의 산·강 모양을 그대로 우주에 놓는 방식은 요구로 간주하지 않는다.

## 2. 기존 세계관과 지도 대상

기존 `star-map.md`의 **19개 성계, 45개 권역, 15개 회랑**을 대상으로 한다. 성역은 성계의 행정 명칭으로 같은 대상을 가리킨다. 권역은 소유·부분 점령을 표시하는 단위다. 성계 내부의 행성과 거점을 각각 성계 하나로 바꾸지 않는다.

| 화면 대상 | 표시 원칙 | 문서 근거 |
|---|---|---|
| 성계/성역 | 전체에서는 큰 이름과 범위, 확대하면 내부 권역과 거점으로 분해 | `star-map.md` §0~1 · `screens.md` §0.1 |
| 권역 | 고정된 지리 범위 위에 현재 소유자를 표시. 성계 내부의 서로 다른 소유가 드러남 | `partial-occupation.md` · `scenario-200-208.md` ACT 1 |
| 행성 | 구체·이름·소유 표식. 선택 시 시설·방어·주둔 상세 | `star-map.md` §1·§5 |
| 궤도 도시·식민지·조선소·관문 | 해당 종류의 작은 모델/아이콘과 선택 패널 | `star-map.md` §0·§5 |
| 성간 연결 | 고속항로·기저 항로·회랑의 구분과 양 끝 목적지 | `star-map.md` §2~4 |
| 함대/전대 | 같은 부대 ID를 축척별 표식·진형·함선 모습으로 표현 | `ship-specs.md` §2·§5~7 |

예를 들어 **형주성역 → 태양계권 → 구지와 인근 공간**은 동일한 장소를 확대하는 흐름이다. 형주의 북부권·중부권·남부권·태양계권은 각각 다른 주인을 가질 수 있다. 구지의 위치나 지형은 소유권이 바뀌어도 이동하지 않는다. 구지·형혹·태음의 정밀 좌표와 거리는 이 문서에서 임의로 정하지 않는다.

208 시나리오의 **사예 → 남양 → 양번관문 → 형주** 이동, **태양계권 궤도의 적벽 전투**, 전후 권역 분할을 같은 지도에서 따라갈 수 있어야 한다. 적벽 표식은 시나리오 조건과 현재 전투 발생에 따라 나타나며, 미래의 역사적 전투를 항상 예정 사건으로 표시하지 않는다.

## 3. 전체 지도부터 최대 확대까지

다음 Z0~Z4는 이번 안의 **표현 구간 이름**이다. 고정된 다섯 화면이나 다섯 번의 확대 클릭을 뜻하지 않는다. 기존 문서의 화면 깊이 L1~L3 및 제작 단계 L1~L3와 구별한다. 정확한 확대 배율은 화면 검토 이후 정한다.

| 구간 | 주로 보이는 범위 | 지형 | 천체·거점 | 함대·전대 | 기본 명칭 |
|---|---|---|---|---|---|
| **Z0 전체** | 19개 성계 전체 | 큰 성운·먼지·소행성 혼합 영역, 주요 빈 공간 | 성계 중심과 주요 거점 표식 | 관측 가능한 함대의 집계 표식, 진행 중 전투 위치 | 성역명·주요 회랑명 |
| **Z1 광역** | 인접한 여러 성계 | 검은 통행 공간과 녹색 장애물 농도, 큰 경계 | 권역 분포와 주요 행성·관문 | 함대별 표식, 방향, 선택 함대의 목적지 | 성역명·주요 권역명 |
| **Z2 성역/권역** | 성계와 그 내부 권역 | 가스·먼지·소행성대의 분포 차이, 좁아지는 통로 | 거점 종류가 구분되는 축약 모델 | 함대 진형 외곽과 전대 집단, 간략 상태 | 권역명·행성명·거점명 |
| **Z3 국지** | 행성 인근·회랑 일부·교전 지역 | 성운층과 작은 소행성 군집, 국지 경계 | 입체 행성, 궤도 시설, 주둔 위치 | 전대 단위 배치와 실제 진형, 기함 식별 | 선택 관련 대상 우선 |
| **Z4 최대 상세** | 선택한 전대·시설·행성 주변 일부 | 개별 소행성의 형상·배치·빈틈, 가스 깊이 | 표면 질감과 명암, 가까운 시설 형상 | 함종별 선체·방향·간격·손상과 진형 내 위치 | 선택 대상·작전 대상 위주 |

Z0에서는 작은 소행성을 하나씩 그리지 않는다. Z4에서는 전체 지도에 없던 지형 종류나 밀집 구역을 새로 만들어 보여주지 않는다. Z0의 넓은 녹색 영역은 Z4의 장애물 분포를 축약한 결과여야 한다.

**전환 동작 설계안**

- 손가락 두 개의 확대 중심 또는 마우스가 가리키는 지점을 기준으로 확대한다. 확대 중 그 지점이 다른 곳으로 밀려나지 않는다.
- 성역 경계에 걸친 화면은 양쪽 공간을 함께 보여준다. 경계를 넘을 때 별도 지도로 순간 이동하지 않는다.
- 이름·아이콘은 점진적으로 교대한다. 같은 함대가 축약 아이콘과 상세 모델 양쪽에 중복으로 존재하는 듯 보이지 않게 한다.
- 확대 기준 부근에서 조금씩 왕복해도 표식이 깜빡이지 않도록 진입·이탈 기준을 조금 다르게 둔다.
- 축소로 여러 부대가 겹치면 집계 표식으로 묶고, 선택하면 구성 목록을 펼친다. 묶인 부대의 월드 좌표는 바뀌지 않는다.
- 확대·축소·패널 열기는 시간 진행 상태를 바꾸지 않는다. 시간은 사용자가 누른 일시정지/재개 상태를 따른다.
- 메뉴에서 복귀하면 이전 중심 좌표·배율·선택 함대를 유지한다. 최초 진입이 전체 지도라는 요구와 메뉴 복귀 위치를 구분한다.

## 4. 우주 지형과 색의 의미

| 대상 | 전체/광역 표시 | 상세 표시 | 통행·판독 의미 |
|---|---|---|---|
| 빈 공간 | 거의 검은 영역, 드문 별빛 | 같은 공간에 장애물 개체 없음 | 연결된 개방 구역 안에서 자유 통행. 회랑 차단대를 넘을 수 없음 |
| 낮은 장애물 밀도 | 옅고 투명한 녹색 | 드문 소행성과 넓은 빈틈 | 통과 가능, 지형에 따른 감속 |
| 지형 참고선 | 지리 대조 모드의 청회색 선 | 황하·장강·한수·위수·회수 등 지형 관계와 항로 굴곡의 제작 기준 | 이동 밀도에 관여하지 않으며 일반 지도에는 표시하지 않음 |
| 분지·평원 대응 공간 | 열린 공간과 분산된 녹색 패치 | 전체 면적의 20~30%만 장애 지대 | 나머지는 개방 공간. 수로는 항상 개방 |
| 높은 장애물 밀도, 70% 미만 | 더 짙고 응집된 혼합색 | 소행성·먼지·가스·방사가 섞인 좁은 빈틈 | 통과 가능, 낮은 밀도보다 큰 비용 |
| 총 밀도 70% 이상 | 짙은 경계와 통과 불가 표시 | 환경 위험의 합이 임계 이상 | 함대·우주선 통과 불가 |
| 먼지·가스 | 낮은 대비의 구름·입자층 | 녹청·갈색 또는 회보랏빛 안개와 깊이감 | 외관은 참고 이미지 기준. 가스의 독립 감속·시야·피해 효과는 미확정 |
| 혼합 지대 | 색과 입자가 겹친 넓은 비정형 영역 | 동일 구성 비율의 가스·먼지·소행성 | 보이는 분포와 이동 판정이 대응 |
| 회랑 | 연결되는 양 끝과 협착부, 관문 표식 | 내부 혼합 장애 약 40%, 주변 차단대 70% 이상 | 험지 사이의 유일 통과로. 외부 빈 공간 우회 불가 |

사용자의 ‘짙은 녹색’은 **녹색의 농도·차폐가 커짐**으로 표현한다. 검게만 낮춰 빈 공간처럼 보이게 하지 않는다. 밀집 지대는 녹색 성분·입자 밀도·경계로 검은 빈 공간과 구별되어야 한다.

**밀도 표시와 이동 판정은 같은 원본 밀도 값을 쓴다.** 색은 평균 밀도의 요약이며, 선택한 경로 패널에서는 실제 이동에 쓰는 비용·도착 예정을 수치로 보여준다. 색 하나가 아니라 소행성·먼지·가스·강한 방사의 총 밀도로 판정하며, 지도 v3에서 **70% 이상은 통과 불가**다. 70% 미만의 비용 기울기는 밸런스 초안이다.

세력권 색은 지형 녹색과 구별해야 한다. 설계안은 **세력 문장·외곽선·이름을 기본으로 하고, 영토 채움은 옅은 보조층**으로 두는 것이다. 지형 밀도를 보는 중 세력의 녹색 채움이 소행성대로 오인되지 않게 한다. 소유 표시를 끄거나 켜도 장애물 밀도는 바뀌지 않는다.

지형 경계는 약한 비정형 선, 행정 경계는 문장과 이름이 붙은 선, 선택 범위는 강조 테두리로 구분한다. 참고 이미지의 사각형·다각형·경계선을 모두 영토나 통과 불가 지역으로 단정하지 않는다.

## 5. 성계·성간·항로 표시

| 대상 | 지도 위 표시 | 선택했을 때 |
|---|---|---|
| 성역 | 고정 위치의 큰 성역명, 옅은 범위선, 권역별 소유 차이 | 권역 목록·소유·분쟁·주둔 함대 |
| 권역 | 중간 확대부터 이름·경계·소유 문장, 주권역 표식 | 소유·담당관·공략 진행·거점 목록 |
| 행성·시설 | 모델 가까이에 이름과 작은 종류·소유 표식 | 해당 대상의 방어·시설·주둔 상세 |
| 고속항로 | 기존 청록 계열 실선과 방향 표식 | 출발/도착 성역·연결 권역·통행 상태·예상 소요 |
| 기저 항로 | 평상시 숨김. 함대 이동 명령 때 실제 경로로 표시 | 목적지·예상 소요·지형 비용 |
| 회랑·관문 | 기존 적갈색 이중선/협착 기호와 이름 | 귀속 권역·통제 세력·통행/전개/진형 조건 |
| 다른 성역으로 나가는 연결 | 화면 가장자리의 연결선과 목적지 이름 | 같은 좌표계를 따라 연결 방향으로 화면 이동 |

**상시 전략 연결과 함대가 선택한 이동 경로를 구별한다.** 회랑·고속항로는 지속되는 지도 정보이고, 기저항로는 함대 이동 명령을 내릴 때만 실제 예정 경로로 나타난다. 경로에는 화살표와 함대명이 붙는다. 기존 문서에서 점선은 오래된 관측 정보에 쓰이므로, 새 경로라는 이유만으로 점선을 사용하지 않는다.

성역·권역 이름은 가까워질수록 무조건 커지는 방식이 아니라, 해당 축척에서 읽어야 할 이름으로 교대한다. 큰 성역명이 상세 전투를 덮지 않게 한다. 선택 대상·현재 명령 목적지·현재 전투의 명칭은 우선 유지하고, 겹치는 비선택 명칭은 접는다.

### 5.1 경로 우선 이동과 회랑 [사용자 최신 확정]

2026-09-04 사용자는 회랑을 ‘두 지점 사이의 지형이 험해서 해당 회랑으로만 이동 가능한 곳’으로 확정하고, 37개 성간 경로를 먼저 고정한 뒤 지형을 배치하도록 지시했다. 이 결정은 2026-09-03의 회랑 우회 허용 해석을 폐기한다.

- 검은 공간에서는 선을 따르지 않고 진로를 선택할 수 있지만, 연결된 개방 구역 밖의 70% 이상 차단대를 통과할 수 없다.
- 회랑 내부는 약 40%로 통과 가능하고 주변은 70% 이상이므로, 회랑으로 연결된 두 지역은 반드시 회랑을 지난다.
- 기저항로 15개는 평상시 숨기고 함대 이동 명령의 실제 경로로만 표시한다.
- 회랑 경로 13개와 고속항로 5개, 고속항로+관문 4개는 전략 연결로 상시 표시한다.
- 고속항로는 이탈할 수 있으나 이용 시 속도·비용 이점이 있다. 고속항로+관문은 일반 구간과 회랑 구간의 판정을 나눈다.
- 하천 형상은 이동 밀도 판정에서 제외한다. 회랑과 항로의 통행 규칙은 하천 참고선과 독립적으로 적용한다.

## 6. 공통 화면 배치 설계안

**2026-09-03 사용자 확정: Windows PC용을 먼저 개발하고 Android·iOS에서도 플레이를 제공한다.** 현재 화면·입력 검토는 Windows PC의 마우스·키보드를 우선 기준으로 한다. Android와 iOS의 개발 순서는 별도로 정해지지 않았다.

기존 1600×900은 초기 레이아웃 검토용 크기로만 참조한다. 태블릿 고정 해상도나 PC의 유일한 지원 해상도를 뜻하지 않는다. 우주 공간이 중앙 대부분을 차지하고, 상단 상태·측면 선택·하단 명령의 위치는 확대해도 유지한다. 창 크기·화면 비율·UI 배율이 달라져도 지도 좌표는 바뀌지 않으며, 패널 치수는 후속 화면 시안에서 구체화한다.

| 자리 | 기본 화면 | 선택/지휘 중 |
|---|---|---|
| 상단 왼쪽 | 군주/세력, 기존 자원과 천명 요약 | 유지 |
| 상단 중앙 | 게임 시각, 현재 위치와 지도 범위 | 현재 성역·권역, 선택 함대의 위치 |
| 상단 오른쪽 | **일시정지** 또는 **재개**, 진행 상태 | 일시정지 중에는 ‘일시정지 · 변경 대기 n’ |
| 왼쪽 접이식 도구 | 전체 보기·검색·지형/세력권/항로/거점/전투 필터 | 경로 지휘 중에도 필요한 지도 필터 사용 가능 |
| 중앙 | 연속 확대 지도 | 선택 테두리·경로·진형 미리보기·교전 영역 |
| 오른쪽 | 아군 함대 바로가기 목록: 제독 초상·함대명·상태 | 선택 상세 패널로 전환. 목록과 상세를 겹쳐 지도를 가리지 않음 |
| 하단 | 현재 대상의 요약, 사건/명령 상태의 축약 행 | 대상에 맞는 명령 버튼과 수정 중인 설정 |

참고 삼국지 화면의 판촉·이벤트 버튼이나 참고 우주 게임의 상단 도착 알림은 그대로 이식할 항목이 아니다. 이번 범위에서는 사용자가 요청한 지도·지휘 기능만 배치한다.

PC에서는 지도를 클릭해 선택하고 하단에서 명령을 고른다. 빈 공간을 단순 클릭한 것만으로 함대가 움직이지 않는다. **이동 명령 편집 중에 목적지를 클릭했을 때** 경로가 수정된다. 카메라 드래그와 경로점 드래그는 조작 시작 대상을 기준으로 구분한다. 이후 절의 ‘탭’은 모바일 대응 조작이며, PC 우선 화면에서는 해당 버튼·대상을 클릭하는 것으로 읽는다.

일시정지 상태는 배경을 크게 어둡게 만드는 대신 상단의 지속 표시와 버튼 상태로 알린다. 지형과 함대 상태를 정확히 읽을 수 있어야 한다.

## 7. 실시간·일시정지·재개와 함대 이동

### 7.1 상태와 적용 시점

| 상태 | 지도/시간 | 설정 |
|---|---|---|
| 진행 중 | 함대와 게임 시간이 실시간으로 진행 | 현재 경로·진형·속도·무장 상태 표시 |
| 사용자가 일시정지 | 초안에서는 캠페인 시뮬레이션 시간을 정지하는 것으로 해석. 확대·선택은 계속 가능 | 기존 상태를 유지한 채 수정 시작 |
| 일시정지 중 수정 | 함대는 실제 위치에서 정지 | 현재값과 재개 시 적용할 값을 별도로 표시 |
| 재개 클릭 | 수정안을 검증하고 적용한 뒤 시뮬레이션 진행 | 경로·진형·속도·무장 변경 반영 |

사용자가 일시정지한 상태에서 메뉴를 닫거나 다른 함대를 선택해도 자동 재개하지 않는 안이다. 메뉴 열기 자체는 자동 일시정지로 정하지 않는다. 시즌·네트워크 모드 및 오프라인 진행과의 관계는 별도 확인이 필요하다.

재개 시 **설정 적용**과 **물리적 이동 완료**를 구분한다. 새 경로가 적용되었다고 함대가 목적지로 순간 이동하지 않는다. 진형 변경도 적용된 목표 진형과 전개 중 상태를 표현할 수 있으나, 실제 전개 시간·전투 효과가 바뀌는 시점은 기존 페이즈 규칙과 조정해야 한다.

### 7.2 경로 변경 화면

1. 함대 선택 → **이동/경로** 선택.
2. 일시정지 후 목적지·경유점을 지도에서 지정하거나 옮긴다.
3. 현재 경로는 옅은 실선, 수정 경로는 강조 실선과 ‘수정안’ 표식으로 구별한다.
4. 지형을 지나는 구간과 회랑 진입점에 감속·진형 제한을 표시한다.
5. 하단에 **목적지 / 남은 거리 / 예상 소요 / 지형 감속 / 경유 회랑**을 표시한다.
6. **재개**를 누르면 수정 경로로 항행한다.

예상 소요는 실제 경로 계산 결과를 사용한다. 녹색 지역을 가로지르는 짧은 길과 검은 공간으로 우회하는 긴 길의 시간 차이는 같은 이동 규칙으로 산출한다. 기존 성간 구간 시간과 새로운 국지 거리·밀도 감속을 무조건 중복 곱하지 않는다. 계산 분담은 검토 포인트 6에서 확정한다.

수정 버튼은 **경유점 추가 / 선택 경유점 삭제 / 해당 수정 취소**를 사용한다. 수정 취소는 일시정지 전에 실행 중이던 경로로 되돌린다. 이미 이동한 거리를 되감지 않는다.

### 7.3 여러 함대의 변경과 실패 처리

일시정지 중 함대를 바꿔 선택하면 각 함대의 수정안을 보관하는 안이다. 상단 ‘변경 대기 n’을 누르면 함대별 **경로·진형·속도·무장 변경 요약**을 펼친다. 입력만 하고 적용을 잊었는지 알 수 있어야 한다.

재개 전 지형·권한·보유 장비·대상 유효성을 함께 검사한다. 오류가 있으면 해당 함대와 이유를 표시하고 일시정지를 유지하는 안이다. 일부 설정만 조용히 버리고 진행하지 않는다. 사용자에게 수정 취소 또는 오류 해소 경로를 제공한다.

### 8.1 함대 설정 패널

**진형**은 기존 7종(어린·학익·방원·안행·봉시·장사·팔진)을 작은 배치 그림과 이름으로 표시한다. 선택한 후보를 중앙 지도에서 실제 전개 방향에 맞춰 미리 본다. 현재 진형의 실제 함선은 움직이지 않고, 후보는 외곽 윤곽과 ‘재개 시 적용’ 표식으로 구별한다.

회랑 폭·지휘관 조건 등 기존 제약을 함께 표시한다. 대회랑에서 장사진 외 후보가 불가능한 기존 규칙을 이번 메뉴가 임의로 해제하지 않는다. 전투 중 페이즈 사이 1회 변경 규칙과 ‘재개 시 적용’의 관계는 검토 포인트 2에 남긴다.

**속도**는 현재 실제 속도와 사용자가 설정하는 목표 속도를 나눠 표시한다. 지형 감속 때문에 목표 속도에 도달하지 못하면 그 이유와 예상 소요를 함께 보여준다. ‘게임 시간 배속’과 ‘이 함대의 항행 속도’는 다른 조작으로 명확히 표시한다. 속도 범위·함종 제약·연료 대가는 미정이다.

**무장**은 기존 함종별 장비·탄약·기술 해금과 전투 지시를 묶어 표시한다. 함대 구성 변경은 기존 편성안·강화 축으로, 전투 중 운용은 기존 페이즈 지시와 특수 무기·보급 조건으로 연결한다. 구체적인 패널은 §8.2를 따른다. 함포를 다른 함종의 장비로 교체하는 슬롯 편집이나 신규 사격 모드는 기존 문서에서 확인되지 않아 추가하지 않는다.

**편성**은 기존 `SC-F1` 함대 목록·`SC-F2` 편성·`SC-F3` 임명 구조를 연결한다. 지도 우측에서는 요약과 진입점을 제공하고, 긴 인물 목록이나 함종별 편성은 전용 시트에서 편집한다. 재개 시 변경 적용이라는 공통 규칙을 연결할 범위는 표시한다.

전대 28척·함대 140척·방면군 700척은 기존 **표준 편제**다. 손실·분할된 부대도 항상 정원으로 표시하지 않고 현재 척수를 쓴다. 중간 축척에서 모델 수를 줄여도 부대 수나 실병력이 줄어든 것으로 읽히지 않게 한다.

**변경 가능한 기존 항목의 연결**

- **전투 운용:** 기존 지시 중 해당 페이즈에 가능한 항목을 표시한다. 예를 들어 ② 포화에는 원거리 유지·거리 압축·포격 집중 등 기존 지시를 연결한다. 무기별 자동 발사 허용 스위치·표적 우선순위는 정본에 없으므로 새 규칙으로 추가하지 않는다.
- **함대 구성:** 기존 6편성안(균형·회랑 돌파·개활 결전·강습 특화·성계 공략·봉쇄 유지)과 강화 축 **화력·돌파·지속 중 하나, ±2단계**를 사용한다. 1단계는 함종 비율 5%p 이동이며 장비 자체의 레벨 상승이 아니다. 결과 함종 수·무장 요약·유지점·지휘 한도·대가를 비교한다.
- **기술 개발:** 세력 단위의 **화력·방어·특수 0~5단계**를 조회하고 기존 연구 메뉴로 연결한다. 편성 강화의 화력·돌파·지속과 구분한다. 일시정지 중 기술 수치를 직접 올리거나 재개 시 연구를 즉시 완료하지 않는다.
- **일시정지 중 수정:** 허용된 지시를 수정안으로 보관하고 재개 시 반영한다. 반영 전에 보유 장비·해금·잔탄·현재 전투 단계·표적 조건을 확인한다. 적용된 지시의 실제 발사·설치·보급 완료는 각 기존 실행 조건을 따른다.

특수 기술 3·5단계의 무기, 장비별 세부 운용 명령, 전투 중 편성의 실제 재배치 조건은 기존 문서에도 남은 설계 공백이다. 이를 이유로 이미 있는 무장 계획을 다시 질문하지 않는다. 현재 패널은 정의된 무장과 명령을 사용하며, 정의되지 않은 기능을 승인된 사양으로 표시하지 않는다.

## 9. 함대전과 행성 전투

### 9.1 함대전

전체 지도에서는 해당 위치에 교전 표식과 참여 함대 요약을 표시한다. 확대하면 **같은 위치·같은 지형·같은 함대**가 상세 전장으로 드러난다. 전투를 선택했다고 임의의 소행성 배경으로 교체하지 않는다.

| 자리 | 전투 중 표시 |
|---|---|
| 상단 | 게임 시각·일시정지/재개 유지, 현재 전투 단계 |
| 중앙 지도 | 양측 함대의 진형·접근 방향·이동 경로·지형과 교전 모습 |
| 오른쪽 | 선택 함대의 현재 전력·사기·보급·무장·제독 |
| 하단 | 현재 단계에서 가능한 지시·진형·속도·무장·이탈 관련 조작 |

기존 전투는 **접적 → 포화 → 교전 → 강습 → 결착**의 5페이즈와 사기 붕괴가 중심이다. 페이즈별 기존 지시를 맥락 메뉴로 노출한다. 모든 페이즈 버튼을 언제나 동시에 활성화하지 않는다. 사기는 정본인 **0~125, 기준선 100, 붕괴 위험 39 이하**로 표시한다.

확대는 정보를 더 자세히 표현하는 조작이지 적 정보 해금이 아니다. 기존 관측 단계 0(미접촉)·1(포착)·2(판독)와 신선도에 따라 표시한다. 판독하지 않은 적의 실제 함종 모델·정확한 진형을 최대 확대에서 노출해 정보를 유출하지 않는다.

현재 초안은 메뉴와 표시를 정의한다. 소전투 자동 처리, 전 페이즈 수동 지휘, 사용자의 임의 일시정지 개입이 어느 규모까지 적용되는지는 기존 규칙과 함께 인터뷰로 확정한다.

### 9.2 행성·거점 공략

행성을 선택하면 화면 중심을 해당 행성과 주변 공간에 맞추고, 우측에 행성 정보와 **공략 단계**를 표시한다. 단계는 기존 **외곽 → 궤도권 → 식민지 → 지구형 행성**을 사용한다. 이 네 단계는 줌 단계가 아니라 공략의 진행 상태다.

| 공략 대상 | 지도 표현 | 메뉴/상태 표시 |
|---|---|---|
| 외곽 | 진입 항로·관측 거점·방어 함대 | 참가 함대 선택, 이동/공격 지시, 외곽 확보 여부 |
| 궤도권 | 행성 가까운 시설·방어망과 공격 함대 | 공략 명령, 공성함 등 필요 조건, 공격 가능한 표적 |
| 식민지 | 실제 배치된 각 시설과 교전 표식 | 거점별 선택, 점령 n/m, 강습 진행 |
| 행성 | 입체 행성과 관련 표적·부대 | 공성·강습 진행과 확보 상태 |

진입할 수 없는 단계는 이름·상태·이유를 남긴다. 예: ‘공성함 없음 — 궤도권 공략 조건 미충족’. 내부를 아직 공략하지 못했다는 이유로 행성 자체를 지도에서 숨기거나 좌표를 이동하지 않는다.

무장 위성의 수·성능·전투 규칙은 기존 개발 계획에서도 후속 설계 대상(G-08)이다. UI에 방어망 정보 자리를 두되 새 수치를 만들어 채우지 않는다. 지상 전투를 별도 조작 화면으로 여는지, 궤도 지도에서 진행 상황과 지시를 다루는지는 확인이 필요하다.

행성을 확보한 뒤에는 공략 패널을 소유·주둔·방어 상태로 바꾼다. 시나리오의 권역 귀속 판정을 받아 표시하며, 한 행성의 승리를 전체 성역 점령으로 표현하지 않는다.

## 10. 축척 간 지형 일치를 위한 시스템 요구

> **2026-09-04 공간 데이터 V-69:** [은하 상세지도](../01-world/galaxy-detail-map.md) · [좌표표](../01-world/galaxy-map-coordinates.md) · [독립 미리보기](../assets/galaxy-detail-map.html). 성간 항로는 지형 추종 곡선이며 하천은 이동 규칙이 아닌 지형 참고선이다. 분지·평원은 전체 면적의 20~30%가 장애 지대다. 실제 게임 이동·전투·저장 연동 완료는 아니다.

### 10.1 하나의 장소, 하나의 원본

화면별 배경을 따로 제작해 확대 시 교체하는 것만으로는 사용자의 지형 일치 요구를 만족할 수 없다. **공통 월드 좌표와 영구 지형 데이터**가 필요하다. 현재 관계도의 ID 순서 기반 배치는 이름 순서의 일관성이지, 확대 가능한 실제 지형의 일관성은 아니다.

| 데이터 | 역할 | 고정/변경 |
|---|---|---|
| 지도 식별자·버전 | 어떤 지리 원본인지 식별 | 캠페인 동안 고정 |
| 성계·권역·행성·시설 ID와 좌표 | 모든 축척의 같은 대상을 연결 | 정적 위치 고정, 동적 상태만 별도 변경 |
| 지형 경계·가스/먼지/소행성 밀도 | 광역 색과 상세 개체, 통행 비용의 공통 근거 | 지형 원본 고정 |
| 소행성 ID·위치·크기·형상·방향 | 확대할 때 동일한 암석을 복원 | 카메라와 독립적으로 고정 |
| 항로·회랑·관문의 공간 형상과 연결 | 광역 경로와 상세 통로의 대응 | 기존 설정과 대조한 뒤 고정 |
| 함대 ID·좌표·방향·편성·명령 | 움직이는 부대의 실제 상태 | 게임 시간·명령에 따라 변경 |
| 소유·전투·점령·시설 손상 | 지리 위에서 변화하는 캠페인 상태 | 시나리오와 플레이에 따라 변경 |
| 카메라·선택·확대 정도 | 어떤 부분을 어떻게 보는지 결정 | 표시 상태이며 지형 생성 입력이 아님 |

행성과 함대가 서로 다른 축척 체계를 써야 하더라도 월드↔성계 로컬↔상세 로컬 좌표 변환은 고정되어야 한다. 화면의 가로세로 비율이 바뀌어도 실제 위치가 재배치되지 않는다. 천체·함선 모델을 가독성 때문에 과장할 경우, 시각 크기와 이동 판정 공간을 별도로 명시한다.

### 10.2 생성과 불러오기

성계와 권역, 회랑의 구조는 기존 고정 설정을 따른다. 상세 암석 배치에 절차 생성을 쓰는 경우 **지도 시드 + 지형 구역 ID + 생성기 버전 + 자산 버전**을 고정한다. 매번 확대할 때 현재 시각이나 새 난수로 생성하지 않는다.

기존 37개 성간 경로는 지형 생성의 선행 입력이다. 회랑·고속항로·기저항로의 역할에 따라 주변 밀도와 표시 정책을 정하며, 특정 경로를 선택할 때마다 지형을 별도로 생성하지 않는다.

전투·AI용 난수와 지형 생성 난수를 분리한다. 카메라를 몇 번 확대했는지, 어느 순서로 지역을 방문했는지가 다음 전투 결과나 지형에 영향을 주어서는 안 된다. 비동기 로딩 순서도 암석 배치에 영향을 주지 않는다.

광역 지도는 같은 밀도장의 축약 결과를 사용한다. 상세는 그 밀도장과 배치 데이터에서 읽는다. 성능을 위해 주변 구역만 불러오더라도 내린 구역을 다시 읽으면 동일한 데이터가 복원되어야 한다. 인접 구역 경계에서 암석 중복·빈 줄·밀도 단절이 생기지 않게 소유 구역과 식별자를 정한다.

같은 시드만 저장하는 것으로 충분하지 않을 수 있다. 생성기·자산 순서가 바뀌면 결과도 바뀐다. 구버전 생성기와 자산을 보존할 수 없으면 해당 지형 배치 원본을 저장하거나 버전별 정적 자산으로 유지해야 한다. 기존 캠페인의 지형을 업데이트로 조용히 다시 생성하지 않는다.

### 10.3 표시와 판정의 일치

- 통행 가능한 공간·지형 감속·회랑 폭 판정은 카메라 축척과 무관한 공간 데이터를 읽는다.
- 상세 화면에서 물체를 적게 그리는 최적화가 실제 장애물을 제거하지 않는다.
- 저해상도 지형 요약이 중요한 빈틈이나 협착을 가리는 경우 별도 통행 표식으로 위치를 보존한다.
- 전투장 지형은 해당 월드 구역을 참조한다. 별도 연출 뷰가 필요해도 실제 지형과 부대 상태를 같은 ID로 연결한다.
- 장식 별빛·안개 애니메이션이 통행 경계·밀도 판정·고정 암석 위치를 바꾸지 않는다.

현재 요청은 시간 경과에 따른 지형 변형을 정하지 않았다. 기본 설계는 고정 배치이며, 회전·가스 흐름 같은 연출을 넣더라도 같은 게임 시각에는 같은 모습이어야 한다. 향후 파괴·채굴 등을 추가하면 그 변경은 별도 상태로 저장해야 하며, 이번 초안에 해당 기능을 추가하지 않는다.

### 10.4 저장·일시정지의 접점

기존 저장 계약은 시드·명령 로그에 기반한다. 새로운 공간 지도를 도입할 때 지도 버전·지형 시드/배치·생성기/자산 버전의 참조가 복원 가능해야 한다. 카메라 방문 이력으로 지형을 복원하지 않는다.

경로·진형·속도·무장 수정안은 실행 중 상태와 구분한다. 재개 시 확정된 변경 묶음의 적용 시각·순서를 기록해 저장 복원에서도 동일하게 적용한다. 일시정지 상태로 저장할 때 수정안을 함께 보존할지 여부도 저장 규격에 명시한다. 초안은 **일시정지 상태와 대기 수정안 보존**을 제안한다.

정지 시간 동안 누적된 실제 시간을 재개 직후 몰아서 진행하지 않아야 한다. 이는 사용자가 경로를 고치는 동안 함대가 정지했다는 의미를 유지하기 위한 조건이다. 앱 종료 후 시간 처리와는 별도의 계약이다.

| 저장 복원 | 앱을 종료하고 같은 저장을 열어도 지도 원본과 지형 지문이 같음 |
| 표시와 이동 | 같은 경로의 감속·회랑 판정·도착 시간이 확대 수준과 무관함 |
| 자유항행 범위 | 연결된 검은 공간 안에서는 임의 경로 지정 가능. 통과 불가 지형과 회랑 차단대는 넘지 못함 |
| 회랑 경계 판정 | 중심 통로는 약 40%로 통과 가능하고 주변 교차 차단대는 70% 이상. 회랑 밖 직접 우회가 성립하지 않음 |
| 경로 표시 | 기저항로는 명령 시에만, 회랑·고속항로는 상시 표시 |
| 일시정지 | 카메라·메뉴는 조작 가능, 합의된 시뮬레이션 범위의 시간과 부대 상태는 정지 |
| 수정안 | 현재 상태와 재개 적용안이 구별되고, 메뉴를 닫아도 수정안이 유실되지 않음 |
| 재개 | 유효한 변경을 한 번 적용한 뒤 진행. 정지 중 시간이 몰아서 흐르지 않음 |
| 전투 연계 | 상세 전장의 지형이 같은 월드 좌표의 지형과 일치 |
| 관측 | 확대만으로 미관측 적의 편성·진형·무장을 알 수 없음 |
| 행성 공략 | 공략 단계·주둔·소유 변화는 보여주되 행성 지리 위치는 유지 |
