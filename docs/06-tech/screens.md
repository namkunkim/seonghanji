## 0. 이 문서가 닫는 것

`ui-design.md` §8이 화면 13종을 **우선순위만 매겨 두고 명세 없이** 남겨 두었다.
그중 셋이 요구 B6·B7이고 로드맵 S3.3·S3.4·S3.6이며, **24주차 【최소 플레이 가능】의 내용물**이다.

| 요구 | 로드맵 | 이 문서 | 화면 ID |
|---|---|---|---|
| **B6** 전쟁 화면 — 성역 뷰 + 세부 뷰, **진형 갖춘 함대** | S3.3 · S3.4 | §2 · §3 | `SC-L2` · `SC-L3` |
| **B7** 함대 규모·배치 — **사용자 정의 / 추천 모드** | S3.6 | §4 | `SC-F1` · `SC-F2` · `SC-F3` |

**이 문서가 정하지 않는 것:** 명령 메뉴 3종(S3.5 — 입력은 `domestic.md` §7 ⑧) ·
알림 인터럽트(S3.7) · 전투 진행 표현(S4) · 3D 전투 씬(S5 · 요구 B9).
**진입점만 정의하고 넘긴다.**

### 0.1 「성역 뷰」와 「성계 뷰」는 같은 화면이다

`star-map.md` §1이 **「성역은 행정 명칭, 성계는 천체 단위. 동일 대상」**이라고 적었다.
발주자 요구(B6)는 **성역 뷰**, `ui-design.md` §3.1은 **성계 뷰**로 쓴다.

**화면 이름은 성역 뷰로 통일한다.**
플레이어가 그 화면에서 다루는 것은 항성과 궤도가 아니라 **소유·생산·위임·주둔**이다.
즉 천체가 아니라 **통치 단위**이며, 그것의 이름이 성역이다.

### 0.2 내비게이션 3단계는 유지된다 — 다만 L3의 정의를 고쳤다

`ui-design.md` §3.1은 L3을 **「상세 패널(하프 시트)」**로 적었고,
`roadmap-solo.md` S3.4는 L3을 **「세부 뷰 — 권역 내부·함대 아이콘」**으로 적었다.
**둘은 같은 층에 있는 다른 것이다.**

| | 성격 | 지도가 보이는가 | 시간 |
|---|---|---|---|
| **하프 시트** (조회) | 값을 읽는다 · 명령을 건다 | **보인다** — L2 위에 겹친다 | 흐른다 |
| **세부 뷰 `SC-L3`** (전장) | 권역 내부 4층 · 함대 진형 | 아니다 — 전체 화면 | 흐른다 |

**하프 시트는 층이 아니라 L2의 오버레이로 내린다.** L2에서 카드를 탭하면 시트가 올라오고,
시트의 「세부」를 눌러야 `SC-L3`으로 간다. **깊이는 L1 → L2 → L3으로 그대로 셋이다.**

> `ui-design.md` §1.3이 6단계를 3단계로 접은 것이 이 설계의 출발점이다.
> 오버레이를 층으로 세면 그 압축이 도로 풀린다.

## 1. 공통 규약 — 비차단(non-blocking)

**`DECISIONS.md` V-25 결정 ④가 이 문서 전체의 상위 규칙이다.**

> 모든 메뉴는 비차단이며, 명령은 **발행 시각과 도달 시각**을 갖는다.

이것은 편의 규칙이 아니라 주제 규칙이다 — 「시간은 자원이다」(불가침 ①)가
화면 안의 사실이 되는 지점이다(`roadmap-solo.md` §1.4).

### 1.1 다섯 조항

| # | 조항 | 결과 |
|---|---|---|
| **①** | **화면은 시뮬레이션을 멈추지 않는다** | 편성 화면을 3분 붙들고 있으면 게임 내 **3개월**이 지난다 |
| **②** | **화면이 읽는 값은 스냅샷이 아니라 구독이다** | 열어 둔 채 값이 바뀌면 **그 자리에서** 바뀐다 |
| **③** | **확정하지 않은 조작은 세계에 없다** | 편성안을 고르는 것은 명령이 아니다. 「발행」을 눌러야 명령이다 |
| **④** | **확정은 발행이고, 도달은 나중이다** | 모든 발행 결과에 「발행 ○월 → 도달 △월」을 함께 표시한다 |
| **⑤** | **취소도 명령이다** | 같은 사자 지연을 탄다. **이미 도달한 명령은 취소할 수 없다** |

### 1.2 상시 요소 — 시각 바

L1·L2·L3·시트 전부의 최상단에 고정한다. **소유는 S3.2(게임 루프)이고 이 문서는 참조만 한다.**

```
건안 십삼년 시월    ▶▶ ×2     대기 결정 3     ⚑ 2
```

| 요소 | 내용 |
|---|---|
| 연호·월 | 게임 내 시각. **실제 1시간 = 게임 내 1개월** |
| 배속 | ×1 / ×2 / ×4 (`roadmap-solo.md` §1.3 · **상한은 미결** — 검토 1) |
| 대기 결정 | 결정 큐 잔량 (`ui-design.md` §4.2) |
| ⚑ | 미확인 인터럽트 수 (S3.7) |

### 1.3 재진입 표시 — 조항 ②의 화면 표현

값이 흐르므로 **플레이어가 보고 있던 것과 지금이 다를 수 있다.**

| 사태 | 표시 |
|---|---|
| 값이 변했다 | 해당 수치를 **1.5초 강조** 후 원복 |
| 대상이 사라졌다 (함대 전멸·권역 상실) | 카드를 **회색 처리하고 조작 불가**. 닫기만 남는다 |
| 발행 대기 중 전제가 무너졌다 | **발행 버튼이 잠기고** 사유를 한 줄로 적는다 |

> **선택지를 조용히 바꾸지 않는다.** 사라진 이유를 적지 않으면
> 플레이어는 자기가 잘못 눌렀다고 생각한다.

### 1.4 예외 후보 하나 — 전투 개입

`combat.md` §2.2 ②는 개입 분기에서 **최대 10분 대기**를 규정한다.
그 10분 동안 시간이 흐르면 대기의 뜻이 없어진다.

**이 문서는 이것을 결정하지 않는다.** `roadmap-solo.md` 검토 7 · V-25 「대가」로 열려 있다.
다만 **화면 쪽 요건 하나는 미리 못 박는다.**

> 개입 알림은 **어느 화면에 있든 배너로 뜬다.** 편성 화면 안에 있다고 놓치지 않는다.
> 배너를 무시해도 위임 처리되어 전투는 끝난다 — **개입은 잘 싸우기 위한 것이지
> 전투를 굴러가게 하기 위한 것이 아니다**(`combat.md` §2.2).

## 2. `SC-L2` 성역 뷰 — S3.3

> **전략 지도 · 권역 소유 · 함대 위치.** L1에서 성역 노드를 탭하면 들어온다.

### 2.1 레이아웃

```
┌──────────────────────────────────────────────┐
│ 건안 십삼년 시월   ▶▶ ×2    대기 3   ⚑ 2     │
│ ◀ 성도        형주성역        [일괄] [필터]  │
├──────────────────────────────────────────────┤
│                                              │
│      ○ 북부권 ─── 양번관문 ═══ 남양          │
│       │                                      │
│      ● 중부권 ★ ─── 장강대항로 ─── 오회      │
│       │  ⚔                                   │
│      ● 남부권 ─── 오령회랑 ═══ 교주          │
│                                              │
├──────────────────────────────────────────────┤
│ ● 중부권 ★    오        국력 20   ⚔ 분쟁    │
│   ━━━━━━━━━░░░  공략 68%      직할           │

│ ○ 북부권      위        국력 14   비지 위험  │
│   ━━━━━━━━━━━━  —             위임 · 문빙   │
├──────────────────────────────────────────────┤
│ ● 남부권      오        국력 11              │
└──────────────────────────────────────────────┘
```

**상단은 관계도, 하단은 카드다.** 권역은 2~4개뿐이므로 **한 화면에 전부 들어간다**
(`ui-design.md` §3.1). 스크롤이 필요한 성역은 없다.

### 2.2 상단 — 권역 관계도

**지도가 아니라 그래프다.** 좌표는 성역 내 실제 배치가 아니라 **항로 인접**으로만 그린다.
45권역을 정확히 배치할 좌표계가 없고, 필요하지도 않다 — 플레이어가 이 화면에서 알아야 하는
것은 **무엇이 무엇과 이어져 있는가**뿐이다.

| 요소 | 표현 | 출처 |
|---|---|---|
| 권역 노드 | ● 아군 · ○ 타 세력 · ◌ 중립 | `partial-occupation.md` §1 |
| **주권역** | **★ 표식** — 치소가 놓인 권역 | 동 §1.2 |
| 분쟁 | ⚔ — 두 세력 이상이 나눠 가진 성역 | `ui-design.md` §6.3 |
| 기저 항로 | 회색 실선 | `star-map.md` §4 |
| 고속항로 | 청록 실선 | 동 §2 |
| **회랑·관문** | **이중선 ═══ + 귀속 권역에 붙인다** | `partial-occupation.md` §3 |
| 외부 연결 | 성역 밖으로 나가는 선 + 상대 성역명 | — |
| 함대 광점 | 항로 위 위치 + 도착 예정 시각 | `ui-design.md` §3.3 |

> **회랑을 항로가 아니라 권역에 붙여 그린다.**
> 「그 권역을 쥔 세력이 통행을 통제한다」(§3)가 그림에서 바로 읽혀야 한다.
> 관우가 왜 양번을 쳤는지가 이 한 화면에서 설명되지 않으면 이 화면은 실패다.

### 2.3 하단 — 권역 카드

| 행 | 항목 | 출처 | 평시 |
|---|---|---|---|
| 1 | 권역명 · **★주권역** · 소유 세력 · 국력 지수 · ⚔ | `partial-occupation.md` §1 · `region-power.md` §1 | 표시 |
| 2 | **공략 진행도 바**(4층 축약) · **직할/위임 배지** · 담당관 | `ui-design.md` §3.2 · `domestic.md` §3 | **공략 중에만 바 표시** |
| 3 | 전화 계수 · 권역 안정도 · 개발여지 잔여 · 주둔 함대 수 | `region-power.md` §3 · `function-events.md` §0.3-④ · `domestic.md` §5.3 | 접힘 — 탭하면 펼침 |

**눈금 정본**

| 값 | 범위 | 정본 |
|---|---|---|
| 권역 안정도 | **0~100** (초기 60 · 정복 직후 40 · 변경 25) | `function-events.md` §0.3-④ |
| 전화 계수 | 0.25 ~ **0.95 상한** | `region-power.md` §3.1·§3.5 |
| 사기 | 게이지 **0~125** · 명목 100 | `combat.md` §1.1 |

> ⚠ **사기 게이지는 100에서 끝나지 않는다.** 게이지 폭을 100으로 그리면
> 고양 구간(101~125)이 화면에서 잘린다. **전 게이지를 0~125로 그리고
> 100 위치에 눈금선 하나를 둔다** — 「100은 상한이 아니라 보정 없음」이 보여야 한다.

### 2.4 주목 권역 표면화

45권역 전부를 신경 쓰지 않게 하는 것이 `ui-design.md` §6.3의 약속이다. **카드를 접는다.**

| 상태 | 카드 |
|---|---|
| 분쟁 중 · 비지 위험 · 공략 중 · 명령 완료 | **펼침** (기본) |
| 위임 · 평시 · 변화 없음 | **한 줄로 접힘** — 이름·소유·국력만 |

**필터** — 국력순 · 위험순 · 미개발순 · **직할만**(`ui-design.md` §6.3).

### 2.5 조작

| 조작 | 결과 |
|---|---|
| 권역 카드 탭 | **하프 시트** — 권역 상세 · 내정 명령(S3.5) |
| 권역 카드 롱탭 | 세부 뷰 `SC-L3` 직행 |
| 함대 광점 탭 | **하프 시트** — 함대 상세 · 편성 진입(`SC-F2`) |
| **[일괄]** | 성역 단위 명령 → 하위 권역 자동 배분 (`domestic.md` §6) |
| 좌우 스와이프 | 인접 성역으로 이동 — **L1을 거치지 않는다** (검토 8) |
| ◀ | L1 성도 |

## 3. `SC-L3` 세부 뷰 — S3.4

> **권역 내부 4층 · 함대 아이콘 · 진형.** 요구 B6의 **「진형 갖춘 함대」**가 여기다.

### 3.1 무엇을 펼치는가

`ui-design.md` §3.2가 4층을 **진행도 바 하나로 접었다.** 그 바를 되펴는 화면이다.
**내부 계산은 언제나 4층이고, 접는 것은 L2뿐이다.**

```
┌──────────────────────────────────────────────┐
│ 건안 십삼년 시월   ▶▶ ×2    대기 3   ⚑ 2     │
│ ◀ 형주성역        중부권 ★           [편성]  │
├──────────────────────────────────────────────┤
│  외곽         ✓ 오       진입점 2 · 관측소   │
│  ──────────────────────────────────────────  │
│  궤도권       ✓ 오       조선소 · 방어위성 3 │
│  ──────────────────────────────────────────  │
│  식민지       3 / 5      ⚔ 교전 중           │
│  ──────────────────────────────────────────  │
│  지구형 행성  —          강릉  인구 12       │
├──────────────────────────────────────────────┤
│  ▣ 제3함대  140척  ◤◥ 어린   사기 ███░ 72   │
│     주유 · 부 정보 · 강습 감녕               │
│  ▣ 제5함대   84척  ◎ 방원    사기 ██░░ 58   │
│  ▢ 조 선봉  140척  ⌒ 학익    [적]            │
└──────────────────────────────────────────────┘
```

| 층 | 표시 | 공략 수단 | 출처 |
|---|---|---|---|
| **외곽** | 항로 진입점 수 · 관측소 · **봉쇄 지점** | 함대전 승리 | `star-map.md` §5 |
| **궤도권** | 궤도 도시 · 조선소 · **방어 위성망** | **공성함 필요** | 동 |
| **식민지** | n / m 점령 · 개별 교전 표식 | 강습 백병전 | 동 |
| **지구형 행성** | 거점명 · 인구 · 생산 | 공성함 + 강습부대 | 동 |

> **층은 순서다.** 바깥을 못 뚫으면 안쪽 줄은 회색으로 잠긴다.
> 공성함이 없는 함대로 궤도권을 두드리면 **왜 안 되는지가 이 화면에서 보여야 한다** —
> 「공성함 0척」이 잠금 사유로 뜬다.

### 3.2 함대 아이콘 — 요구 B6의 본체

**함대 하나 = 아이콘 + 진형 도형 + 사기 게이지 + 지휘부 한 줄.**

| 진형 | 도형 | 대응 지시 | 전개 폭 | 요구 통솔 |
|---|---|---|---|---|
| **어린진** | `◤◥` | 중앙 돌파 | 중 | 60 |
| **학익진** | `⌒` | 양익 포위 | **광** | **75** |
| **방원진** | `◎` | 종심 방어 | 협 | 55 |
| **안행진** | `⋰⋰` | 사격 전개 | **광** | 65 |
| **봉시진** | `▲▲▲` | 축차 투입 | 협 | 70 |
| **장사진** | `▬▬▬` | 종렬 항진 | **최협** | 40 |
| **팔진** | `✳` | — | 가변 | **90 + 전용** |

**정본은 `ship-specs.md` §5.2다.** 도형은 그 표의 「전개 폭」을 눈에 보이게 옮긴 것뿐이며,
**광폭은 넓게, 최협은 한 줄로 그린다.**

| 요소 | 표현 |
|---|---|
| 아군·적 | ▣ 아군 · ▢ 적 · ▨ 동맹 |
| 규모 | **척수**를 적는다. 140척 = 1함대 · 28척 = 1전대 |
| 사기 | 0~125 게이지 · 100 눈금선 · **39 이하 붉게**(붕괴 위험) |
| 지휘부 | 제독 · 부(부제독) · 임무대장 중 **배치된 것만** |
| 훈련도 | 게이지 아래 가는 선 · **전대장 없으면 40에서 끊긴 표식** |
| 이동 중 | 도착 예정 시각 + 진행 바 |

> **빈자리는 빈자리로 보여야 한다.** `ship-specs.md` §6.4는
> 「빈 자리는 무명 장교가 맡고 보정은 0」이라고 정했다.
> 이름을 지어 채우면 플레이어는 **자기가 아무것도 배분하지 않았다는 사실을 모른다.**

### 3.3 지형 강제의 표시

`ship-specs.md` §5.3이 **회랑이 진형을 강제한다**고 정했다. 화면이 그것을 먼저 말한다.

| 지형 | 사용 가능 | 화면 |
|---|---|---|
| 개활 궤도 · 고속항로 | 전부 | — |
| 기저 항로 | 광폭 제외 | 학익·안행 **회색** |
| **중회랑** | 방원 · 봉시 · 장사 | 나머지 회색 |
| **대회랑** | **장사진 강제** | **선택 자체가 사라진다** + 「변경 불가」 |

> 대회랑에서는 진형 칸이 **잠긴 채 장사진으로 고정**되고, 그 옆에 ② 포화 계수 **0.6**을 적는다.
> **이릉이 왜 그렇게 끝났는지를 화면이 미리 말해 준다** — 그러고도 들어가는 것은 플레이어의 선택이다.

## 4. 함대 편성 UI 3종 — S3.6 (요구 B7)

### 4.1 왜 셋인가

요구 B7은 **「함대 규모·배치 — 사용자 정의 / 추천 모드」**다.
`ship-specs.md`가 이 요구에 답할 재료를 두 곳에 나눠 두었고, **묻는 질문이 서로 다르다.**

| 화면 | 질문 | 정본 |
|---|---|---|
| **`SC-F1` 함대 목록** | **몇 개를 어디에 두는가** — 규모·배치 | §6.1 지휘 한도 · §7.2 유지점 |
| **`SC-F2` 편성 시트** | **무엇을 태우는가** — 편성안·강화 축·진형 | §7.2 · §7.3 · §7.4 |
| **`SC-F3` 임명 시트** | **누가 지휘하는가** — 임명 4계층 | §6.4 · §6.5 · §6.6 |

> **셋을 한 화면에 합치지 않는다.** 합치면 스크롤이 생기고,
> 스크롤이 생기면 **`ui-design.md` §1.1의 12~15행 한계**를 넘는다.
> 그리고 셋은 각각 **다른 자원**을 쓴다 — 유지점 · 자금 · **인물**.

### 4.2 편제 정본 [V-38]

```
전대 28척   ·   함대 140척(5전대)   ·   방면군 700척(5함대)
```

**균형 편성 함대 140척의 내역**

| 전열 | 포격 | 강습 | 전자 | 공성 | 보급 |
|---|---|---|---|---|---|
| 56 | 28 | 21 | 14 | 7 | 14 |

**지휘 한도가 함대 단위로 정확히 떨어진다.** 균형 편성 전대당 유지점 1.195 기준:

| 통솔 | 등급 | 지휘 한도 | 균형 편성 환산 | 편제 |
|---|---|---|---|---|
| 95~100 | 특급 | **30** | 25.1전대 | **5함대 = 1방면군** |
| 85~94 | 1급 | 24 | 20.1전대 | 4함대 |
| 75~84 | 2급 | 18 | 15.1전대 | 3함대 |
| 65~74 | 3급 | 12 | 10.0전대 | **2함대** |
| 55~64 | 4급 | 8 | 6.7전대 | 1함대 + 1.7전대 |
| 40~54 | 5급 | 5 | 4.2전대 | 4전대 |
| ~39 | 급외 | 2 | 1.7전대 | 1전대 |

> **이것은 우연이 아니라 검산이다.** 특급 제독 하나가 방면군 하나를 정확히 든다.
> **그러므로 한도 게이지는 유지점이 아니라 「함대 몇 개」로 읽어 준다** —
> 플레이어가 아는 단위로 말해야 한도가 제약으로 체감된다.

**다만 편성안을 바꾸면 그 대응이 깨진다.**

| 편성안 | 전대당 | 함대당 | 특급 30이 드는 함대 |
|---|---|---|---|
| 봉쇄 유지 | 1.10 | 5.50 | **5.45** |
| 개활 결전 | 1.18 | 5.90 | 5.08 |
| **균형** | **1.195** | **5.975** | **5.02** |
| 회랑 돌파 | 1.22 | 6.10 | 4.92 |
| 강습 특화 | 1.23 | 6.15 | 4.88 |
| **성계 공략** | **1.25** | **6.25** | **4.80** |

> ⚠ **방면군을 통째로 「성계 공략」으로 바꾸면 특급 제독도 한도를 넘는다** —
> 5함대 × 6.25 = **31.25 > 30**. 초과 1.25 → **전 부대 사기 −3**(§6.2).
> **편성 화면은 이 −3을 확정 전에 보여야 한다.** 편성을 바꾸는 것이 지휘 능력을 갉는다는 것이
> 이 게임의 규칙이고, 그것을 확정 후에 알리면 규칙이 아니라 함정이 된다.

### 4.4 `SC-F2` 편성 시트 — 조작 2회

`ship-specs.md` §7.1이 **6종 비율 슬라이더를 명시적으로 기각**했다.
**조작은 둘뿐이다.**

```
┌──────────────────────────────────────────────┐
│ 제7함대                     [추천]  [사용자] │
├──────────────────────────────────────────────┤
│ ① 편성안                                     │
│   균형 · 〔회랑 돌파〕 · 개활 결전            │
│   강습 특화 · 성계 공략 · 봉쇄 유지           │
│                                              │
│   전열 42  포격 56  강습 7  전자 7           │
│   공성 14  보급 14                  = 140척  │
│                                              │
│ ② 강화 축     화력 〔＋1〕  돌파 —  지속 —   │
│   1단계 = 5%p = 7척 · ±2단계                 │
│   전열 −7 → 35     포격 +7 → 63              │
│   ⚠ ③ 교전 약화 · 유지점 상승                │
│                                              │
│ ③ 초기 진형   ▬▬▬ 장사  (대회랑 강제)       │
│                                              │
│ 유지점 6.10 → 6.20    한도 12  ████████░░    │
│                                              │
│            [ 발행 ]    도달 십일월           │
└──────────────────────────────────────────────┘
```

| 항목 | 규칙 | 정본 |
|---|---|---|
| 편성안 | **6종 중 하나** | §7.2 |
| 강화 축 | **3축 중 하나 · ±2단계** · 1단계 = 5%p | §7.3 |
| 강화 원천 | **전열함 비율을 헐어** 키운다 | §7.3 |
| 진형 | 7종 · **지형 필터 적용**(§3.3) | §5.2·§5.3 |
| 즉시 표시 | 함종별 척수 · 유지점 · **한도 게이지** · 대가 한 줄 | §6.2·§7.3 |

**강화 축의 대가를 숨기지 않는다.**

| 축 | 얻는 것 | **화면에 적는 대가** |
|---|---|---|
| 화력 → 포격 | ② 포화 강화 | **③ 교전 약화 · 유지점 상승** |
| 돌파 → 강습 | ④ 강습 강화 | **함대 규모 축소** |
| 지속 → 보급 | 재보급·수리 회전 증가 | **전투력 순감** |

> **유지점은 편성안의 고정값이 아니라 비율에서 매번 다시 센다.**
> 회랑 돌파에 화력 +1단계면 전열 30 → 25 · 포격 40 → 45 이므로
> 전대당 1.22 → **1.24**, 함대로는 6.10 → **6.20**이다(`combat.md` §4.3.2 함종 유지점).
> **표를 미리 만들어 두지 않는다** — 6 편성안 × (3축 × ±2단계 + 무보정) = **78가지**이고,
> 그중 하나라도 표와 어긋나면 §7.2가 2026-08-25에 겪은 전사 오류가 그대로 재발한다.

> **±2단계 상한이 곧 「편성안의 성격은 유지된다」는 약속이다**(§7.3).
> 슬라이더를 주지 않은 이유가 여기서 지켜진다 — **최적해 하나로 수렴하지 않는다.**

### 4.5 추천 모드 — 알고리즘 [신설]

`ship-specs.md` §7.4가 목적지별 대응표를 주었으나 **선택 규칙은 없었다**
(`roadmap-solo.md` 미작성 항목 「함대 추천 편성 알고리즘」 · 요구 B7). 여기서 닫는다.

**입력** — 목적 권역 · 경로(`core/world/routing.gd`) · 제독 통솔 · 여유 유지점 · 관측된 적 편성

**규칙 — 위에서부터 첫 일치를 채택한다.**

| # | 조건 | 편성안 | 초기 진형 | 근거 |
|---|---|---|---|---|
| 1 | 경로에 **대회랑** 포함 | 회랑 돌파 | **장사진**(강제) → 돌파 후 방원진 | §5.3 · §7.4 |
| 2 | 경로에 **중회랑·관문** 포함 | 회랑 돌파 | 방원진 | 동 |
| 3 | 목적지가 **적 권역** ∧ 궤도권 이상 공략 | 성계 공략 | 안행진 | §7.4 |
| 4 | 목적지가 **자국 회랑·관문 권역** ∧ 주둔 | 봉쇄 유지 | 방원진 | §7.4 |
| 5 | 경로가 고속항로 ∧ 조우 예상 | 개활 결전 | 어린진 | §7.4 |
| 6 | 그 밖 | **균형** | 어린진 | — |

**보정 — 규칙 적용 후 한 번만 얹는다.**

| 조건 | 보정 |
|---|---|
| 관측된 적 강습모함 비율 > 25% | 강화 축 **돌파 +1** |
| 목적지가 비지 · 보급 단절 위험 | 강화 축 **지속 +1** |
| 규칙 1·2 채택 | 강화 축 **화력 +1** |
| 관측 정보 없음 (전자전함 미보유) | **보정 없음** — 모르는 것을 아는 척하지 않는다 |

> **관측 규칙은 §12 가 정한다.** 강습모함 비율 항만 관측에 의존하며(**단계 2 판독 + 신선도 3개월**),
> 나머지 셋은 아군이 이미 아는 것(경로·항로 상태)으로 얹는다.

**진형 하향** — 요구 통솔 미달이면 **충족하는 가장 가까운 진형으로 내린다.**

```
학익 75  →  봉시 70  →  안행 65  →  어린 60  →  방원 55  →  장사 40
```

**규모 추천**

```
추천 전대 수 = min( 제독 지휘 한도    ÷ 편성안 전대당 유지점 ,
                    세력 여유 유지점  ÷ 편성안 전대당 유지점 )
             를 5전대(= 1함대) 단위로 내림. 최소 1전대.
```

**동률 처리** — 규칙 번호 오름차순 → **권역 ID 오름차순**.
`DECISIONS.md` V-31(결정론)에 따라 **무순서 굴림·부동소수를 쓰지 않는다.**

> 플레이어는 **추천을 받아들이거나, 한 번 바꾸거나, 강화 축을 하나 얹는다.
> 그 이상은 요구하지 않는다**(§7.4). 추천 결과는 사용자 정의 화면에 그대로 실려 나오며,
> **어느 규칙이 걸렸는지 한 줄로 적는다** — 「대회랑 통과 · 화력 +1」.

### 4.6 `SC-F3` 임명 시트 — 4계층

```
┌──────────────────────────────────────────────┐
│ 제3함대 임명              [자동]  [수동]     │
├──────────────────────────────────────────────┤
│ 제독      주유   통솔 96    한도 30          │
│ 부제독    정보   통솔 82    한도 +9 → 39     │
│ 강습대장  감녕   무력 94                     │
│ 공성대장  —      지력 —     ④ 보정 0        │
│ 보급대장  —      정치 —     ⚠ 순욱 배치 시  │
│                             세력 내정 −25%   │
├──────────────────────────────────────────────┤
│ 전대장 (5)                         [일괄]    │
│  1 여몽 78 │ 2 서성 71 │ 3 — 40 │ 4 — 40    │
│  5 — 40                                      │
│  ⚠ 3~5 훈련도 상한 40에서 멈춘다             │
└──────────────────────────────────────────────┘
```

| 직 | 스탯 | 효과 | 필수 |
|---|---|---|---|
| **제독** | 통솔 | 지휘 한도(§6.1) · 초기 사기(`combat.md` §1.2) | **필수** |
| 부제독 | 통솔 | **자기 지휘 한도의 절반이 제독의 한도에 가산** · 제독 상실 시 승계 | 선택 |
| 강습대장 | **무력** | ④ 강습 페이즈 계수 | 선택 |
| 공성대장 | **지력** | 궤도 요새·행성 방어망 격파 | 선택 |
| **보급대장** | **정치** | 재보급·수리 회전 · 보급 페널티 완화 | 선택 |
| 전대장 | 통솔 | **훈련도 상한** — 없으면 **40에서 멈춘다** | 선택 |

> **부제독 가산은 「통솔의 절반」이 아니라 「지휘 한도의 절반」이다.**
> §6.5의 문장은 「통솔의 절반이 가산」이라 읽히지만, 같은 절의 예시가
> **「통솔 80의 부제독을 붙이면 한도가 9만큼 늘어난다」**로 못 박는다 —
> 통솔 80은 2급이라 한도 18이고, 그 절반이 9다.
> 코드도 같다(`core/world/roster.gd` `command_limit`). **화면은 예시 쪽을 따른다.**

**전대장 자동·수동은 함대 단위 토글이다**(§6.6).

| 모드 | 조작 | 배정 |
|---|---|---|
| **자동** (기본) | **함대당 1회** | 미배치 인물 중 **통솔 상위부터** 예하 5전대에 채운다 |
| 수동 | 전대당 1회 | 플레이어가 고른다 |

> **한 함대만 수동으로 바꾸는 것이 성립해야 한다** —
> 주력은 손으로 짜고 나머지는 맡긴다(§6.6).

**보급대장 자리에 대가를 적는다.** `ship-specs.md` §6.5가
「순욱을 전선에 보내면 세력 전체 내정 효율 +25%가 함께 나간다」고 정했다.
**후보 목록에 그 인물의 현재 내정 담당 권역을 함께 띄운다** —
`domestic.md` §3의 담당관과 **같은 풀**이기 때문이다.

> **함대 참모를 채우면 위임할 사람이 없고, 위임하면 함대가 빈다**(§6.7).
> 「통일 vs 분권」이 인물 배분에서 한 번 더 물어지는 자리이므로,
> **임명 화면은 그 대가를 반드시 같은 화면에 적는다.**

## 5. 검산 — 실제로 몇 번 누르는가

`domestic.md` §6이 내정에서 한 것을 편성에서 한다. **208년 조조 기준.**

### 5.1 편제 환산

```
실동원 101  ÷  1.195  =  84.5전대  =  16.9함대  =  3.4방면군
```

| 항목 | 수 |
|---|---|
| **필수 임명** (제독 17 + 방면군 사령 4) | **21** |
| 전부 (제독 17 + 부제독 17 + 임무대장 51 + 전대장 85 + 사령 4) | **174** |
| **보유 인물** | **72** |

> **전부는 채울 수 없다. 그것이 설계다**(§6.7).
> 필수 21을 빼면 **51인을 어디에 쓸 것인가**가 선택이 되고,
> **그 51인은 내정 담당관과 같은 풀이다.**

### 5.2 조작 횟수

| 경로 | 함대 1개 | 조조 17함대 |
|---|---|---|
| **추천 모드** (수락) | **1회** | **17회** |
| 추천 + 1회 변경 | 2회 | 34회 |
| 사용자 정의 · 전대장 자동 | 9회 | 153회 |
| 사용자 정의 · 전대장 수동 | 13회 | 221회 |

사용자 정의 9회 내역: 편성안 1 · 강화 축 1 · 진형 1 · 제독 1 · 부제독 1 · 임무대장 3 · 전대장 일괄 1.

**전대장만 따로 세면 자동 17회 대 수동 85회다.**
§6.6이 「자동 12 대 수동 62」로 적은 것은 **실동원 74** 기준이고,
V-37 이후 정본은 **101**이므로 17 대 85가 된다. **비율 5배는 같다.**

> **추천 모드가 없으면 이 게임은 3~5분 세션에 들어가지 않는다.**
> 153회는 세션이 아니라 작업이다.

## 11. `SC-INT` 알림 · 인터럽트 배너 — S3.7

> 입력: §1.2 시각 바 「⚑」 · `ui-design.md` §4.2 결정 큐 · §7 알림 3등급 · `function-events.md` 40종 · §1.4 전투 개입.

### 11.1 긴장의 소재

§1.1 ① — 화면은 시뮬레이션을 멈추지 않는다. 그런데 배너는 「지금 봐야 하는 것」을 알려야 한다. **멈추지 않으면서 어떻게 「지금」을 만드는가.**

**답 — 긴급성을 정지가 아니라 응답 기한으로 표현한다.**

배너는 뜨는 순간부터 **기한 카운트다운**을 갖는다. 기한 안에 처리하지 않으면 **기본 처리**(전투 = 위임 · 결정 = 보류/기본안)되고, 배너는 사라지지 않고 **복귀 브리핑 로그로 내려간다.** 「무엇을 놓쳤는지」가 항상 남는다 — §1.3 「선택지를 조용히 바꾸지 않는다」의 연장이다.

정지가 필요한 유일 후보는 전투 개입이고, 그것은 §1.4 · 검토 2 로 열려 있다. **이 절은 배너의 분류 · 형태 · 수명을 확정하고, 정지 여부는 넘긴다.**

### 11.2 무엇이 배너를 띄우는가 — 긴급만

`ui-design.md` §7 이 알림을 셋으로 나눴다. **배너(⚑)는 긴급 등급만이다.**

| 등급 | `ui-design.md` §7 예 | 이 문서에서 | ⚑ 카운트 |
|---|---|---|---|
| **긴급** | 전투 분기점 · 적 함대 접근 · 인재 이탈 경고 | **배너** | **들어감** |
| 완료 | 항행 완료 · 건조 완료 · 명령 도달 | 브리핑 묶음 (아침·점심·저녁) | — |
| 정보 | 천명 변동 · 외교 제안 | 브리핑에만 | — |

**배너를 띄우는 계기 — `function-events.md` 40종 중:**

| 계기 | 근거 | 응답 기한 (잠정 — 검토 15) |
|---|---|---|
| **전투 개입 분기** | `combat.md` §2.2 ① · §1.4 | **10분** (combat 규정) |
| **[F-13] 고립·비지화** (아군 권역이 끊김) | 전이 사건 · 안정도 −8/월 | 사자 지연까지 (명령이 닿는 시각) |
| **[F-12] 배후 기습 성공** → 요충 상실 | 되돌릴 수 없다 | 없음 — **확인만** |
| **[F-30] 지도자의 죽음** → 후계 공백 | 동원율 −0.15 · 안정도 −20 | **90초** ([F-27] 결정 타이머와 같은 값 · `function-events.md` §5) |
| **[F-39] 후방 반란 발발** | 매월 확산 −5 | 느슨 (회유/진압은 12개월 소요) |
| **적 공세 개시** ([F-16]·[F-17] 등 — 아군 권역·관문 피격) | 적 함대 접근 | 전투 개입으로 이어짐 |
| **인재 이탈 경고** ([F-04]·[F-05] 절의 이탈 · [F-28] 참모 이탈) | 「칭왕 시점 이탈 경고」 등 | 다음 판정까지 (≈3개월) |

> **[F-07] 견제 연합 결성 · [F-11] 반환 요구 예약 · 천명 구간 이동은 배너가 아니다.**
> 급하지 않다 — 브리핑·결정 큐로 충분하다. 배너를 헐값에 쓰면 ⚑ 가 소음이 되고, 소음이 되면 §1.1 ①을 지켜도 플레이어가 스스로 접속을 끊는다 (`ui-design.md` §7 「알림 피로가 이 장르 이탈의 주원인」).

### 11.3 배너의 형태

```
 건안 십삼년 시월   ▶▶ ×2   대기 3   ⚑ 2      ← 시각 바 (§1.2)
┌──────────────────────────────────────────────┐
│ ⚑ 관우군 고립 — 중부권이 끊겼다     09:12 ▸  │ ← 배너 (시각 바 바로 아래)
└──────────────────────────────────────────────┘
              (그 아래 — 현재 화면 그대로)
```

| 항목 | 규칙 |
|---|---|
| 위치 | 시각 바 **바로 아래**, 폭 전체. 현재 화면 위에 얹힌다 — **화면을 교체하지 않는다** |
| 개수 | 표시는 1행. 여럿이면 **가장 급한 것**(기한 짧은 순 → 계기 우선도) 1개 + 「외 n」 |
| 기한 | 우측에 카운트다운 (mm:ss 또는 「△월 도달 전」). 기한 없는 통지는 카운트다운 대신 「확인」 |
| ⚑ 카운트 | 시각 바 ⚑ = **미확인 배너 수.** 탭하면 배너 스택 전체 펼침 |
| 조작 비가로채기 | 편성·명령 중이어도 배너는 얹히기만 한다. 배너 탭 시 현재 작업 **위에** 결정 큐 항목이 오버레이 (하프 시트처럼) |
| 소멸 | 처리 완료 → 사라짐. 기한 만료 → 기본 처리 + **브리핑 로그로 이동** (사라지지 않고 기록) |
| 야간 (23~07시) | 푸시 없음 (`ui-design.md` §7). 인게임 배너는 뜨되 진동·소리 없음 |
| 빈도 상한 | 긴급 푸시 1일 5회 (동). 초과분은 배너만, 푸시 없음 |

### 11.4 조작 · 전이

| 조작 | 결과 |
|---|---|
| 배너 탭 | 해당 결정 큐 항목을 **현재 화면 위 오버레이**로 (`ui-design.md` §4.2 형식) |
| ⚑ 탭 (시각 바) | 배너 스택 목록 — 기한 순 |
| 배너 가로 스와이프 | 「나중에」 — **기한이 있으면 불가**(회색), 사유 표시 |
| 무시 + 기한 만료 | 기본 처리 → 복귀 브리핑 로그 |

```
(어느 화면이든) ──⚑ 발생──▶ 배너 ──탭──▶ 결정 큐 오버레이 ──처리──▶ 배너 소멸
                              └──기한 만료──▶ 기본 처리 ──▶ 복귀 브리핑 로그
```

> **개입 배너는 편성 화면 안에서도 뜬다** (§1.4 에서 이미 확정). 이 절은 그 요건을 **전 계기로 확장**한다 — 배너는 화면에 종속되지 않는다.

## 12. 적 편성 관측 규칙 [검토 6 해소 · `SC-F1` §4.5 의 선행]

### 12.1 왜 이 절이 먼저인가

§4.5 추천 알고리즘의 보정표가 「관측된 적 강습모함 비율 > 25%」를 읽는다. 그런데 **적 편성을 어떻게 관측하는지가 어느 문서에도 없다.** §4.5 는 이미 못을 하나 박아 두었다 — 「관측 정보 없음(전자전함 미보유) → 보정 없음. **모르는 것을 아는 척하지 않는다**」. 이 절은 그 「관측」을 정의한다.

**코어 확인.** `core/` 에 은폐·정찰·가시성 시스템이 없다. `detector_wits`(`fleet.gd`:71)는 계략 **간파**용이지 편성 관측이 아니다. `ai-design.md` §9 는 난이도별 「정보」(적 함대 위치·병력 가시 범위)를 표로만 두고 규칙이 없다. **신규 정의이며, 이 절이 그 규칙이다.** (`combat.md` 는 고치지 않는다 — §12.5.)

### 12.2 세 단계 관측

`combat.md` §2.1 ① 접적이 「탐지 판정」을 말하나 산식이 매복 성공률 외에는 없다. 관측을 **세 단계**로 둔다 — 무엇을 알려주는가로 나뉜다.

| 단계 | 조건 | 플레이어가 아는 것 |
|---|---|---|
| **0 · 미접촉** | 적 함대와 같은 성계에 아군 자산 없음 | 아무것도. 관계도에 광점조차 없다 |
| **1 · 포착** | 같은 성계에 아군 함대 · 관측소(§3.1 외곽 층) · 주둔 권역 | 적 **함대 존재 · 위치 · 척수(±20%) · 이동 방향** |
| **2 · 판독** | 접적(전투 ① 페이즈 돌입) **또는** 아군 함대에 **전자전함 ≥ 10% 편성 + 같은 성계 1개월 체류** | 적 **편성안 · 함종 비율 · 진형 · 제독 이름 · 사기 구간** |

> **전자전함이 판독의 열쇠다.** `combat.md` §4.1 이 전자전함 ① 접적 계수 1.9 로 이미 「정찰함」의 성격을 줬고, `ship-specs.md` §3.4(유정 — 초계함)가 이름으로 못 박았다. §4.5 보정표의 「전자전함 미보유 → 보정 없음」이 여기서 규칙이 된다 — **판독에 이르지 못하면 편성 보정을 얹지 않는다.**

### 12.3 관측의 신선도

관측값은 **찍힌 시각을 함께 갖는다.** 적이 시야를 벗어나면 마지막 값이 **유령으로 남는다.**

| 경과 (마지막 판독 이후) | 표시 · 취급 |
|---|---|
| ~1개월 | 실선 · 현재값 |
| 1~3개월 | 점선 · 「n개월 전 관측」 |
| 3개월+ | 회색 · 추천 알고리즘이 **단계 1 로 강등**해 읽는다 (척수만, 편성 보정 없음) |

> **오래된 정보는 없는 정보보다 위험하다.** §4.5 가 낡은 관측으로 강습 +1 을 얹으면 그 편성으로 엉뚱한 곳에서 싸운다. 신선도 강등이 그것을 막는다.

### 12.4 추천 알고리즘과의 접속 [§4.5 보정표 갱신]

§4.5 「보정」표의 관측 의존 항을 이 절에 묶는다.

| §4.5 보정 조건 | 요구 관측 | 미달 시 |
|---|---|---|
| 관측된 적 강습모함 비율 > 25% → 돌파 +1 | **단계 2 · 판독** (신선도 3개월 이내) | **보정 없음** |
| 목적지 비지 · 보급 단절 위험 → 지속 +1 | 관측 불요 (아군 항로 상태) | 그대로 적용 |
| 규칙 1·2 채택 (대회랑·중회랑) → 화력 +1 | 관측 불요 (경로 정보) | 그대로 적용 |

즉 **관측에 의존하는 보정은 강습모함 항 하나뿐**이고, 나머지는 아군이 이미 아는 것으로 얹는다. §4.5 의 「관측 정보 없음 → 보정 없음」이 정확히 이 한 줄을 가리킨다.

### 12.5 AI 대칭 · `combat.md` 로 넘기는 것

- `ai-design.md` §1.3 「정보 가시성 동일」 — AI 도 같은 3단계를 쓴다. AI 가 아군 편성을 읽는 조건도 전자전함 보유 + 체류다. 난이도 「극한」의 완전 정보만 예외다 (`ai-design.md` §9, 이미 «유일한 예외»로 표기).
- `combat.md` §2.1 ①의 「탐지 판정」에 실제 산식이 없다. **단계 1↔2 를 확률로 둘지(지력 대결 등) 결정형으로 둘지는 `combat.md` 소관**이며 계략 레인이 그 문서를 잡고 있다 — 검토 17 로 넘긴다. 이 절은 「전자전함 + 체류 = 판독」이라는 **결정형 게이트**로 잠정 확정한다. 추천 알고리즘이 결정론이어야 하므로(V-31) 확률 판정을 추천 입력에 넣지 않는다.

## 13. 분할 · 합류 시 지휘부 승계 [검토 10 해소]

### 13.1 무엇이 비어 있었나

§4.3 이 전대 단위 분할·합류를 허용하는데, **분견 함대의 제독이 정해져 있지 않다.** 코어 `Fleet` 는 함대당 지휘부 5직(제독·부제독·강습·공성·보급)을 **한 벌**만 갖고, 전대장 통솔(`squadron_command`)·훈련도(`drill`)도 함대 단위 스칼라다 (`fleet.gd`:33~88). 분할은 새 `Fleet` 객체를 만드는 일이고, 그 객체의 지휘부는 빈 상태로 태어난다.

### 13.2 분할 — 원함대가 지휘부를 지킨다

```
제7함대 140척 (주유 · 부 정보 · 강습 감녕 · 균형 · 학익 · drill 72)
   │ 우스와이프 → 분할: 2전대(56척) 떼어냄
   ▼
제7함대  84척  주유 · 부 정보 · 강습 감녕 · 균형 · 학익 · drill 72   ← 원함대 (전부 유지)
제12함대 56척  무명 장교 · 부 — · 임무 — · 균형 · 어린 · drill 40   ← 분견대 (지휘부 공석)
```

| 항목 | 분견대가 받는 값 | 근거 |
|---|---|---|
| 제독 | **무명 장교 (공석 · 보정 0)** | `ship-specs.md` §6.4 「빈 자리는 무명 장교가 맡고 보정 0」 |
| 부제독 | 따라가지 **않는다** — 원함대에 남는다 | §6.5 부제독은 「제독 상실 시 승계」이지 분견 인솔이 아니다 |
| 임무대장 3 | 따라가지 않는다 | 동 |
| 편성안 | 원함대와 **동일** (분할 시점) | — |
| 진형 | **어린진** (지휘부가 없어 학익 요구 통솔 미달) | `ship-specs.md` §5.2 |
| 훈련도 | 분견 전대들의 **최소값** | §13.4 |
| 전대장 통솔 | **0** (재지정 필요 — 상한 40) | `domestic.md` §5.5 |

> **분할은 「빈 함대를 만드는 것」이다.** 그 함대를 쓰려면 `SC-F3` 에서 제독을 임명해야 하고, 그 전까지는 보정 0 · 훈련 상한 40 으로 움직인다. 분할 조작 시 **「제독 미임명 — 보정 0」 경고를 확정 전에 본다** (§1.1 ④ · §4.3 경고 규칙).
> 예외: 분할 대화상자에서 곧바로 제독을 지정하면(미임명 풀에서) 그 사람이 분견대를 맡고, 위 표의 제독·진형 행이 그 통솔로 다시 계산된다.

### 13.3 합류 — 통솔 상위 제독이 통합 함대를 맡는다

```
제3함대 84척 (주유 통 96 · 균형 · drill 58)  +  제12함대 56척 (여몽 통 78 · 균형 · drill 44)
   ▼
제3함대 140척  주유 통 96 · 균형 · drill 44
   여몽 → 미임명 풀로 (조용히 부제독으로 강등하지 않는다)
```

| 항목 | 통합 함대가 받는 값 | 근거 |
|---|---|---|
| 제독 | 두 제독 중 **통솔 상위.** 하위 제독은 **미임명 풀로 반환** | §1.3 「선택지를 조용히 바꾸지 않는다」 |
| 부제독·임무대장 | 통합 함대 한 벌만 유지 (상위 제독 쪽). 나머지는 미임명 풀 | `ship-specs.md` §6.4 |
| 편성안·진형 | 전대 수 **많은 쪽.** 동수면 상위 제독 쪽 | — |
| 훈련도 | 두 함대 `drill` 의 **최소값** | §13.4 |
| 지휘 한도 | 합산 유지점이 제독 지휘 한도 초과 시 **§6.2 초과 편성 페널티(사기 −3/유지점).** 합류 조작이 이 −3 을 **확정 전에** 표시 | `ship-specs.md` §6.2 · §4.2 V-38 주석과 같은 원칙 |

### 13.4 코어가 스칼라라 생기는 근사 [검토 16]

`domestic.md` §5.5 는 「재편도 전대 단위로만 일어나고, 따라서 훈련도가 섞이지 않는다」고 정했다. 그러나 코어 `Fleet.drill`·`squadron_command` 는 **함대 단위 스칼라**라 전대별 훈련도를 담지 못한다. 분할·합류에서 값이 섞인다.

**이 문서의 잠정 규칙:** 섞일 때는 **최소값**을 취한다 (약한 전대에 맞춘다 — 보수적이고, 「정예 전대를 쪼개 재활용」 편법을 막는다 · `domestic.md` 검토 7 과 같은 우려).
**정본 판정:** 전대별 훈련도를 코어가 배열로 들 것인가는 코어 작업이다. 이 문서는 코드를 고치지 않으므로 **검토 16 으로 코어 레인에 넘긴다.**

### 13.5 `combat.md` §6.5 「제독 상실 시 승계」와의 구분

그것은 **전투 중 제독 전사** 시 부제독이 그 함대의 제독이 되는 사건이다. 분할·합류는 플레이어 편성 조작이고 제독이 살아 있다. 둘은 다른 경로다 — 분할에서 부제독은 승계하지 않고 원함대에 남는다(§13.2).

## 14. 권역 관계도 배치표 — 필요성 판정 [검토 5 해소]

### 14.1 물음

§2.2 가 관계도를 「항로 인접만으로 그린다」고 정했고, 검토 5 는 「성역 내 45권역의 상대 위치가 어느 문서에도 없다. 자동 배치는 매번 모양이 달라져 지도로 쓸 수 없다」고 우려했다. **성역별 고정 배치표(성역 19 × 권역 2~4)를 데이터로 만들 것인가.**

### 14.2 판정 — 불필요하다

`app/views/region_graph.gd` 가 이미 구현했고, 그 구현이 검토 5 의 우려를 세 갈래로 무력화한다.

| 우려 | 실제 |
|---|---|
| 「매번 모양이 달라진다」 | `_layout()` 이 **권역 ID 순서**로 지그재그 열에 배치한다. ID 순서는 고정 → **같은 성역은 언제나 같은 모양.** 비결정성이 없다 (코드 주석 11~14) |
| 「지도로 쓸 수 없다」 | §2.2 가 이미 「지도가 아니라 그래프다. 45권역을 정확히 배치할 좌표계가 없고, 필요하지도 않다」고 정했다. 이 화면에서 알아야 하는 것은 **무엇이 무엇과 이어져 있는가**뿐이다 |
| 「배치할 좌표계가 없다」 | 권역이 성역당 2~4개다. 지그재그 열 하나에 전부 들어가고 스크롤이 없다. 좌표계가 **필요 없다** |

**결론:** 정본 배치표를 만들지 않는다. 검토 5 를 취소선으로 닫는다. 관계도는 위상 그래프이며 ID 순서 결정론이 「학습 가능한 안정된 모양」을 이미 보장한다.

### 14.3 남는 것 — 비회랑 항로의 권역 귀속 [검토 13]

`region_graph.gd`:105~110 주석이 지적한 별개 공백: `data/routes.json` 에 **항로 이름이 없고 `kind` 와 회랑 ID 만** 있다. 그래서 비회랑 항로(고속·기저)가 성역 안에서 **어느 권역에 붙는지 데이터로 알 수 없다.** 코드는 임시로 **주권역**에 붙인다 — 이 화면의 대체 규칙이지 정본이 아니다. 회랑은 `regions.json` 의 `routes_hosted` 가 이름으로 귀속을 적어 정확하다.

이것은 배치표가 아니라 **`routes.json` 스키마 확장**(항로에 `host_region` 필드)이다. 데이터 작업이므로 범위만 적고 넘긴다:

- **범위:** 비회랑 항로 각각에 귀속 권역 1개. `star-map.md` §2·§4 의 항로 목록 × 성역 내 권역 — 대략 고속항로 + 기저 항로 합 30~40개.
- **우선순위: 낮음.** 주권역 폴백으로 관계도는 이미 그려진다. 「관우가 왜 양번을 쳤는가」(§2.2)는 회랑 귀속이 설명하고 그것은 이미 정확하다.
