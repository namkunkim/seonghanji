## 2. 지리 근거와 각색의 경계

### 2.1 참조 범위

동경 90~134도, 북위 16~46도 범위로 삼국지 주무대, 하서 축, 요동, 교주 관련 공간을 포함한다.
현대 중국 전역의 행정지도나 역사시대 영토 지도는 아니다. 현대 국가 경계는 게임 지형에 사용하지 않았다.

주요 산맥·평원·분지 윤곽은 Natural Earth 공개 벡터, 하천은 같은 배포처의 하천 중심선에서 가져왔다.
원본 배포 릴리스는 `v5.1.2`로 고정하고 원본 및 선별 파일의 SHA-256을 기록했다.
자료는 Public Domain이며 가공·상업 이용이 허용된다. [Natural Earth 이용 조건](https://www.naturalearthdata.com/about/terms-of-use/)

**정밀 지형 측량자료가 아니다.** Natural Earth 지형 면은 지명 표기를 위한 개략 영역이며, 제공처도 경계의 정밀도를 제한적으로 안내한다.
따라서 산맥의 큰 방향과 분지의 상대 위치를 참고하는 데 쓰고, 개별 소행성·통로 폭·거점 위치·권역 경계는 게임용으로 제작했다. [지형 면 자료의 범위와 한계](https://www.naturalearthdata.com/downloads/10m-physical-vectors/10m-physical-labels/)

장강·황하의 큰 형상은 실제 하천 선형을 반영하지만 **후한 말의 물길을 고증 복원했다고 표기하지 않는다.** 특히 황하 하류는 역사적으로 유로가 변했다. [NASA 황하 변화 자료](https://www.earthobservatory.nasa.gov/Features/WorldOfChange/yellow_river.php)

### 2.2 삼국지 주무대의 지형을 읽는 방식

|---|---|---|

사천분지가 산악지대에 둘러싸이고 장강 수계로 배수되는 큰 구조는 NASA 지형 자료와 대조했다. [사천분지](https://science.nasa.gov/photojournal/sichuan-basin-china/) · [사천의 산악 지형](https://science.nasa.gov/earth/earth-observatory/sichuan-provinces-rugged-terrain-8762/)

한중·남양·강한은 공개 지형 면의 누락을 보완하기 위해 문헌의 위치 관계를 따라 **별도의 게임용 근사 윤곽**을 작성했다. 논문의 경계선을 복제·측량 추출한 것은 아니다. [한수 상류와 한중 지형 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC3551924/) · [한수 유역의 한중·남양분지 및 강한평원 연구](https://www.nature.com/articles/s41598-025-10514-z)

### 2.3 창작 배치로 명시한 것

- 성계·권역 중심은 역사 지명의 대략적인 상대 위치를 따른다. 좌표의 소수점은 게임 배치 정밀도이며 고증의 정확도 표기가 아니다.
- 권역 경계는 45개 중심점 사이의 고정 공간 분할이다. 역사상의 주·군 경계가 아니며, 시나리오 세력 소유를 나타내지 않는다.
- 보조 행성·시설은 권역 내부에 고정 배치한다. 모든 거점에 실측 지리 좌표가 있는 것은 아니다.
- **구지·형혹·태음은 형주 `RGN-04` 태양계권**에 배치한다. 태양계권 자체의 중국 지리 대응은 세계관을 위한 창작 위치다.
- 회랑의 중심·폭과 항로 연결 곡선은 기존 연결망을 유지한 공간 초안이다. 강·산맥 참고선과 모든 항로를 동일시하지 않는다.
- 산악축 5개, 분지·평원 보완 윤곽 3개는 `basis` 필드로 개략 원자료와 구분한다.

## 3. 사용자 확정 지형 규칙

### 3.1 검은 공간

장애 밀도 0. 함대는 **서로 연결된 검은 공간 안에서** 명명된 선을 따르지 않고 자유롭게 진로를 선택할 수 있다. 그러나 검은 공간의 자유항행은 통과 불가 지형이나 회랑 차단대를 넘어가는 권한이 아니다. 회랑으로만 이어진 두 지역은 회랑 밖으로 우회할 수 없다.

### 3.2 지형 참고선

황하·장강·한수·위수·회수 등의 하천 벡터는 **중국 지형 관계와 항로 굴곡을 제작하기 위한 참고선**이다. 이동 판정을 0%로 바꾸거나 자유항행 통로를 만들지 않는다.

- 일반 은하 지도에서는 표시하지 않고 ‘지리 대조’ 모드에서만 청회색 선으로 표시한다.
- 지형 참고선은 회랑을 절단하거나 우회시키지 않으며 밀도 판정 우선순위에도 들어가지 않는다.
- 황하·장강의 큰 굴곡은 관련 성간 항로의 곡선 형상을 검토하는 기준으로 사용한다.

### 3.3 분지·평원

사용자가 확인한 **20~30%는 장애 밀도 수치가 아니라 전체 면적 중 장애 지대의 점유 비율**이다.

분지·평원마다 면적 25%를 목표로 연속적인 불규칙 장애 패치를 배치한다. 나머지는 밀도 0의 개방 공간이다. 회랑 통로·차단대와 행성 주변을 포함한 최종 판정 뒤 실제 장애 면적을 검사한다.
장애 패치 내부의 밀도는 별도 값이며, 이번 초안은 65~155/255 범위의 완만한 변화를 사용한다. 이 내부 밀도와 속도 수치는 사용자 확정 밸런스가 아니다.

| 지형 구역 | 검증된 장애 면적 비율 |
|---|---:|
| 익주 분지공간 | 24.43% |
| 중원 평원 대응 공간 | 24.67% |
| 요동 평원 대응 공간 | 24.98% |
| 한중 분지공간 | 25.11% |
| 남양 분지공간 | 25.32% |
| 강한 평원공간 | 24.88% |

측정은 제작용 보정 표본과 다른 100×100 격자 표본을 사용한 면적 근사 검사다. 정밀 해석기하 면적값이라고 주장하지 않는다.

### 3.4 산악대·고원·먼지대

산악대는 소행성·파편의 집중 구역으로, 고원·사막 대응 지형은 먼지·가스와 파편이 혼합된 구역으로 표현한다.
옅은 녹색은 장애물이 적고, 짙은 녹색은 장애물이 많다. **이전 v1의 ‘모든 장애 지대 통과 가능’ 규칙은 폐기한다. 밀도 70% 미만은 통과 가능하고, 70% 이상은 통과 불가다.** 개별 암석 하나가 아니라 합산 환경 밀도로 판정한다.

검토 화면의 임시 지형 비용 계수는 70% 미만에서 `1 + 2.5 × density / 255`, 속도 계수는 그 역수다. 0이면 비용 ×1·속도 ×1이며 70% 이상은 비용 계산 전에 이동 불가로 반환한다.
이 값은 기존 항로 시간과 중복 곱하지 않으며, 항로·회랑·함대 속도와의 최종 계산식은 후속 연동 사항이다.

### 3.5 거주 행성계와 혼합 장애물 — 지도 v3

기존 지구형 행성 **22곳**을 거주 행성으로 판정한다. 각 거주 행성 주변에 다음 고정 천체를 둔다.

- 중심 항성 1개
- 거주 행성 1개와 그 위성 1개
- 수성형 내행성 1개와 금성형 행성 1개
- 구지 행성계는 고유명 **태양·수성·금성·구지·태음·형혹·목성**을 사용하며 목성까지를 표시 범위로 삼는다.
- 다른 거주 항성계는 고정 시드로 외행성 1~4개와 최외곽 거리를 달리한다. 같은 지도 버전에서는 항성계 길이와 행성 수가 바뀌지 않는다.
- 추가 천체는 경제·점령 단위를 늘리지 않는 표시·공간 개체다. 기존 45개 권역과 104개 경제·시설 개체의 게임 수치를 바꾸지 않는다.

거주 행성계 주변의 환경 밀도는 **5~10%**로 고정 생성한다. 회랑과 겹치면 회랑 규칙이 먼저다. 분지·평원은 이 행성 주변 지대를 포함한 뒤에도 장애 면적 20~30%가 되도록 다시 보정한다. 최대 상세 화면에서는 회색 소행성, 황갈색 먼지 입자, 청록색 가스층, 자홍색 방사 띠를 동시에 그리며 네 성분의 고정 혼합 가중치는 각 75~125 범위로 제한해 한 성분만 과도하게 나타나지 않게 한다.

장애 밀도는 소행성만을 뜻하지 않는다. 각 400×400 월드 구역마다 고정 시드로 **소행성·먼지·가스·강한 방사** 네 성분의 비율을 달리하고, 네 성분의 합이 해당 지점의 총 밀도와 정확히 일치한다. 카메라 재진입 때 새로 섞지 않는다.

소행성의 물리 반지름은 **0.04~0.12 월드 단위**다. 거주 행성의 최소 표시 반지름 5보다 매우 작으며 최대 확대에서 다수의 작은 개체로 표현한다. 암석 외곽이 행성을 침범하는 배치는 제외한다.

한 성계 안의 모든 행성·위성·거점은 최소 연결망으로 이어 총 **150개 행성 간 이동 경로**를 만든다. 경로 폭은 반폭 4 월드 단위이며, 경로 안의 밀도는 주변 환경의 **75%**로 낮춘다. 회랑 통로·차단대에서는 이 감쇠를 적용하지 않는다. 경로 감쇠율·폭·비용 계수는 조정 가능한 초안 수치다.

### 3.6 경로 우선 성간 지형 — V-68·V-69

기존 **37개 성간 경로를 먼저 고정하고**, 경로의 역할을 설명하도록 주변 밀도 지형을 생성한다.

| 경로 역할 | 수량 | 상시 표시 | 공간 판정 |
|---|---:|---|---|
| 기저항로 | 15 | 아니요. 함대 이동 명령 때만 실제 경로 표시 | 반폭 32 안에서 밀도 상한 76/255 |
| 회랑 경로 | 13 | 예 | 회랑 내부 102/255(40%), 주변 차단대 최소 190/255(74.5%) |
| 고속항로 | 5 | 예 | 반폭 42 안에서 밀도 상한 26/255, 별도 속도·비용 이점 |
| 고속항로+관문 | 4 | 예 | 일반 구간은 고속항로, 관문 구간은 회랑 판정 |

지도 데이터에는 회랑 개체 15개가 존재하며, 37개 경로의 종류별 개수와는 별도다. 각 회랑은 중심 통로와 그에 직교하는 차단대를 함께 갖는다. 통로는 항상 통과 가능하고 차단대는 70% 이상이므로, 회랑으로 연결된 두 지역 사이에서 검은 공간을 이용한 직접 우회가 성립하지 않는다.

각 항로는 작성된 성계 끝점·중간 기준점·관문 축을 먼저 보존한다. 관문 내부 축을 제외한 구간은 좌우 곡선 후보의 기초 지형 밀도를 비교해 더 낮은 쪽을 선택하고, 최대 100 월드 단위 간격으로 표본화한다. 결과 좌표열은 화면 선, 성간 항로 밀도 상한, 이동 비용 판정이 공동 사용하므로 보이는 선과 실제 통행 공간이 어긋나지 않는다.

## 4. 전체 지도와 확대 지도

| 배율 | 지형 표시 | 거점 표시 |
|---|---|---|
| ×1~2 | 중국 지형에서 옮긴 산악·먼지대의 큰 실루엣, 장애 패치, 전략 곡선 항로 | 19개 성계 중심과 이름 |
| ×2~6 | 같은 지형의 윤곽과 분지 내부 패치 확대 | 주요 행성, 선택 가능한 권역 경계 |
| ×6~18 | 장애 지대의 밀도 차이와 곡선 항로의 세부 굴곡 | 행성·시설 개별 이름과 유형 |
| ×18~55 | 고정 좌표의 개별 소행성으로 상세화 | 행성 표면·시설 형태 |
| ×55~512 | 같은 암석의 형상·반지름·방향·분포와 가스·먼지·방사 레이어 확인 | 구형 행성의 표면·명암 등 상세 표현 |

배율 경계는 미리보기 초안이며 최종 카메라 연출의 확정값이 아니다. 각 단계는 별개 지도가 아니라 하나의 데이터를 다르게 그리는 단계다.
함대 집계→전대→함선 및 이동·전투 메뉴는 [지도 UX 문서](../06-tech/map-ux-concept.md)를 따른다. 이 미리보기에는 가짜 플레이 기능이나 임시 함대를 넣지 않았다.

**PC 조작:** 드래그로 이동, 휠로 커서 중심 확대, 클릭으로 지점 고정, 더블클릭으로 상세 확대, `Home`으로 전체 복귀. 관찰 위치 선택과 ‘선택 지점 최대 확대’로 같은 곳을 바로 대조한다.
‘지리 대조’는 동일 좌표에 원자료의 지형 면·해안선을 겹치는 검토 모드이며 게임 내 현실 지구 지도 모드가 아니다.

## 5. 지형을 바꾸지 않는 데이터 구조

### 5.1 좌표와 해상도

- 지도 ID `seonghanji-china-galaxy`, 지도 버전 **3**, 시드 190208. v1·v2는 `data/maps/archive/`에 보관하고 지도 지문으로 구분한다.
- 동쪽이 +X, 남쪽이 +Y. 지도 크기 **37,312 × 30,000 월드 단위**.
- `x = (경도 − 90) × 848`, `y = (46 − 위도) × 1000`. 월드 단위는 km나 실제 성간 거리 단위가 아니다.
- 기초 밀도장은 200 단위 간격, **187×150 셀**. 분지 패치·회랑·곡선 항로는 이 격자와 별개의 연속 좌표 판정을 사용한다.
- 로딩 구역은 최대 5×5 셀, 1,000 단위 크기다. 경계 셀의 소유 구역은 하나뿐이다.

### 5.2 고정 상세 개체

소행성 생성 입력은 **지도 시드·셀 X/Y·셀 내부 슬롯 번호·생성기 버전**뿐이다.
v3는 셀마다 작은 소행성 후보 1,024개를 만들고 혼합 밀도의 소행성 몫과 행성 제외 규칙으로 선택한다. ID는 `AST2-셀X-셀Y-슬롯`이다.
위치·반지름·형상 시드·회전이 항상 같은 값으로 복원된다. 렌더링 순서, 카메라 배율, 현재 시각, 전투 난수는 입력에 없다.

광역 배경·지점 정보·소행성 배치는 동일 규칙인 `sample_world`를 사용한다. 판정 우선순위는 **회랑 통로 40% → 회랑 차단대 70% 이상 → 거주 행성 주변 5~10% → 분지·평원/광역 밀도장 → 성간 곡선 경로 밀도 상한 → 행성계 경로 감쇠 → 70% 차단**이다.
미리보기는 확대 시 필요한 셀만 생성하고 캐시를 제한한다. 캐시에서 지워진 셀도 재생성하면 동일하다. 다수 암석을 영구 세이브에 모두 복사하는 방식은 아니다.

### 5.3 저장과 버전

저장 참조에 `map_id`, `map_version`, `content_sha256`, `seed`, `generator_version`, `asset_version`이 필요하다.
한 항목이라도 다르면 원래 버전의 지도 패키지를 요구한다. 같은 시드라는 이유로 새 알고리즘을 적용해 지형을 조용히 바꾸지 않는다.

v3 계약은 `route-first-curves-u32-v3`와 `route-first-curves-v3`다. 출시 후 수정하려면 구버전을 보존하거나 명시적 지도 버전 이전이 필요하다.
브라우저·Python 구현의 동일성은 검사했지만 **Godot·Android·iOS 실기기 검증은 아직 하지 않았다.** Godot 포팅 시 32비트 정수 연산·반올림·지문 검사까지 동일하게 옮겨야 한다.

시나리오 소유·함대 상태·시설 손상은 지도 원본과 분리한다. 카메라를 저장하더라도 지형 생성 입력으로 사용하지 않는다.

## 6. 재생성 및 검증

프로젝트 루트에서 실행한다. 이미 원자료가 포함되어 있으므로 일반 재생성은 네트워크를 사용하지 않는다.

```powershell
python -X utf8 tools/build_galaxy_map.py
python -X utf8 tools/validate_galaxy_map.py
node tools/capture_galaxy_preview.cjs
```

마지막 화면 검사는 Playwright와 Edge가 필요하다. 데이터 제작·검증은 Python 표준 라이브러리와 Node.js만 사용한다.
원자료를 다시 받는 작업은 `tools/fetch_map_geography.py`로 별도 수행하며, 기존 지도 버전의 입력 파일을 덮어쓴 뒤 기존 세이브에 적용해서는 안 된다.
