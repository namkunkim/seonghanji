# MGMT-HANDOVER-01 — 적벽 데모 요구사항 인터뷰 기록

> Task ID: `MGMT-HANDOVER-01`
> 공식 작업 제목: 성한지 프로젝트 진행·일정·작업 프롬프트 관리
> 새 작업 제목: MGMT-HANDOVER-01 — 성한지 프로젝트 진행·일정·작업 프롬프트 관리
> 인터뷰 일자: 2026-09-10
> 상태: 진행 중 — 사용자 최종 확정 및 시작 승인 전
> 구현 잠금: 인터뷰가 끝나고 사용자가 시작을 명시하기 전에는 구현, 자산 생성, 외부 음원 반입을 시작하지 않는다.

## 1. 제품 목표와 시작점

- 1차 데모의 플레이어는 유비다. 손권과 조조는 AI다.
- 데모는 적벽 전투 직전의 역사적 세력·장수·함대 위치가 준비된 상태에서 시작한다.
- 선행 역사 사건 선택과 장거리 집결 과정은 데모에서 생략하고 바로 전투 준비·전투로 진입한다.
- 내정·경제·함선 생산 시설·세력별 함종 보유 수량 시스템은 배경 정본으로 존재하되, 1차 데모에서는 그 결과만 역사적 초기 데이터로 제공한다.
- 결과 화면 확인이 데모 종료점이다. 이후 캠페인으로 이어지지 않는다.
- 결과 화면에서 새 전투 시작, 저장 불러오기, 전투 기록 다시 보기를 제공한다.

## 2. 플레이어와 연합 함대 권한

- 기본적으로 유비는 자기 전대만 직접 지휘한다.
- 매 턴 유비 명령 입력 뒤 손권 함대를 직접 제어할지 묻는다.
- `Yes`이면 손권 전대의 이동·편성·진형·무기·공격 명령을 유비 측과 같은 수준으로 직접 입력한다.
- `No`이면 손권 AI가 그 턴의 명령을 정한다.
- 질문 화면에서 `더 이상 묻지 않기`를 선택하면 이후 턴은 손권 AI 자동 운용으로 넘어간다. 설정에서 질문을 다시 활성화할 수 있어야 한다.
- 조조군은 항상 AI가 지휘한다.
- 플레이어는 유비지만 전투 결과는 손유 연합 단위로 판정한다. 단, 유비군 패배는 연합군 패배다.

## 3. 전투 준비와 편성

- 기본 편성은 적벽 시점의 역사적 편성이다.
- 사용자 설정 메뉴에서 모든 참가 함선을 재배치할 수 있다.
- 기존 함대·전대 사이 재배치, 신규 함대·전대 생성, 해체를 모두 제공한다.
- 세력별 함종·보유 수량을 관리하고, 편성하면 재고에서 차감하며 해체·제외하면 반환한다.
- 남은 함종만으로도 전대를 구성할 수 있다. 예를 들어 전열함만 남았다면 전열함 단일 구성도 허용한다.
- 함대·전대 편성 한도는 단순 척수보다 함종별 코스트 합계로 관리한다.
- 코스트 상한은 담당 장수·제독의 지휘 능력에 따라 달라진다.
- 상한 초과 편성은 금지하지 않고, 초과 비율에 따라 기동·명중·사기 불이익을 점진 적용한다.
- 진형은 정본으로 정의된 진형 목록에서 선택한다.
- 전투 시작 뒤에는 함대 간 함선 또는 장수를 재배치하지 않는다.
- 적벽 시점에 생존하고 해당 전역에 동원 가능한 각 세력의 주요 장수 전체를 편성 후보로 제공한다.
- 장수·제독을 함대·전대에 재배치할 수 있으며 지휘 한도·기동·사기·명중 등에 영향을 준다.
- 초기 위치와 인물 가용성은 역사적 기준을 유지하되 함선 수·함종·코스트·능력치는 보통 난이도의 데모용 균형을 적용한다.

## 4. 턴 흐름

한 턴은 다음 순서로 진행한다.

1. 유비 전대별 명령을 설정한다.
2. 턴 실행을 누른다.
3. 손권 함대 직접 제어 여부를 묻는다.
4. `Yes`이면 손권 전대별 명령을 설정하고 다시 턴 실행을 누른다.
5. `No`이면 손권 AI가 명령을 설정한다.
6. 조조 AI 명령을 포함한 세 진영 명령을 함께 판정한다.
7. 이동·요격·사격·피격·상태 결과를 2D 연출로 재생한다.
8. 턴 종료 뒤 모든 승리 조건을 검사한다.
9. 승패가 없으면 다음 턴으로 간다.

- 턴 실행 전에는 입력한 모든 명령을 수정·취소할 수 있다.
- 턴 실행 후 결과는 되돌리지 않으며 전투 기록으로만 다시 본다.
- 전투는 최대 20턴이다.

## 5. 전대 명령과 공간 판정

- 모든 이동·공격 명령은 함대가 아니라 전대별로 입력한다.
- 전장 지도에서 격자 없이 자유 좌표를 클릭해 목적지를 지정한다.
- 여러 경유점을 이어 이동 경로를 계획할 수 있다.
- 전대는 위치와 방향을 가지며 정면·측면·후방 공격 효과가 다르다.
- 이동은 기동력 순서로 짧은 구간씩 교차 실행해 빠른 전대가 위치 선점과 요격에서 유리하다.
- 적대 전대 경로가 교차하면 이동 도중 요격·교전이 발생한다.
- 이동 중 탐지된 적이 사거리·사격각에 들어오면 그 턴의 무기 배분에 따라 기회 사격한다. 공격 보류 전대는 사격하지 않는다.
- 성운·잔해·행성 그림자 등 전장 지형이 이동·탐지·무기 효과에 영향을 준다.
- 퇴각은 지정 탈출 지점까지 실제 이동한 뒤 턴 종료 판정에서 성공한다.
- 지정 턴·사건 조건에 따라 증원 전대가 등장하며 위치와 이유를 알린다.

## 6. 탐지와 정보전

- 탐지되지 않은 적의 정확한 위치·편성·상태는 공개하지 않는다.
- 탐지를 놓친 적은 마지막 확인 위치와 확인 시점을 표시하고 현재 위치와 다를 수 있음을 알린다.
- 마지막 확인 좌표에 추정 사격을 허용하되 정확한 표적 사격보다 명중률을 낮춘다.
- 탐지는 함종별 센서·전자전 능력, 장수·제독 능력, 진형, 거리, 지형의 영향을 받는다.
- 탐지된 적에 대해서는 정보 정확도에 따른 예상 이동 방향과 위협 행동을 표시한다. 확정 명령으로 표현하지 않는다.

## 7. 무기·보급·수리

- 함선 무장 구성은 전투 시작 전에 고정한다. 전투 중 장비 교체는 하지 않는다.
- 매 턴 전대가 장착한 가용 무기의 사용 비율을 정한다.
- 가용 무기 배분 합계는 100%다. 균형·근거리·장거리·함재기 집중 프리셋과 합계 자동 보정을 제공한다.
- 사거리·탄약·재사용 대기 등으로 사용할 수 없는 무기는 0%로 잠근다.
- 공격하지 않는 행동은 무기 비율 0%가 아니라 별도 `공격 보류` 명령으로 제공한다.
- 모든 무기는 탄약·함재기·에너지·열·특수 자원 등 제한 자원을 소비한다.
- 보급함은 범위 안의 아군 전대에 탄약·에너지·함재기를 보급할 수 있다.
- 보급함은 제한 자원을 소비해 생존 함선 수리와 부상 장수 후송을 수행할 수 있다.
- 파괴된 함선은 전투 중 복구하지 않는다.

## 8. 특수 전술

- 역사적 화공은 SF식 `연쇄 폭발 작전`으로 재구성한다.
- 표현 요소는 무인 폭발정, 플라스마 소이탄, 조조군 밀집 진형, 태양풍·성운 흐름, 반응로 연쇄 유폭이다.
- 발동 조건은 폭발정 전대 생존, 조조군 밀집 진형, 목표 탐지, 지정 사거리 진입, 태양풍·성운 흐름 확보다.
- 모든 조건을 충족해 사용자가 직접 선택하면 확률 판정 없이 성공한다.
- 성공은 즉시 승리가 아니라 대규모 피해·사기 저하·센서 장애·지형 효과를 적용한 뒤 일반 승리 조건으로 판정한다.
- 조조 AI는 발동 전 진형 분산·폭발정 요격·탐지 교란·거리 이탈로 조건 성립을 방해할 수 있다. 발동 이후 성공을 취소하지 않는다.

## 9. 사기와 장수 상태

- 전대는 함선 손실뿐 아니라 사기에 따라 명령 불복종·강제 퇴각·항복할 수 있다.
- 사기 결과는 확률이 아닌 고정 임계값으로 결정하며 현재 값과 다음 위험 단계를 UI에 표시한다.
- 기함 피격·전대 격파·퇴각 실패 등에 따라 장수·제독이 부상·전사·포로가 될 수 있다.
- 장수 결과도 조건에 따른 결정적 판정을 사용한다.

## 10. 승리 조건과 우선 판정

- 매 턴 이동·전투 결과 적용 뒤 모든 승리 조건을 검사하고 하나라도 충족하면 종료한다.
- 같은 턴에 양측 승리 조건이 동시에 성립하면 조조군 승리다.
- 유비 기함 격침은 즉시 연합군 패배다.
- 유비군이 시작 코스트의 70% 이상을 잃거나 사기 붕괴·항복하면 연합군 패배다.
- 조조 기함 격침은 남은 조조군과 관계없이 연합군 승리다.
- 조조 기함이 조조군 탈출 지점까지 퇴각하면 연합군 승리다.
- 유비 기함과 필수 전대가 연합군 탈출 지점에 도달하면 연합군 제한적 승리다.
- 그 밖의 전력 붕괴는 손유 연합과 조조군 각각의 시작 함선 코스트 대비 70% 이상 손실로 판정한다.
- 손권군만 패배해도 유비군이 지속 가능하면 연합 판정은 계속한다.
- 20턴까지 다른 종료 조건이 없으면 양측 시작 대비 잔존 함선 코스트 비율을 비교하며 높은 쪽이 승리한다. 동률은 조조군 승리다.

## 11. 저장과 복원

- 전투 준비, 유비 명령 입력, 손권 제어 질문, 손권 명령 입력, 턴 결과 이후 등 언제든 저장할 수 있다.
- 수동 저장 슬롯은 3개다.
- 턴 종료 자동 저장을 별도 제공하며 수동 저장을 덮어쓰지 않는다.
- 저장은 입력 중인 명령, 손권 제어 질문과 `더 이상 묻지 않기`, 탐지 정보, 자원, 사기, 장수 상태, 증원, 승리 조건 진행을 복원해야 한다.

## 12. 화면·이미지·입력

- 함선 표현에는 기존 모델을 포함해 3D 모델과 3D 시네마틱을 사용하지 않는다.
- 모든 함선·항해·전투 표현은 생성 또는 승인된 스틸 이미지와 2D 레이어 연출을 사용한다.
- 턴 판정은 함선 이미지의 이동, 사격, 피격, 발광, 확대·축소, 패닝 효과로 재생하며 전체 재생·배속·건너뛰기를 제공한다.
- 단일 2D 전술 지도에서 전대를 선택하고 하단 명령 패널에서 이동·진형·무기 비율·표적을 설정한다.
- 지도 전대는 위에서 내려다본 함선 이미지와 진형 실루엣으로 표시한다.
- 선택 전대 상세는 측면 함선 스틸 이미지를 표시한다.
- 어두운 우주 배경과 세력별 색상을 유지한다.
- 동양적 문양은 UI 테두리와 세력 문장에 절제해 사용한다.
- 기준 환경은 Windows 1600×900, 마우스·키보드다.
- 필수 조작은 마우스 기준이며 키보드 단독 완주는 요구하지 않는다.
- 마우스 휠 확대·축소와 드래그 지도 이동을 제공한다.
- 첫 실행에 단계별 튜토리얼을 제공하고 설정에서 다시 볼 수 있게 한다.
- UX 디자이너와 독립 리뷰어가 이미지 일관성, 정보 계층, 입력, 가독성, 상태 피드백을 검수한다.

## 13. 장수·제독 초상

- 초상은 사실적인 반실사 회화풍으로 통일한다.
- 기존 샘플을 우선 사용하고 누락된 필수 인물만 생성한다.
- 유비·제갈량·주유·손권·조조뿐 아니라 적벽 시점에 해당 전역에 동원 가능한 각 세력 주요 장수 전체를 제공한다.

## 14. 음악과 효과음

- 음성 연기는 제외하고 배경음악·효과음·텍스트 대사를 사용한다.
- 음악감독 역할을 둔다.
- 음악 방향은 동양 전통 악기와 우주 오케스트라의 혼합이다.
- 항해·전투 준비·교전·위기·결착에 따라 음악 강도를 전환한다.
- 외부 음원은 무료이면서 합법적으로 사용할 수 있는 자료를 우선한다.
- 무료 후보로 해결되지 않을 때 유료 후보를 제안한다. 결제·회원가입·약관 동의는 사용자 승인 전 실행하지 않는다.
- 채택 음원은 출처·라이선스·가격·크레딧 조건을 기록한 뒤 저장소에 반입한다.
- 효과음 범위는 UI 조작, 함대 이동, 탐지·경보, 함포·미사일·함재기, 피격·폭발, 사기 붕괴, 특수 전술, 승리·패배다.
- 전체·BGM·효과음 음량을 각각 조절하고 전체 음소거를 제공한다.
- 핵심 음향 신호에는 시각 알림과 효과음 자막을 함께 제공한다.

## 16. 구현·조율 규칙

- 인터뷰와 사용자 최종 확인을 마친 뒤에만 구현을 시작한다.
- 오케스트레이터와 구현·감사·리뷰 에이전트는 `gpt-5.6-sol`, reasoning `medium`을 사용한다.
- 오케스트레이터는 코드를 직접 구현하지 않고 작업 분해, 에이전트 배정, 독립 검증, 일정, Tracker·Handover 정합성을 관리한다.
- 구현은 멀티 에이전트 방식으로 하되 코어 판정, 전투 UI/UX, 이미지, 오디오, QA/독립 리뷰의 소유 경로를 분리한다.
- 신규 3D 모델 제작, 기존 3D 모델 런타임 사용, 3D 시네마틱 제작은 금지한다.
- 이미지와 음원은 출처·라이선스·생성 프롬프트·해시를 기록한다.
- 각 구현 Task는 Task ID, 공식 작업 제목, 새 작업 제목을 동일하게 사용하고 구현·관련 시험·독립 검증·Tracker·Handover·경로 지정 스테이징·커밋·`origin/main` 푸시·HEAD 일치를 완료 조건으로 둔다.
- 공유 작업 트리의 기존 변경을 다른 작업의 소유물로 취급한다. `git add .`, `git add -A`, reset, clean, stash, 무단 checkout을 사용하지 않는다.
