# DEMO-RC-G2-01 — 유비 직행 전투 준비 화면 및 역사적 초기 상태 경계

> Task ID: `DEMO-RC-G2-01`
> 공식 작업 제목: 유비 직행 전투 준비 화면 및 역사적 초기 상태 경계
> 새 작업 제목: DEMO-RC-G2-01 — 유비 직행 전투 준비 화면 및 역사적 초기 상태 경계

## 범위

메인 화면의 기존 `적벽` 조작은 손권 플레이, 선행 사건 선택과 장기간 함대 집결을 시작하지
않는다. 이제 검증된 적벽 전용 초기 데이터에서 유비 플레이어, 손권·조조 AI 구도와 세 세력의
초기 전대를 읽고 순수 2D 전투 준비 화면을 직접 연다.

화면은 역사 편성 복원, 사용자 편성, 전투 시작 진입점을 표시한다. 이번 단위에서는 역사 편성
요약만 읽을 수 있다. 사용자 편성은 데이터를 바꾸지 않고 후속 작업임을 알리며, 전투 시작도
미구현 턴 전투로 진입하지 않고 다음 단계가 필요하다는 상태를 표시한다.

## 데이터 기준

`data/red-cliffs-demo-setup.json`은 다음 두 층을 분리한다.

- `historical_context`: 208년 적벽의 세력·인물·역할 구도를 설명한다.
- `balance_profile.id = normal-demo-v1`: 함선 수, 함종별 비용, 총비용과 초기 2D 좌표가 게임
  밸런스 값이며 역사적 사실이 아님을 명시한다.

전대는 고유 ID, 세력, 지휘관, 기함 여부, 진형, 2D 좌표, 함종별 수량·비용과 계산 총비용을
가진다. 새 경계는 기존 28척 고정 전대 상수를 사용하지 않는다. 기존 6함종에 `요격함`을
추가하고, `고속정`은 기본 선체와 요격·뇌격·정찰·구조 임무장비를 별도 확장 목록으로 둔다.

`RedCliffsDemoSetup` 로더는 필수 필드, 중복 세력·함종·전대, 필수 3세력과 세력별 전대,
미지 함종, 음수 수량·비용, 고속정 장비, 선언·계산 총비용을 검증한다. 오류가 하나라도 있으면
준비 화면에 이유를 표시하고 전투 시작을 잠그며 과거 흐름으로 폴백하지 않는다.

로더는 프로필 ID를 정확히 `normal-demo-v1`로, 세력 제어를 유비 `player`·손권
`turn_prompt_ai`·조조 `ai`로 제한한다. 고속정 장비 ID도 요격·뇌격·정찰·구조 네 종류와
정확히 일치해야 하며 누락·중복·추가를 거부한다. 진형은 `data/formations.json`의 현재 정본
ID `FRM-01`~`FRM-07`만 허용한다. 이 좁은 허용 목록은 setup 로더가 전체 `GameData`를
초기화하지 않게 하며 집중 시험이 진형 데이터와의 드리프트를 감시한다.

## 2D 화면 경계

`RedCliffPreparationView`는 `Control` 노드만 사용한다. GLB, `Node3D`, 기존 3D 항해 화면이나
3D 시네마틱을 참조하지 않는다. 1600×900에서 유비·손권·조조 열, 역사/밸런스 고지, 전대와
함종 비용, 네 개의 마우스 버튼을 한 화면에 배치한다. 반복 진입은 같은 View 인스턴스를
재사용한다.

## 후속 작업

- 함선·장수 재고를 사용하는 실제 사용자 편성 편집기
- 여러 전대를 묶는 함대와 지휘 한도·초과 불이익
- 유비 명령과 손권 턴별 문의를 포함하는 최대 20턴 전투 코어
- 자유 좌표 전술 지도, 탐지, 무기·자원과 2D 판정 재생
- 결과 전용 화면과 3개 수동 슬롯·별도 자동 저장

## 검증

집중 시험은 `tests/test_demo_rc_g2_01_direct_preparation.gd`다. 정상 데이터와 오류 경계,
유비 상태, 세 세력·전대, 2D 전용 소스, 1600×900 제품 진입, 후속 기능의 비파괴 상태와
중복 진입 단일 View를 확인한다. 실제 실행 결과와 GUI 관찰 기록은 구현 완료 보고에 덧붙인다.

구현 시점 실행 결과:

- 집중 시험: `63 PASS / 0 FAIL`, exit code `0`.
- 기존 2D 정지 이미지 전투 View 회귀: `0 failures`.
- 기존 canonical 전투 진입 셸 회귀: `33 통과 / 0 실패`.
- 과거 선행 사건 선택 제품 시험 `test_demo_rc_qa03_full_scenario_loop.gd`: 새 직행 계약과
  충돌하는 overlay 기대에서 `74 통과 / 3 실패`. 구계약 시험으로 보존하며 실패를 숨기거나
  수정하지 않았다.
- 실제 Godot 1600×900 렌더 캡처:
  `out/demo-rc-g2-01-direct-preparation/preparation-1600x900.png`. 유비·손권·조조 세 열,
  역사/밸런스 구분, 함종 수량·비용과 네 조작이 겹침·잘림 없이 표시됨을 육안 확인했다.

독립 UX 검증은 같은 집중 시험을 다시 실행해 `63 PASS / 0 FAIL`, exit code `0`을 확인했다.
캡처는 1600×900, 97,595 bytes이며 SHA-256은
`1B45E0AF6AE53183AB0BF30A0F3F343EB653457C10287EBFAB670D70DFB95FA6`다. 신규 데이터·로더·
준비 화면에서 `Node3D`, `Camera3D`, `MeshInstance3D`, GLB와 3D 항해 참조는 0건이고, 이번
Task 범위의 P1/P2 결함은 없다. 버튼 신호와 비파괴 상태는 자동시험으로 확인했으며 실제 OS
물리 마우스 입력은 후속 제품 QA에서 확인한다. `out/` 캡처는 Git에 포함하지 않는다.
