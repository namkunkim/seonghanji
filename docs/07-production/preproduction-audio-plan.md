## 2. 씬 ↔ 큐 매핑

### 2.1 원칙

1. **동시에 우는 BGM 은 하나다.** 상태 기계로 관리한다.
2. **화면(L1/L2/L3)에는 BGM 이 붙지 않는다.** BGM 은 **게임 상태**(평시 / 결정 / 전투 / 결착 / 막간)에 붙는다.
   성역 뷰·세부 뷰·외교·초빙·기록은 전부 「평시」이며 `BGM-001` 하나다.
3. **긴급은 정지가 아니라 전환으로 표현한다.** `screens.md` §11.1 이 정한 그대로 —
   시뮬레이션은 멈추지 않고, 「지금」은 음악과 배너 카운트다운이 만든다.
4. **소전투는 BGM 을 바꾸지 않는다.** `combat.md` §2.2 ③ — 소전투는 개입 0회.
   플레이어가 전투 지시 시트(`screens.md` §10)를 **실제로 띄운 대회전에서만** `BGM-003` 으로 전환한다.
   지도 위에서 전투가 결착되면 완료 통지음(`SFX-016`)과 복귀 브리핑 로그로 처리한다.

### 2.2 상태 기계(state machine)

```
                 ┌───────────────── [평시] BGM-001 ──────────────────┐
                 │  성역 뷰 · 세부 뷰 · 외교 · 초빙 · 기록 · 지도       │
                 └──┬──────────────────────────────┬──────────────────┘
     결정 큐 열림 /  │                              │  대회전 · 전투 지시 시트 진입
     긴급 배너(⚑) 뜸 ▼                              ▼
        [결정] BGM-002 ──── 큐 비고 배너 없음 ──▶ [평시] BGM-001
                 │                              │
                 │  대회전 진입                 │  ⑤ 결착 붕괴 판정 확정
                 └──────────────▶ [전투] BGM-003 ─┴─┬─ 아군 승 ─▶ BGM-004 (원샷)
                                                    └─ 아군 패 ─▶ BGM-005 (원샷)
                                                          │
                                       원샷 종료 후 ────────┤
                                                          ├─ 캠페인 계속 ─▶ [평시] BGM-001
                                                          └─ 막간/엔딩 진입 ─▶ BGM-006

  [막간 · 엔딩] BGM-006  ← 별도 모드. 상태 스택 밖. 진입/이탈은 §2.3 겹침 페이드
  [복귀 브리핑]          ← BGM-006 또는 무음 위에 SFX-013. 「처리하기」 → BGM-002
```

**우선순위(높→낮):** 원샷(`BGM-004`/`005`, 1회) > 전투(`BGM-003`) > 결정(`BGM-002`) > 평시(`BGM-001`).
전투 중 다른 긴급 배너가 떠도 `BGM-003` 을 유지한다(이미 최상위). 막간·엔딩(`BGM-006`)은
모드 전환이라 스택 밖이다.

### 2.3 전환 규칙

**기본 전환은 등출력(equal-power) 크로스페이드(crossfade)다.** 표에 없는 전환은 2.0 s 를 쓴다.

| 전환 | 트리거 | 방식 | 길이 |
|---|---|---|---|
| `BGM-001` → `BGM-002` | 결정 큐 오버레이 open · 긴급 배너(⚑) 최초 출현 (`screens.md` §11.2) | 크로스페이드 | **2.0 s** |
| `BGM-002` → `BGM-001` | 미처리 긴급 배너 0 **그리고** 결정 큐 비었을 때 | 크로스페이드 | **2.0 s** |
| `BGM-001`/`BGM-002` → `BGM-003` | 대회전에서 전투 지시 시트 진입(① 접적) | 크로스페이드 | **1.0 s** (빠르게) |
| `BGM-003` → `BGM-004`/`005` | ⑤ 결착 붕괴 판정 확정 (`combat.md` §1.4) | 하드 컷 후 원샷 | 0.2 s |
| `BGM-004`/`005` 종료 → `BGM-001` | 원샷 자연 종료 · 캠페인 계속 | 페이드 인 | **2.0 s** |
| `BGM-004`/`005` 종료 → `BGM-006` | 원샷 자연 종료 · 막간/엔딩 진입 | 페이드 인 | **3.0 s** |
| 임의 → `BGM-006` | 막간·엔딩 모드 진입 | 겹침 페이드(이전 out 3.0 s · `006` in 3.0 s) | **3.0 s** |
| `BGM-006` → `BGM-001`/`002` | 막간 종료 · 복귀 브리핑 「처리하기」 | 크로스페이드 | **2.0 s** |

## 4. SFX-101~130 — 전투 (30종)

### 4.1 확보 방식 — CC0 + 자작 합성. **AI 미사용 (확정 · 2026-08-30 발주자)**

`asset-ledger.md` §4.4-b 결론(「효과음은 AI 를 쓰지 않는다」)을 **전투 SFX 30종에도 적용한다.**
`SFX-001~020`(§3)과 같은 규율이다 — 저장소 전체에서 AI 효과음은 **0종**이다.

- **1순위 CC0** (Freesound · Kenney), **2순위 Audacity 로컬 합성·레이어링**. **3순위는 없다.**
- 자작 합성분은 `확보: 자작` · 라이선스 `자사`. 대장 규율 §5.3.
- CC0 로도 자작으로도 못 채우는 소리가 나오면 **그 SFX 를 목록에서 빼거나 다른 소리로 대체**한다 —
  AI 로 돌아가지 않는다.

> **왜 배제했나.** ① AI 효과음은 모델 라이선스 검증·스토어 고지(함정 3)를 20종을 위해 새로 떠안는다.
> ② `asset-ledger.md` §4.4-a 가 「AI 산출물은 저작권 대상이 아닐 수 있다」고 적었다 — 방어가 약한
> 에셋을 늘릴 이유가 없다. ③ 전투 SFX 는 CC0 라이브러리가 두껍고, 규격이 넓은 만큼 레이어링
> 자유도도 크다. **초상·BGM 과 달리 화풍 일관성 문제가 없어 AI 의 이점(시드 고정)이 무의미하다.**

### 4.2 무기군(weapon family) — 「같은 무기군은 한 출처로 묶는다」

### 5.3 SFX — 파일별 확인은 P0-08 · P-02 로

**이 문서는 SFX 파일을 확보하지 않는다.** 다만 규율을 여기 건다.

## 6. R-14 검수 순서 — 대표 세트 먼저 (못박음)

> R-14 대응안: 「짧은 대표 세트로 게임 내 반복 청취 후 전체 수집·생성으로 확장」.
> GATE-PRE-06: 「음원별 본생산 전 표본·품질·중단 기준」. **아래 순서를 뒤집지 않는다.**

### 6.1 대표 짧은 세트 (Audio Vertical Slice)

**BGM 루프 1곡 + 무기군 1개**로 최소 세트를 만든다.

1. **`BGM-003` 전투 루프 1곡** 완성 — ACE-Step 생성(§1) → Audacity 루프컷 → −16 LUFS(§2.5).
2. **무기군 A (광선 병기)** `SFX-110`·`111`·`116` 확보 → §4.3 정규화(피크 −3 dBFS · RMS ±1.5 dB · 공통 리버브).
3. 이 둘을 **시나리오 3 「적벽 전야」 ② 포화 페이즈에 인게임 배선**한다.
4. **배속 ×1·×2·×4 로 최소 10분 연속 청취** — 확인 항목:
   - 루프 이음매 클릭·박자 이탈 (`ai-media-pipeline.md` §5.3)
   - 반복 피로 (같은 프레이즈가 몇 번째부터 거슬리는가)
   - BGM ↔ SFX 음량 충돌 · 덕킹 동작
   - 배속 시 SFX 스팸 여부
5. **크로스페이드 3종 실전이 확인** — `BGM-001↔002`(2.0 s) · `002→003`(1.0 s) · `003→004`(하드컷+원샷).
