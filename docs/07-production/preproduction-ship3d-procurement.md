## 2. 4개 시각 세력군 — 도장·문장·색상 적용 규칙

### 2.1 대전제 — 색만으로 소유를 구분하지 않는다

`visual-direction-guide.md` §7 시각 쟁점 2는 **확정**이다 — 세력 색은 보조층이며, 소유는
**소유 글리프(● 아군 / ○ 타 세력 / ◌ 중립) + 세력명**이 정본 부호다(`app/views/ui_palette.gd`
`owner_glyph()`). 리스크 **R-11**(색만으로 소유·위험·잠금을 표현)을 다시 건다.

**세력 판독의 우선순위 — 3D 함선에서도 같다:**

```
1. 소유 글리프 + 세력명 라벨   (UI 오버레이 · 코어 정본)
2. 문장 (데칼)                 형태로 구분 — 흑백에서도 읽힘
3. 도장 패턴 (파이핑·2톤)      배치·질감으로 구분
4. 세력 색 (틴트)              가장 마지막. 단독으로 소유를 나르지 않는다
```

색각 이중 부호화(§8.2 판정 5): **흑백 변환 후에도** 문장 형태 + 도장 패턴만으로
4계열이 구별되어야 한다.

### 2.2 선체는 세력과 무관하다 (시각 쟁점 4 — 확정 범위)

- **3D 모델 6종은 세력 중립으로 제작한다.** 세력 차이는 **런타임 머티리얼 변형**으로만 준다.
- 세력별 **선체 실루엣 분화는 이번 단계에서 확정하지 않는다**(`visual-direction-guide.md`
  §7 쟁점 4 · `preproduction-av-plan.md` D3). 「동일 세력은 도장·문장·세부 파이핑을 공유하되
  **함종 실루엣을 덮지 않는다**」(§4.3)가 상한이다.
- 개별 세력 도장을 4계열 넘어 신설하지 않는다 — 그것이 **세력별 독립 함선 49종 설계로
  미끄러지는 지점**이다(작업 지시 금지 사항).

## 3. CC0 후보 탐색 기준 + 파일 단위 라이선스 검수 양식

### 3.1 탐색 기준 — `asset-sourcing` 순서 ②(범용물)

| 축 | 기준 | 불합격 |
|---|---|---|
| **라이선스** | **CC0 · Public Domain · Unlicense만.** CC-BY는 이번 단계 제외(표기 의무 승격 회피) — 다만 차선 후보로 별도 기록 가능 | **CC-BY-NC · NC 계열 · CC-BY-SA · 「개인 사용만」 · 독자 EULA 상용 불명 → 즉시 제외** |
| **출처 신뢰** | **파일 단위 라이선스 표기가 있는 곳만.** Poly Haven(전량 CC0)·Kenney(CC0)는 사이트 단위 신뢰 가능. OpenGameArt·Sketchfab·기타는 **파일마다 확인 필수** | 사이트가 CC0라고 광고하나 개별 파일 라이선스 명시가 없음 |
| **포맷** | glTF/`.glb`, 또는 `.fbx`/`.obj`+텍스처로 무손실 변환 가능 | 독점 포맷 · 텍스처 누락 · 재배포 불가 조건의 번들 |
| **지오메트리** | UV 존재 · 스케일 정규화 가능 · 삼각형 예산 내 or 감폴리 가능 · 하드서피스 | 서브디비전 원본만 · UV 없음 · 스캔 메시(수십만 폴리, 리토폴 불가) |
| **실루엣 매핑** | §1.3의 6함종 중 하나에 실루엣이 대응(또는 소폭 키트배시로 대응) | 6종 어디에도 안 맞는 함형 · 판타지/유기체 |
| **금지 요소** | §1.4 공통 금지 목록 통과 · 프랜차이즈 함형 아님 | §1.4 위반 1개 이상 |
| **텍스처 권리** | 동봉 텍스처·머티리얼도 같은 CC0이며 재배포·수정 허용 | 모델은 CC0인데 텍스처는 별도 유료/CC-BY |

### 3.2 탐색 로그 — 후보마다 한 행

| 필드 | 내용 |
|---|---|
| 후보 ID | `CAND-01` … (에셋 ID 아님 — 검토 단계 임시 번호) |
| 출처 URL · 페이지 스냅숏일 | 링크 + 확인한 날짜 |
| 원본 파일명 | 다운로드 전이므로 표기상 파일명만 |
| 선언 라이선스 · 원문 URL | 페이지에 적힌 그대로 + 라이선스 전문 링크 |
| 매핑 함종 | ①~⑥ 중 하나 (또는 「불가」) |
| 삼각형 수 (표기값) | 페이지 표기 기준 |
| 규격 적합 | §3.1 축별 O/X |
| 금지 요소 | 발견 시 명시 |
| 판정 | `후보` / `보류` / `제외` + 사유 |

> 라이선스 검수 양식(§3.3)을 채운 뒤에만 한다.

### 3.3 파일 단위 라이선스 검수 양식 — 반입 시 1파일 1양식

`asset-ledger.md` §0의 「에셋 하나 = 대장 한 줄」을 파일 단위로 강제한다.
**아래가 전부 채워지고 판정이 `검증`이 되기 전에는 게임에 반입하지 않는다.**

| # | 필드 | 기입 규칙 |
|---|---|---|
| 1 | 에셋 ID | `MDL-001`~`MDL-006` (함종 대응 고정) |
| 2 | 원본 파일명 · SHA-256 | 내려받은 파일 그대로. 해시는 반입 시점 계산 |
| 3 | 출처 URL · 페이지 스냅숏일 | 라이선스가 적힌 그 페이지. 캡처 보관 |
| 4 | 저작자 표기 | CC0라도 저작자명 기록(권장 표기용) |
| 5 | 선언 라이선스 · 원문 URL | CC0 1.0 등. **전문 URL 필수** |
| 6 | 상업적 이용 명시 여부 | 원문에서 확인. 「비상업」 문구가 있으면 제외 |
| 7 | 재배포·수정 허용 | 게임 빌드에 포함 = 재배포. 수정(리토폴·리텍스처) 허용 확인 |
| 8 | 파생물 라이선스 요구 | CC0는 없음. SA/전염성 조항 유무 |
| 9 | 표기 의무 | 있으면 **크레딧 화면이 UI 요건으로 승격**(`ui-design.md` · `asset-ledger.md` §0) |
| 10 | 동봉 텍스처·리깅의 별도 라이선스 | 모델과 다를 수 있음. 각각 1~9 반복 |
| 11 | 확인자 · 확인일 · 판정 | `판정` → `확보`(파일 있음) → `검증`(라이선스 확인 완료) |

**AI 도구를 리토폴/변환에 쓰는 경우:** `asset-ledger.md` §3.2 AI 3원칙 적용 —
서비스 상업 조건·확인일 기록, 「AI 처리」 명시, **미공개 서사 원고를 도구에 넣지 않는다**
(3D 작업에서는 해당 소지가 적으나 프롬프트 기반 도구 사용 시 R-20).

### 5.2 P0-09 게이트 추가 결정 기록 — 초안 (신설 예정 V-nn)

> `DECISIONS.md` 최신은 **V-54**. 아래는 P0-09 게이트에서 등재할 **초안**이며, 이 세션에서
> `DECISIONS.md`를 직접 편집하지 않는다(동시 세션 · 커밋 사고 방지 — `CLAUDE.md` §7 함정 7).

**결정(안).** L2 실시간 3D가 채택될 경우 함선 3D 조달은 다음으로 한정한다.

1. **공통 함급 6종만** 제작·조달한다(`ship-specs.md` §2.2). 세력별 독립 함선을 설계하지 않는다.
2. 세력 차이는 **위·촉·오·군웅 4계열의 도장·문장·색상 마스크로만** 표현한다(§2). 색은 판독
   우선순위 4번째이며 단독으로 소유를 나르지 않는다(R-11 · 시각 쟁점 2).
3. 후보는 **CC0만**, 탐색 **5일 상한**. 실패 시 **A(유료 스톡) → B(외주) → C(L2 보류)** 순으로
   전환하며 순서는 발주자가 확정한다.
4. **세력별 선체 실루엣 분화는 유보**한다 — 별도 결정으로 남기고, 장기판(6시나리오·인물 492)
   확장 시 소급 적용 가능성을 함께 검토한다(`asset-ledger.md` 검토 5).
