# DEMO-RC-G6-01 — 고속정 전대와 요격·뇌격·정찰·구조 임무 장비·코스트

## 범위

적벽대전의 전투 준비 단계에 실제 유비군 독립 고속정 전대 `RC-LIU-FC-01`을 제공한다. 사용자는 고속정 척수와 요격·뇌격·정찰·구조 중 하나의 임무 장비를 편집하고, 여러 고속정 전대를 선택·생성·해체하며 혼성 전대의 고속정을 별도 전대로 분리할 수 있다. 시나리오 전용 비용·재고·권장 지휘비 및 초과 예정치를 확인한 뒤 전체 setup을 원자적으로 적용한다.

고속정 `SHP-08`은 소형 전투정 범주이고, 요격함 `SHP-07`은 독립 고속 전투함 범주다. 화면에서 두 범주가 다르며 재고와 비용을 합산하지 않는다고 문구로 표시한다. 고정 28척이나 전역 경제 비용은 사용하지 않는다.

## 데이터와 API 권위

- 역사 시작 상태와 전대 구성: `data/red-cliffs-demo-setup.json`
- 시나리오 장비·비용 규칙: `data/red-cliffs-fast-craft-rules.json`
- 편성 정본: `core/demo_red_cliffs/red_cliffs_fast_craft_formation.gd`
- UI는 `catalog()`, `squadron_summary()`, `faction_summary()` 및 변경 receipt만 렌더한다.
- 수량·재고·단가·소계·권장 비용·초과 단계·불이익은 UI에서 다시 계산하지 않는다.
- `apply()`가 반환한 `applied_setup`, `formation_revision`, `digest`를 기존 편성 적용 signal로 전달한다. 이 전체 setup은 기존 setup 검증을 통과하며 전투 초기화 입력으로 사용된다.

## 정보 구조와 조작

1600×900 화면은 상단 범주 경계, 중앙 3열, 고정 하단 CTA로 구성한다.

- 왼쪽: 세력 및 여러 고속정 전대 선택, 역사/현재 척수와 임무, 여유 재고 생성·혼성 전대 분리·선택 전대 해체, 독립/함대 편입과 운용 기반 지정.
- 중앙: 척수 SpinBox와 네 임무 장비 버튼. 각 장비의 선체 단가·장비비·척당 총비용은 catalog 값을 표시한다.
- 오른쪽: 선택 전대 비용, 시나리오 재고·기존 배치·예약·잔여, 권장 지휘비·초과 단계와 기동/명중/진형 변경 불이익.
- 하단: 상태/오류, 역사 편성 복원, 변경 취소, 원자 적용, 편성 화면 복귀.

버튼과 수량 컨트롤의 최소 높이는 44px이며 기본 키보드 포커스를 지원한다. 적용하지 않은 변경이 있을 때 닫기나 Esc는 조용히 폐기하지 않고 상태 영역에서 적용 또는 취소를 요구한다. 중복 열기는 기존 패널을 재사용하되 부모의 최신 applied setup으로 다시 구성한다. 부모와 자식은 true historical과 latest applied를 별도로 전달하므로 재진입 뒤 역사 복원과 취소가 서로 뒤섞이지 않는다. 변경 없는 중복 적용은 signal을 다시 내지 않는다.

## 적용 및 전투 경계

역사 기본은 `RC-LIU-FC-01`, 조운, `SHP-08` 6척, 정찰 장비, 독립/작전 가능 배치다. 새 전대는 독립 또는 기존 같은 세력 함대에 편입할 수 있고, 운용 기반은 독립정·강습모함 탑재형·거점 배치형 metadata로 구분한다. 이 기반은 준비 편성 정보이며 실제 발진·복귀·보급 처리는 후속 기능이다. 편성 적용 뒤 준비 화면 요약과 기존 applied setup 경계가 즉시 갱신된다. 전투 화면은 자기 전대의 적용된 척수·장비·선언 비용만 읽기 전용으로 표시하며, 전투가 시작된 뒤 편성 초안을 변경해도 진행 중 battle의 deep copy는 바뀌지 않는다.

권장 비용 초과 단계 중 기동 수치는 기존 G4 이동 소비 경로에 적용된다. 명중·진형 변경 수치는 준비 단계의 예정치이며 G6-01 전투 resolver는 아직 소비하지 않는다. UI는 이 차이를 명시하며, 나머지 실제 전투 소비는 별도 수용 범위가 필요하다.

이번 작업은 준비 단계 편성만 다룬다. 전투 중 상시 장비 변경, 보급, 귀환, 표류 및 구조 결과는 후속 기능이며 활성 컨트롤이나 결과로 가장하지 않는다.

## 비범위와 안전 경계

- 순수 `Control` 기반 2D이며 `Node3D`, GLB, 3D 항해 화면을 참조하지 않는다.
- 요격함과 고속정 재고/비용을 합산하지 않는다.
- 초과 편성은 코어 receipt가 허용할 때만 적용되며, 표시 수치는 코어 summary를 그대로 사용하되 G6-01 전투 미적용 예정치라고 명시한다.
- active battle에는 준비 단계 편집 기능을 제공하지 않는다.
