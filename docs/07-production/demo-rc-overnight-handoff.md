## 검증 근거의 수준

[중간 QA 증거](demo-rc-fin-qa-evidence.md)에는 격리 사용자 경로·명령·종료 코드·로그·일부 후보 해시가 기록되어 있다. 이후 변경된 파일에는 이전 해시의 시험 결과를 그대로 적용하지 않는다.

후속 집중 시험 보고는 권한64/0(구현자), LT02 38/0, 실제 데모 프로필 QA03 107/0, 결과 재열람 QA01 실패0, 저장 UI15/0, 입력 이벤트28/0, 설정16/0이다. 이는 각 실행 시점의 범위별 결과이며 전체 최종 패키지 수용을 뜻하지 않는다. GPU 캡처6건은 headless 환경에서 보류되었고 사람이 직접 입력한 결과가 아니다.

중간 실패를 삭제하지 않았다. Main/시험의 parse 오류, LT02 이전 계약 기대, importer 중단/권한 오류를 분리 기록했다. 특히 프로세스가 exit0을 돌려주었어도 UI 시험이 실행되지 않은 사례는 무효로 판정했다.

마감 감사에서 run33의 `quality-gate/summary.json`과 21개 실제 stage 로그를 확인했다. 요약상 **21단계 PASS, exit0, timeout 없음**이다. 이는 해당 실행 결과의 확인이며 현재 파일과 당시 후보의 동일성은 [마감 기술 감사](demo-rc-final-technical-audit.md)의 해시 판정을 함께 따른다.

**감사 결론:** run33 자체에 후보 manifest가 없고 과거 중간 해시와 현재 파일6개가 다르므로, run33와 현재 후보의 동일성은 미확인이다. 변경 사실을 결함으로 단정하지는 않지만 최종 기술 수용은 보류한다. 다음 재실행에서는 시작/종료 시점 후보 해시와 로그를 함께 고정해야 한다.

## 남은 필수 절차

- [ ] 최종 whole-gate 결과와 현재 전체 후보 식별 근거를 확정한다.
- [ ] 원본·미사용 자산·import 노이즈와 실제 런타임 필수 파일을 구분해 재현 가능한 소스/자산 묶음을 만든다.
- [ ] Godot Windows export template를 준비하고 독립 exe/PCK를 생성한다. 현재 설치 경로에서는 템플릿이 발견되지 않았다.
- [ ] 패키지의 자산 사용 조건·고지·크기 및 깨끗한 PC 실행을 수용한다.
- [ ] 실제 GPU·1600×900·OS 배율·마우스/키보드·음향·성능을 검수한다.
- [ ] 정상×4 첫 완주 시간과 모든 필수 저장/앱 재실행·승패·AI 위임 경로를 수용한다.
- [ ] 개발 과정을 모르는 사람이 힌트 없이 완주하는지 관찰하고 주요 혼란을 해결한다.
- [ ] 최종 후보 소스·패키지 해시와 tracker/handover를 맞춘 뒤 전체 완료를 선언한다.

## 주의 사항

기존 Godot를 통한 소스 실행은 가능 경로로 안내했지만, export 앱과 같지 않으며 사용자 저장 위치가 기존 프로젝트와 공유될 수 있다. [플레이 안내](demo-rc-fin-play-guide.md)의 저장 주의사항을 먼저 읽는다.

구버전 실제 보관 저장 파일의 호환은 미검증이다. 합성 legacy 명령 재생 시험을 실제 과거 파일 호환 보증으로 확대하지 않는다. 중요 저장은 별도 보존한다.

관리·시나리오 판단은 현재 모델, 비관리 구현·UI/UX·QA·기술 검토는 GPT-5.6 Terra로 분담했다. 모든 `out` 폴더 내용은 검토에서 제외했다.
