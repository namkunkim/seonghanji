## 목적과 보존 범위

밤사이 후보를 검증 가능한 실행 결과물로 연결한다. 이전 run33의21단계 PASS를 현재 후보 수용으로 재사용하지 않고 새 후보 해시와 새 실행 결과를 묶는다.

- 제품 후보: `C:/WorkSpace/Seonghanji/tmp/demo-rc-fin-20260909`, 출발 SHA `111d0f2a6e8cfbf98000ae3a88eefcfc60296bd5`.
- 원본 `C:/WorkSpace/Seonghanji`의 기존 코드·자산 변경은 보존한다. 원본에서 이 작업이 관리하는 것은 진행 보고서다.
- 모든 `out` 폴더 내용은 계속 조사 대상에서 제외한다. 새 시험 결과는 별도 `tmp` 경로에 저장한다.
- 관리·시나리오 판단은 현재 모델, 구현·UX·시험·기술 검토는 GPT-5.6 Terra를 사용한다.
- 기존 야간 예약은 중지 상태로 유지한다. 이번 요청을 새로운 8시간 예약으로 해석하지 않는다.

## 소유와 진행 순서

| 묶음 | 담당 | 변경 소유 | 수용 조건 |
|---|---|---|---|
| R1 / G1·G9 | terra_gate | tools/ci 및 새 manifest/QA 증거 | 실행 전후 후보 SHA-256 목록 일치, 변경 시 실패, 오류·스킵 분리 |
| R2 / G1·G8·G10 | terra_packaging | export preset·신규 패키징 도구·자산/라이선스 문서 | 공식 동일 버전 템플릿, 실제 exe/PCK, 패키지 해시·기동 증거 |
| R3 / G3~G8 | terra_playability | Main·RedCliffBattleView·신규 플레이/저장/GPU 시험 | 실제 흐름·저장 후 별도 실행 복원·정상배속·GPU 확인 및 결함 수정 |
| R4 / 전체 | 조율자 | 범위·수용 체크리스트·연결 보고서 | 후보 동결, 트랙 교차 검토, 최종 결과와 미수용 구분 |

각 트랙은 독립 준비를 병행하지만 공유 Godot import와 최종 회귀는 실행 순서를 합의한다. UI/패키징이 제품 파일을 바꾸는 동안 전체 gate를 시작하지 않는다. 환경 승인 대기는 구현 실패·진행 시간과 구별한다.

## 검토 포인트

1. 공식 Godot4.7.2 템플릿의 실제 확보 가능성을 먼저 확인한다. 확인되지 않은 다른 버전으로 몰래 교체하지 않는다.
2. 변경 전후 해시에는 소스뿐 아니라 규칙 데이터·시험·runner·필수 자산도 포함한다. 생성 로그가 manifest 자신을 바꾸는 순환을 피한다.
3. 내부 입력 이벤트 시험·GPU 캡처는 사람의 무힌트 완주를 대체하지 않는다.
4. 핵심 자동수용과 패키징이 끝나기 전에 결과물을 ‘완성’이라고 하지 않는다.

## 중간 진행 기록

- 세 트랙이 기존 지침과 후보를 읽고 소유 범위를 확인했다. 첫 Godot 실행 슬롯은 플레이성 검증에 배정했다.
- 검증 담당은 시작/종료 manifest 비교 및 파일 추가·삭제·변경 시 실패하는 게이트를 준비 중이다. 제품 변경 중 전체 회귀는 시작하지 않는다.
- 패키징 담당은 공식 동일 버전 배포 경로를 확인했다고 보고했으나, 최초 템플릿 다운로드는 0byte 파일만 남겨 실패했다. 이를 템플릿 확보로 인정하지 않고 공식 대체 경로·HTTP/인증 오류 확인을 요청했다.
