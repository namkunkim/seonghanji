## 0. 1차 목표 운영 규칙

### 0.1 목표 흐름

1차 목표는 **적벽대전 시나리오 선택 → 선행 역사 조건 선택 → 손권 함대 수동 집결 → 손유 측 5페이즈 전투 직접 조작 → 승패·판세·후일담 결과 확인**이다. 사용자가 개발자 설명, 시험 전용 명령, 상태 주입 없이 이 흐름을 끝까지 수행해야 한다.

적벽 비발생 선택은 대체 전투 없이 DEC-01 조기 종료 이유와 판세 결과를 확인하는 보조 필수 경로다. 전체 SCN-03, 전체 캠페인, 모든 세력 자유 플레이의 완성은 1차 목표가 아니다.

### 0.2 지금 해야 할 일

- 현재 `main`과 필수 미커밋 구현·자산의 소유권을 구분하고, 실제 플레이 후보 하나를 추적 가능한 소스·시험·필수 자산 해시로 고정한다.
- 시작 화면에서 적벽 시나리오를 명확히 선택하고 새 체험과 이어하기를 구별한다.
- 플레이어를 손권으로 일관되게 표시하고 손유 측 함대와 전술 명령만 조작하게 한다.
- 선택 직후 다음 행동을 안내하고, 손권 함대를 정상 이동 규칙으로 구지에 집결시킨다.
- 일시정지·배속·명령 대기 상태를 화면에서 설명해 사용자가 스스로 진행을 재개하게 한다.
- 접적→포화→교전→강습→결착을 수동 조작으로 완료하고 승자·손실·명령 결과를 표시한다.
- 전투 승패, 데모 목표, 결착 시점 판세를 구분하고 결과와 정본 후일담을 다시 열 수 있게 한다.
- 선택·집결·전투·결말 경계의 저장·종료·재실행을 검증한다.
- 동일 후보에서 자동 회귀, Windows 1600×900 실기, 최초 사용자 무힌트 완주를 순서대로 수용한다.

### 0.3 지금 하지 말아야 할 일

- 1차 완주를 막지 않는 전체 캠페인, 추가 시나리오, 다세력 자유 플레이, 내정·외교 확장을 시작하지 않는다.
- 신규 실시간 3D 전투, 대규모 함선 재제작, 초상·BGM 전량 제작을 우선하지 않는다.
- UI나 시험에서 함대 도착, 전투 결과, 엔딩 값을 직접 주입해 정상 플레이 증거를 대신하지 않는다.
- CI 단계 수와 시험 수를 늘리는 일을 플레이어가 보는 진행 차단 수정보다 우선하지 않는다.
- 미커밋 대형 자산과 다른 작업의 변경을 일괄 스테이징·삭제·복원하지 않는다.
- `git add .`, `git add -A`, reset, clean, stash 또는 무단 checkout으로 공유 작업을 정리하지 않는다.
- 자동시험 PASS, 노드 존재, 소스 실행 성공만으로 데모 완료나 배포 완료를 선언하지 않는다.
- 적벽 전투 승리를 천하 통일이나 전체 캠페인 완료로 표현하지 않는다.

## 1. 종합 의견

현재 프로젝트는 결정론적 캠페인, 적벽 발생 조건, 수동 집결, 5페이즈 전투, 결과 적용과 저장·재생의 기반을 갖추고 있다. 그러나 개별 기능의 자동시험 통과와 처음 접하는 사용자의 데모 완주는 서로 다른 완료 조건이다.

가장 먼저 해결할 것은 플레이어 진영의 일관성과 시작→선택→집결→전투→결말 사이의 연결이다. 특히 1차 리뷰에서 확인한 손권 플레이어의 조조 진형 조작, 선택 완료 직후 안내 공백, 긴 집결 대기, DEC-01 엔딩 판정 연결 부족은 데모 수용 전에 처리해야 한다.

권장 순서는 **범위 확정 → 통합 기준선 확보 → 플레이어 권한 → 선택·집결·전투 연결 → 결말 → 저장·온보딩 → 표현 마감 → 자동·사람 검수 → 실행 패키지 수용**이다. 이미 구현된 기능은 이 순서에 맞춰 재사용하고, 통합본에서 실제 수용됐는지 확인한다.

이 보고서의 초안 작성에서는 코드 구현·수정, 디버깅, 시험 실행, Git 조작을 하지 않았다. 이후 사용자가 순차 실행과 자체 결정을 위임했으므로, 별도 통합 작업 공간에서 구현 에이전트가 진행하고 이 문서에 수용 상태를 관리한다. 원래 작업 공간의 기존 코드·자산은 보존한다.

## 2. 이번 문서에서 말하는 ‘데모 100%’

### 2.1 권장 완료 범위

권장 대상은 **Windows에서 실행하는 SCN-03 적벽 단편 데모**다. 1600×900을 1차 수용 기준으로 삼되, 플랫폼·해상도·최소 사양의 최종 확정은 G0에서 기록한다. 모바일 본편 전체의 완성을 의미하지 않는다.

이번 수용 대상은 선택→집결→적벽 전투 또는 DEC-01의 데모 구간이며, **SCN-03 전체 ACT 완성을 뜻하지 않는다.** 전투 결착을 데모 종료로 삼는 경우에도 정본 캠페인의 ‘마지막 ACT 완료에 따른 정규 종료’와 구별한다. 어느 시점의 상태에 기존 엔딩 규칙을 적용해 데모 결과를 보여줄지는 G0에서 명시한다.

처음 접하는 사용자가 개발자의 설명이나 내부 명령 없이 다음 흐름을 수행할 수 있어야 한다.

1. 배포 파일을 실행하고 새 데모를 시작한다.
2. 자신이 누구이며 무엇을 목표로 하는지 이해한다.
3. 브리핑을 거쳐 사건 선택과 그 결과를 확인한다.
4. 적벽 발생 경로에서는 직접 함대를 집결시키고 개전을 확인한다.
5. 자기 진영에 전술 명령을 내려 5페이즈 전투를 결착까지 진행한다.
6. 적벽 미발생 경로에서는 이유와 정본 종료 판정을 확인한다.
7. 결말에서 자신의 선택·전투·캠페인 결과의 관계를 이해한다.
8. 저장하고 앱을 종료한 뒤 이어하거나, 새 데모를 다시 시작한다.

### 2.2 반드시 유지할 경계

- 문서는 근거, 데이터는 값, 코어는 판정, UI는 표시와 명령 전달을 맡는다.
- 손권 참가 함대의 수동 이동과 조조 참가 함대의 시나리오/AI 이동을 구분한다.
- 참가 함대의 위치·도착 시각·전투 결과를 UI나 시험이 임의 주입해 정상 플레이를 대신하지 않는다.
- 적벽 미발생 경로에 대체 대회전을 추가하지 않는다.
- 전투 우측은 현행 정책인 정지 이미지와 상태 HUD를 사용한다.
- 회랑 소요, 시간 비판매, 병립 엔딩의 정당성 등 기존 원칙을 편의적으로 바꾸지 않는다.

### 2.3 이번 데모 완성의 필수 범위로 자동 편입하지 않을 것

6개 시나리오 전체, 다세력 자유 플레이, 일반 내정·외교 전체, 범용 알림 체계, 모바일 출시, 신규 실시간 3D 전투, 무장 위성·전투기 신규 시스템, 명장 초상 전량 생산은 별도 범위다. 기존 C-04·G-05·G-07 등의 전체 완료를 이 데모 완료와 동일시하지 않는다.

다만 **단편을 완주하는 데 필요한 최소 저장·이어하기, 조작 안내, 결과 브리핑, 설정과 크레딧**은 이번 완료 범위에 포함하는 것을 권한다. 이는 기존 LT-03 단독 계약보다 넓은 ‘완성 데모’ 제안이므로 G0에서 범위를 고정한다.

## 3. 현재 수준과 근거의 유효 범위

아래 내용은 이 채팅의 **이전 1차 리뷰 당시 관찰**이다. 보고서 작성 시점의 새 재현 결과나 최신 원격 통합본의 판정으로 읽지 않는다.

### 3.2 Git 기준점

이전 리뷰의 로컬 HEAD는 `bab276b6c1ac1a855c2314434bc886b5dd19533b`이며 미커밋 LT-03·자산 변경이 존재했다. `origin/main` 참조는 검토 중 `75372cb`에서 `111d0f2a6e8cfbf98000ae3a88eefcfc60296bd5`로 바뀌었고 당시 로컬은 7커밋 뒤였다.

`MGMT-HANDOVER-01`에서 2026-09-10 다시 확인하고 원격 우선으로 동기화했다. 현재 로컬 `main`과 `origin/main`은 모두 `111d0f2a6e8cfbf98000ae3a88eefcfc60296bd5`다. 동기화 뒤에도 기존 소유의 수정 17항목과 미추적 276항목이 남아 있으므로 깨끗한 통합 후보는 아니다. 재생성 출력 `out/` 4,871파일과 명확한 로그·고아 메타데이터만 삭제했으며, 나머지 소스·문서·자산은 소유권 판정 전 보존한다.

## 4. 체크리스트 관리 규칙

각 G 단계는 하나의 완료 게이트다. 아래 체크박스는 **최종 수용 여부**를 나타내며, 코드 존재 여부를 뜻하지 않는다. 초기 체크가 비어 있어도 구현이 전혀 없다는 뜻은 아니다.

- `[ ]`: 미수용. 구현 전·진행 중·검증 대기를 모두 포함한다.
- `[x]`: 지정 범위에서 완료 증거가 등록되고 검토자가 수용했다.
- 세부 상태는 `미착수 / 진행 / 검증 대기 / 차단 / 완료`로 관리한다.
- 구현자가 완료를 주장한 것만으로 체크하지 않는다. 관련 제품 동작과 시험 또는 사람 검수의 증거가 필요하다.
- 공통 증거 묶음에는 commit SHA, 빌드 식별자, 환경, 실행 경로, 기대/실제 결과, 일자, 검토자를 기록한다. 항목별로 적용되는 증거를 연결한다.
- 기능이 변경되면 영향받은 체크만 다시 연다. 변경 전 증거는 이력으로 남긴다.
- 핵심 완주·권한·저장 무결성·결말 설명은 필수다. 플랫폼별 입력, 자동 저장, 음향 구성 등 조건부 세부 사항은 G0에서 채택 여부를 정하고 제외 사유·검토자·일자를 남긴다. 미구현 항목을 사후 제외해 완료율을 높이지 않는다. 제외는 `[x]` 대신 별도 범위 기록으로 관리한다.
- `out`은 임시 산출물일 뿐이다. 장기 관리 문서에는 결론·빌드·재현 절차·증거 식별자를 남겨, 임시 파일 삭제 후에도 판정을 추적할 수 있게 한다.
- 게이트 완료 수는 진행 현황일 뿐 노력이나 구현률의 백분율이 아니다. **100%는 모든 필수 게이트의 최종 수용**을 뜻한다.

| 게이트 | 작업 묶음 | 선행 | 권장 주관 | 리뷰상 출발점 |
|---|---|---|---|---|
| G0 | 완료 범위·플레이 기준 확정 | 없음 | 디렉터 | 검토 대기 |
| G1 | 통합 기준선과 자산 경계 | G0 | 개발·형상관리 | 재확인 필요 |
| G2 | 플레이어 진영·명령 권한 | G1 | 코어·UX | 미수용 |
| G3 | 브리핑·사건 선택 | G2 | 시나리오·UI | 부분 구현 |
| G4 | 수동 집결·시간·개전 | G2, G3 | 코어·UX | 부분 구현 |
| G5 | 5페이즈 전투·결착 | G4 | 전투·UI | 기존 구현 재수용 필요 |
| G6 | 종료 판정·결말·재시작 | G3, G5 | 시나리오·코어·UI | 부분 구현 |
| G7 | 저장·이어하기·최소 온보딩 | G3~G6 | 앱·UX | 코어 기반 있음 |

주관은 책임 영역을 뜻하며 별도 인력이나 멀티 에이전트 실행을 요구하지 않는다. ‘리뷰상 출발점’은 과거 관찰 요약이며 실제 진행 상태는 §7 양식에서 정해진 다섯 상태로 관리한다. 온보딩 문안·상태별 다음 행동 표·검수표는 G0 이후 병행 준비하고 G3~G6 화면과 함께 검토한다. 게이트 수용은 선행 결과를 기준으로 한다.

- [ ] G6-01 DEC-01은 대체 전투 없이 종료하며, 마지막 선행 선택이 확정되기 전에는 성급히 종료하지 않는다.
- [ ] G6-02 G0에서 정한 판정 시점에 `endings.md` §5.2의 세계 상태·천명 축과 플레이어 소멸 예외를 적용하고 표시한다. 종료 사유 문자열만으로 대체하지 않는다. 데모 결말을 전체 캠페인 정규 종료로 과장하지 않는다.
- [ ] G6-03 적벽 전투의 승패와 시나리오 목표 달성/종료 판정을 구분한다. 전투 승리를 자동으로 천하 통일이나 캠페인 성공으로 표시하지 않는다.
- [ ] G6-04 두 경로의 결말에서 ‘선택 → 발생/비발생 또는 전과 → 세계 상태/목표 결과’를 설명하고 기존 정본 후일담을 연결한다.
- [ ] G6-05 홈 복귀 후에도 결과를 확인할 수 있다. 다시 열 수 없는 전투 기록에만 중요한 결말 정보를 남기지 않는다.
- [ ] G6-06 새 데모는 이전 선택·함대·명령·뉴스·결과·화면을 계승하지 않는다. 현재 진행을 잃는 행동은 사용자에게 명확히 알린다.

### G7 — 저장·이어하기와 최소 온보딩을 제공한다

완료 산출물: 개발 도구 없이 사용 가능한 최소 앱 기능.

- [ ] G7-01 시작 화면 또는 명확한 진입점에서 새 데모·이어하기·설정·종료에 접근할 수 있다. 저장이 없으면 이어하기 상태를 설명한다.
- [ ] G7-02 최소 한 개의 사용자 저장 슬롯과 저장 성공/실패 피드백을 제공한다. 자동 저장 채택 시 저장 시점도 고정한다.
- [ ] G7-03 선택 중·명령 대기·이동 중·전투 중·결말에서 저장 완료를 확인한 뒤 앱을 종료·재실행한다. 코어 상태뿐 아니라 현재 선택 단계·적절한 화면·대기 명령·다음 행동 안내가 복원된다. 일시정지·배속의 복원 또는 안전한 초기화 정책을 명시하고 대조한다.
- [ ] G7-04 저장 실패·손상·규칙 버전 불일치 시 이유와 가능한 행동을 제공한다. 실패를 성공으로 표시하거나 진행을 조용히 폐기하지 않는다.
- [ ] G7-05 변경 전 저장의 호환·이관·로드 거부 정책을 명시한다. 같은 버전의 왕복 시험만으로 과거 저장 호환을 주장하지 않는다.
- [ ] G7-06 처음 나오는 선택·이동·시간·전투 조작에 짧은 맥락 안내를 제공하고, 도움말을 다시 볼 수 있다.
- [ ] G7-07 뒤로 가기·Esc·팝업 닫기·포커스 복귀가 일관되며, UI 조작이 지도·전투 뒤편에 중복 전달되지 않는다.

### G8 — 표현과 실행 품질을 마감한다

완료 산출물: 지원 환경에서 읽히고 반응하는 화면, 필수 자산·음향, 측정 기록.

- [ ] G8-01 1600×900에서 브리핑·이동 패널·전투·결말·저장 화면의 잘림과 겹침이 없다. 창 크기·OS 배율의 지원 범위도 기록한다.
- [ ] G8-02 마우스와 Tab/Shift+Tab/Enter/Space/Esc로 필수 흐름을 수행한다. 색상 외에 텍스트·기호로 상태를 구별한다.
- [ ] G8-03 정지 이미지 정책과 전투 HUD가 일치하고, 남아 있는 개발용 명칭·내부 ID·불필요한 고정 날짜를 정리한다.
- [ ] G8-04 채택한 최소 음향 세트를 연결한다. 권장 대상은 명령 피드백·개전·결착이며, 음량 제어와 무음 상태에서도 정보 전달이 유지돼야 한다.
- [ ] G8-05 최종 패키지의 폰트·이미지·음원·모델별 출처·사용 조건·필요 고지·크레딧을 확인한다. 사전 계획 완료를 파일별 인수로 대신하지 않는다.
- [ ] G8-06 실제 참조 자산과 게임용 LOD를 확인하고 원본·미사용 자산의 불필요한 포함을 막는다. 대형 GLB 교체는 별도 인수한다.
- [ ] G8-07 최소 사양에서 실행·로딩·장면 전환·프레임·메모리·패키지 크기를 측정하고 G0의 기준과 대조한다. 제안 기준은 30fps 이상이며, 사양과 측정 조건을 먼저 확정한다.

### G9 — 자동 통과와 사람의 완주를 함께 수용한다

완료 산출물: 동일 후보 버전의 자동 결과와 실제 플레이 기록.

- [ ] G9-01 깨끗한 체크아웃과 격리된 쓰기 가능한 사용자 경로에서 필수 회귀를 수행한다. 환경 문제·실패·스킵을 구별한다.
- [ ] G9-02 LT-02·LT-03·QA-03·QA-04 및 새로 발견한 역할/안내/엔딩 결함의 회귀가 자동 게이트에 포함된다.
- [ ] G9-03 UI 시험이 노드 존재·signal 호출만 검사하는지 점검하고, 실제 표시·입력 가능 여부·포커스·제품 진행 결과를 검증한다.
- [ ] G9-04 이 절의 필수 플레이 매트릭스를 최종 후보에서 수행하고 각 행에 결과와 근거를 기록한다.
- [ ] G9-05 개발 과정을 모르는 사용자 1명 이상이 동일 export 후보·새 사용자 데이터·제품 기본 설정에서 M01을 진행 힌트 없이 완주한다. 가능하면 3명으로 확인하고 자기 진영·목표·다음 행동·명령 처리·결말 이유의 이해를 중립적 질문으로 관찰한다. 소수 표본을 일반적 사용성 보증으로 확대하지 않는다.
- [ ] G9-06 최초 사용자 관찰에서 나온 진행 차단과 주요 혼란을 해소하고 영향 범위를 재검수한다. 관찰자가 진행 방법을 알려줬다면 위치·이유를 기록하고 해당 경로는 다시 수용한다. 만족도만으로 완료 판정하지 않는다.
- [ ] G9-07 P0·P1 결함이 없고, 필수 흐름을 막는 P2도 없다. 나머지 P2/P3는 알려진 제한과 후속 작업으로 기록한다.

#### 필수 플레이 매트릭스

| ID | 실행 경로 | 합격 기준 | 결과/증거 |
|---|---|---|---|
| M01 | 새 실행→역사 선택→수동 집결→수동 전투→결말 | 개발자 보조 없이 완료, 역할·결과 일치. 도달 가능한 손유 승리·패배 결과 각각 확인 | 미수용 |
| M02 | 발생 경로→AI 위임→결말 | 위임 상태가 명확하고 정상 결착 | 미수용 |
| M03 | 각 선행 조건의 비발생 선택 | 미확정 조기 종료 없음, DEC-01 이유·판정 일치 | 미수용 |
| M04 | 앱 종료 후 단계별 이어하기 | G7-03의 모든 경계 복원, 명령·결과 중복 없음 | 미수용 |
| M05 | 잘못된 목적지·출전 불가·취소 | 이유와 가능한 회복/재시작 경로 표시 | 미수용 |
| M06 | 아군 선도착·상대 지연·일시정지 | 양측 진행과 재개 방법을 계속 이해 가능 | 미수용 |
| M07 | 빠른 중복 클릭·화면 왕복·키보드 입력 | 중복 처리·잘못된 대상 입력·포커스 유실 없음 | 미수용 |
| M08 | 결말→홈→새 데모 반복 | 이전 진행 누출 없음, 다시 정상 완주 | 미수용 |
| M09 | 저장 실패·손상·버전 불일치 | 실패 고지와 처리 정책 일치 | 미수용 |
| M10 | 정상 제품 배속·최소 사양에서 첫 완주 | G0 시간 목표와 G8 성능 기준 충족 | 미수용 |

자동 회귀의 기본 대상은 전체 코어, 저장·재생, A-05, G-10, 적벽 선택·집결·페이즈·결과, 제품 E2E다. 잠금 캠페인 회귀도 최종 후보에서 확인한다. 코어 규칙이나 시작 배치를 바꿨다면 기존 밸런스 기준선과 새 데모 전용 조건을 구분해 설명한다.

승패·소멸 등은 G0의 도달 가능 결과 목록과 대조한다. 정상 제품 경로로 도달하지 않는 상태는 코어 계약 검증 또는 지원 제외 근거로 분리하며, 정본에 존재한다는 이유만으로 새 엔딩 콘텐츠를 추가하지 않는다. 드문 상태의 자동시험용 구성은 정상 제품 완주 증거를 대신할 수 없다. DEC-01과 AI 위임 경로의 소요 시간도 M01과 구별해 기록한다.

### G10 — 배포 파일을 실제로 실행하고 마감한다

완료 산출물: 버전이 붙은 실행 패키지, 사용 안내, 수용 기록.

- [ ] G10-01 최종 소스 SHA·엔진 버전·export 설정·패키지 버전·파일 해시를 연결한다.
- [ ] G10-02 Godot 에디터나 개발 경로가 없는 환경에서 배포 실행 파일로 M01·M02·M03·M04·M08을 확인한다. G9 최초 사용자 관찰과 동일한 후보임을 기록한다.
- [ ] G10-03 실행 방법, 지원 사양, 조작, 저장 위치, 알려진 제한, 크레딧을 패키지와 함께 제공한다.
- [ ] G10-04 최종 패키지와 검수한 후보가 동일함을 확인한다. 이후 변경이 있으면 영향받는 수용을 다시 연다.
- [ ] G10-05 tracker·handover·QA 문서의 완료 범위와 수치를 최종 버전에 맞춘다. 과거 기록은 이력으로 보존한다.
- [ ] G10-06 모든 필수 게이트와 잔여 제한을 검토해 ‘데모 플레이 가능 최종 수용’을 기록한다. 외부 공개·업로드는 별도 배포 결정에 따른다.

## 7. 증거와 이슈 기록 양식

### 7.1 체크 완료 기록

| 항목 ID | 상태 | 구현/검토 담당 | 소스 SHA·빌드 | 환경·검증 방법 | 실제 결과·증거 위치 | 검토자·일자 |

### 7.2 발견 사항 기록

| 이슈 ID | 심각도 | 재현 조건 | 기대 결과 | 실제 결과 | 근거 파일/증거 | 연결 체크 | 처리 상태 |
|---|---|---|---|---|---|---|---|
| 예: REVIEW-ROLE-01 | P1 | 손권 플레이어의 진형 변경 | 손유 측만 변경 | 이전 리뷰에서 조조 측 변경 | `core/campaign.gd`의 플레이어 명령 적용 경로 | G2-02 | 통합본 재확인 필요 |

심각도는 P0=데이터 손실·시작/핵심 진행 불가·결정론 파손, P1=주요 기능/역할/결말 오류, P2=UX 혼란·누락·관리 불일치, P3=비차단 개선으로 사용한다. 우선순위는 실제 재현 영향에 따라 조정한다.

## 8. 검토 포인트

1. ‘20~30분 첫 완주’가 원하는 데모 체험인가, 본편의 장시간 전략 리듬을 보여주는 것이 우선인가? 이 선택에 따라 시작 배치와 온보딩이 달라진다.
2. 선행 사건을 여러 세력의 분기 설정으로 보여줄 것인가, 손권의 관점에서 타 세력 상황을 보고받는 흐름으로 바꿀 것인가?
3. 전투 결착 직후 단편을 끝낼 것인가? 캠페인 세계 상태·목표·후일담 판정의 기준 시점을 명시해야 한다.
4. 최소 음향·최소 사양·저장 슬롯 정책의 필수 범위는 어디까지인가?
5. 모바일 검수는 후속으로 분리하는가? 현재 Windows 수용 기록만으로 모바일 플레이 가능을 주장할 수 없다.

위 항목은 제안 또는 미확정 기준이며, 이 문서 작성으로 기존 결정을 변경하지 않는다. 확정 시 해당 체크와 근거 문서를 함께 갱신한다.

## 11. 다관점 교차 검토 기록

사용자 요청에 따라 게임 디렉션·시나리오, UX·플레이성, 기술·릴리스의 세 리뷰 에이전트가 초안을 독립 검토하고 서로 쟁점을 교환했다. 주 작성자는 다음 합의를 반영했다. 이는 문서 검토 결과이며 제품 시험 PASS가 아니다.

| 논의 쟁점 | 보고서 반영 |
|---|---|
| 짧은 대기를 위해 초기 배치를 바로 바꿔도 되는가 | 확정 해법이 아닌 비교 후보로 변경. 서사·규칙·재생·밸런스 보존을 조건으로 둠 |
| 좁은 전투 데모에 정본 엔딩을 연결하면 전체 ACT 구현이 필요한가 | 데모 종료 사건·판정 시점을 G0에서 명시하고 전체 캠페인 정규 종료와 구분 |
| 20~30분 완주와 60초 대기를 어떻게 판단하는가 | 읽기·판단·조작·시스템 강제 대기를 분리하고 미확정 목표로 유지 |
| 체크 항목을 더 늘려야 하는가 | 11개 게이트·71개 항목을 유지하고 증거·도달성·조건부 범위 정의를 보완 |
| 코어 저장 시험과 첫 사용자 완주만으로 충분한가 | 화면·다음 행동까지 복원하고 동일 배포 후보의 AI 위임·앱 재실행도 수용 |

권고: 다음 구현 작업을 시작하기 전에 G0를 짧게 확정하고, G1·G2를 첫 실행 묶음으로 삼는다. 이미 통과한 전투 기능을 확대하는 것보다 사용자가 누구를 지휘하며 어떻게 결말에 도달하는지를 일관되게 만드는 일이 우선이다.

## 12. 자율 실행 후 인계 기준

위 §1~§11의 초기 리뷰와 권고는 당시 관찰 이력이다. 후속 실행은 별도 통합 공간에서 진행했으며, 최신 진행·실패·재시험은 실행 기록과 QA 근거를 우선한다. 코드 존재나 개별 시험 PASS만으로 이 문서의 전체 수용 체크를 올리지 않는다.

다음 마감 순서를 유지한다.

1. 최종 whole-gate의 종료 요약과 실제 후보 해시를 대조한다. 결과 파일이 없거나 이전 후보 해시라면 다시 검증한다.
2. 실제 ×4 완주 시간, GPU 화면·OS 배율·물리 입력, 저장 후 앱 재실행 매트릭스의 미검증 부분을 확인한다.
3. Godot Windows export template를 준비하고 독립 패키지를 만든다. 소스 실행 안내는 이 단계의 대체 수용이 아니다.
4. 패키지 포함 자산·사용 조건·크레딧·크기를 인수하고 깨끗한 대상 환경에서 실행한다.
5. 처음 접하는 사람의 무힌트 완주를 관찰하고 진행 차단을 해결한다. 이 단계까지 끝나기 전에는 ‘데모 100% 완료’라고 선언하지 않는다.

원래 작업 공간의 사용자 변경은 보존되어 있으며, 현재 통합 후보를 원본 main에 자동 병합하거나 공개 배포하지 않는다. 검증 후보 위치와 원본 위치를 혼동하지 않는다.
